# kg/eval — исполняемый экзамен базы знаний (протокол v1)

**Что это.** 28 вопросов в трёх группах, замороженные в `questions.json` с `frozen_hash`. Правка после заморозки
запрещена: новая версия — новый датированный файл. `score.py` считает метрики по прогонам, `freeze.py` разрешает
интенсиональную спеку (`questions.src.json`) в закрытый список ID на сегодня.

## Три группы

| группа | что измеряет | чем оценивается |
|---|---|---|
| **A (E-01…E-15)** | достаёт ли база знание и основания | recall по gold-узлам, precision по блоку `cited:`, рубрика |
| **B (N-01…N-05)** | умеет ли говорить «не знаем» и называть причину | рубрика с полярностью, 5/5 |
| **C (AG-01…AG-08)** | работает ли агент с базой в самом репозитории: вход, запись, поиск, обзор | ожидаемые инструменты + рубрика |

## Почему метрики такие (что исправлено относительно v0)

| проблема v0 | решение v1 |
|---|---|
| gold содержал паттерны и имена файлов — «динамический gold» | `freeze.py` разворачивает всё в закрытые ID; `manifest.json` фиксирует, что разрешилось |
| отсутствующие узлы в gold делали целевой recall недостижимым | recall разложен: `retrieval` (по существующему) и `existence` (ledger недостающих, отдельный бэклог) |
| precision без знаменателя | знаменатель — только блок `cited:`; предки провенанса в `allow_extra` |
| micro-recall съедался большим вопросом | только **macro** по вопросам |
| «15k на круг» при сумме бюджетов 17 600 | 15k — **на вопрос**, включая map+expand+answer |
| у B не было бюджетов | 300 токенов на негативный ответ |
| «0 файлов» противоречило файловому gold | gold — только узлы; `NOT-CLAIMED`/`ELIMINATED`/`CHECK-*` объявлены `expected_absent` до импорта |
| повтор опровергнутой формулы проходил grounding-судью | рубрика **полярная**: `reject`-пункты проверяются кодом (нормализация минусов), `assert` — судьёй |
| снимок чисел корпуса (27/113) валил правильный ответ по мере роста | `registry_consistent`: число сверяется с текущим полем узла, а не с литералом |
| один прогон на круг | 3 сида, macro, порог роста 0.03, стагнация — два круга |

## Как проходит круг

### Вердикт, а не отчёт

`score.py` возвращает три исхода и код 0 только для `PASS`:

| вердикт | значение |
|---|---|
| `INVALID` | покрытие неполное (нужно 28 вопросов × 3 сида), есть дубли или неизвестные id, либо assert-пункты не оценены судьёй |
| `FAIL` | покрытие полное, но цель не достигнута (recall, precision, токены, файлы, reject-пункт, незаземлённое число, цитата отсутствующего) |
| `PASS` | всё измеримое в норме и судья оценил assert-пункты |

`--report-only` печатает отчёт и выходит с нулём: это для отладки, а не для зачёта.
`expected_absent` **не** входит в список разрешённых ссылок: цитирование отсутствующего штрафуется.

```bash
python3 kg/eval/freeze.py                     # один раз; печатает hash
python3 kg/eval/score.py runs-<дата>.json     # прогон агента -> отчёт
python3 kg/eval/score.py runs-<дата>.json history.json   # + стагнация на третьем круге
```

Запись прогона на вопрос (`runs-<дата>.json`):

```json
{"id": "E-01", "seed": 1, "cited": ["C-001", "F-023..F-031"],
 "answer": "…", "map_tokens": 300, "expand_tokens": 900, "answer_tokens": 700,
 "files_opened": 0, "tools": ["kg.py atlas", "kg.py expand"]}
```

## Дисциплина, без которой экзамен бессмысленен

1. **Gold не читается агентом во время круга.** `questions.json` — часть проверки, не корпуса: открывать его,
   чтобы «посмотреть ответ», нельзя (иначе это загрязнение benchmark и запоминание вместо поиска).
2. **Судья заморожен:** модель, промпт, `temp=0`, версия в отчёте. Человек смотрит все спорные и 20 % выборки.
3. **`eval_hash` пишется в отчёт круга** вместе с `map_hash` и `schema_version`; расхождение хеша — остановка.
4. **Нарушения протокола не исключаются из recall**, а флагуются: иначе метрика считает только выживших.

## Ledger: чего в базе ещё нет (это бэклог, не провал)

`manifest.json` перечисляет `expected_absent`: `BRIDGE-AB`, `GAP-BC`, `TERM-T2`, `CHECK-CONSISTENCY`,
`NOT-CLAIMED-NODE`, `FINDING-140/316/317/318/319`. Пока их нет, соответствующие вопросы имеют заведомо неполный gold;
цель по recall относится только к существующему.

## Самопроверка скорера

`demo-runs.json` содержит три намеренные ошибки, которые обязаны быть пойманы:

| ошибка | как ловится |
|---|---|
| ответ повторил опровергнутую `M - t/r` (она «заземлена» в документе об ошибке) | `rejects_total` растёт |
| выдуманное число `9.37` вне полезной нагрузки цитируемых узлов | `ungrounded_total` |
| ответ «не знаем» без чисел | `negative_auto_pass` |
