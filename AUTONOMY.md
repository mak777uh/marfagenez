# AUTONOMY.md — автономная работа

**Этот файл — для того, кто работает один, без владельца рядом.**
Он собирает всё, что нужно помнить, включая то, что легко потерять.

Что исследуем — [`GOAL.md`](GOAL.md).
Как работать — [`PROTOCOL.md`](PROTOCOL.md).
Что узнали на ошибках — [`LESSONS.md`](LESSONS.md).

---

## 0. Цикл работы

```
эксперимент → наблюдение → часть среды → снова эксперимент
```

**Ничего не выбрасываем.** Отброшенное записывается в `docs/ELIMINATED.md` с числом.

**Три слоя, не заменяющие друг друга:**

| слой | что | где |
|---|---|---|
| **Rust-ядро** | типы делают ошибки невыразимыми | `core/` |
| **Lean** | законы доказаны | `laws/` |
| **Симуляция** | проверяет, что закон верен | `checks/` |

**Пробы с подложенными дефектами — гейт, который не может провалиться, не гейт.**

## 1. Что делать каждый раунд

### 1.1. Найди вопрос

**Источники:**
- `docs/OBSERVATION-*.md` — раздел «Что можно посмотреть дальше»
- `docs/FINDING-*.md` — раздел «Что это не доказывает»
- `docs/ELIMINATED.md` — что уже отброшено, не повторяй
- `NOT-CLAIMED.md` — чего мы не утверждаем

**Не бери вопрос, у которого уже есть ответ в `ELIMINATED.md`.**

### 1.2. Напиши арифметику

**До прогона.** Что делает разницу: доход, расход, отношение, точка окупаемости.

**Проверь дважды:** скриптом и руками.

**Если всё поле выше порога в обоих плечах — эксперимент нечувствителен, не запускай.**

### 1.3. Запусти

```bash
wsl -e bash /root/marfagenez/run.sh exp
```

### 1.4. Прочитай числа

**До того, как писать вывод.** Если проза и артефакт расходятся — побеждает артефакт.

### 1.5. Запиши

- `docs/FINDING-<тема>.md` — находка
- `docs/ELIMINATED.md` — если провалилось
- `results/` — артефакт

**Каждый отчёт содержит «что это не доказывает».**

### 1.6. Залей

```bash
cd marfagenez && git add . && git commit -m "..." && git push
```

**Пуш в свой репозиторий — разрешён.** Публикация, рассылка, депозит — нет.

## 2. Когда не получается

**Порядок действий:**

1. **Прочитай `LESSONS.md`** — может, эта ошибка уже была
2. **Прочитай заметки по Кришнамурти** — `../medium/notes/krishnamurti-patterns.md`
3. **Прочитай заметки по Саммерхиллу** — `../medium/notes/neill-patterns.md`
4. **Попробуй иначе**

**Где лежат заметки.** Они **вне этого репозитория**, в соседнем проекте `medium/`:

```
<workspace>/
  marfagenez/          ← этот репозиторий
  medium/notes/        ← заметки (343 КБ Кришнамурти, 739 КБ Нилл)
```

**Если заметок нет** — они не были склонированы вместе с `marfagenez`. Тогда
читай [`docs/SYNTHESIS-readings.md`](docs/SYNTHESIS-readings.md) — там три
источника сведены в четыре утверждения, и этого часто достаточно.

### Как читать

**Читай оба файла целиком.** Не ищи нужный паттерн — читай подряд.

**Почему целиком:**

- **Ты не знаешь, какой паттерн нужен, пока не прочитал.** Проблема, которая
  кажется одной, часто оказывается другой.
- **Паттерны связаны.** Один ведёт к другому. Вырванный паттерн теряет смысл.
- **Это не справочник, а чтение.** Книги читались месяцами; заметки — за час.
  Час — не цена, а вход.

**Кришнамурти — 295 паттернов.** Про наблюдение, мысль, меру, сравнение,
запись, страх, свободу.

**Нилл — 746 паттернов.** Про школу, детей, страх, наказание, свободу,
самоуправление, ожидание.

**Оба файла — на английском.** Это нормально: они читаются как текст, а не
как код.

**После чтения** — вернись к вопросу и спроси: **изменился ли вопрос?**

**Полный список:** [`docs/SYNTHESIS-readings.md`](docs/SYNTHESIS-readings.md) —
три источника сведены в четыре утверждения. Это **выжимка**, не замена чтению.

## 3. Отдаляйся иногда

**Раз в несколько раундов — посмотри на всё сверху, из первых принципов.**

**Что значит «из первых принципов»:** не «что мы делаем», а **«почему мы делаем
именно это, а не что-то другое»**. Смотреть на репозиторий как на целое, а не на
заметки по отдельности.

**Как:** прочитай подряд
1. `GOAL.md` — что мы исследуем
2. `README.md` — что уже есть
3. `docs/CLAIMS.md` — что доказано
4. `NOT-CLAIMED.md` — чего не утверждаем
5. `docs/ELIMINATED.md` — что отброшено

**Спроси себя:**
- Цель всё ещё та же?
- Числа в README совпадают с кодом?
- Есть ли противоречия между заметками?
- Что мы делаем, чего не требует цель?
- Если бы мы начинали с нуля — что бы оставили?

**Это не анализ ради анализа.** Это проверка, что корабль плывёт туда.

## 4. Формулы

**Пиши формулы.** Не слова.

**Каждая формула — с:**
- условиями применимости
- числом, которое её проверяет
- границей, где она ложна

**Пример хорошей формулы:**

$$E_{\max} = \text{capacity} - \text{maintenance} - \text{damage\_rate} \cdot \text{repair\_cost}$$

**Условия:** `energy + taken ≥ capacity`
**Проверка:** `10.0 − 0.6 − 0.03 = 9.370000000000001` ✅
**Граница:** только когда энергия дошла до потолка; на 500 шагах плечо A не дошло

**Пример плохой формулы:** «среда способствует развитию».

## 7. Что писать в чат

**Владелец читает по-русски. Ждёт:**
- короткие ответы
- формулы
- проверку перед сдачей
- **заметки в чат не вставлять** — только в файлы

### 7.1. Язык: только русский

**С 2026-11-13 весь чат — по-русски.** Это правило владельца, а не стилистика.
Оно распространяется на всё, что читает человек:

| где | язык |
|---|---|
| чат | **русский** |
| `README.md`, `GOAL.md`, `PROTOCOL.md`, `LESSONS.md`, `AUTONOMY.md`, `NOT-CLAIMED.md` | **русский** |
| `docs/*.md` | **русский** |
| комментарии в коде (`core/`, `laws/`, `checks/`) | **русский** |
| имена файлов, коммитов, переменных | английский (иначе ломаются инструменты) |
| вывод программ | русский, если это текст для человека |

**Английский остаётся только там, где его требует машина:** имена, ключи JSON,
схемы, сообщения компилятора. Коммит-сообщение — английский: так его читает
`git log`, и так он не превращается в кашу при слиянии.

**Если поймал себя на английском абзаце в чате — это ошибка, а не выбор.**

**Не пиши:**
- длинные пересказы заметок
- «я сделал» без числа

3. **Прочитай заметки Кришнамурти** — может, вопрос поставлен неверно

4. **Попробуй иначе** — другое плечо, другая формулировка

5. **Запиши в `docs/ELIMINATED.md`** — с числом, если не получилось

6. **Спроси владельца** — цена вопроса одно сообщение

## 10. Чего не делать

**Из промпта и из правил проекта:**

| не делать | почему |
|---|---|
| выбрасывать отрицательный результат | он результат, записать в `ELIMINATED.md` |
| заполнять пробел правдоподобным числом | оно выглядит как результат |
| писать вывод до чтения чисел | E1b сказал противоположное своим данным |
| называть контроль, который не может провалиться, контролем | это лозунг |
| сравнивать формы между собой | readout внутри формы, не против других |
| публиковать без явного «да» | §10 `PROTOCOL.md` |
| коммитить `target/`, `.lake/` | `.gitignore` покрывает |
| сидеть в тупике | 40 минут — это уже слишком много |

## 11. Что значит «работать автономно»

**Не:** «делать что угодно без спроса».

**А:** **делать то, что требует цель, и записывать, что сделал.**

**Автономия — это не свобода от правил. Это способность следовать правилам
без напоминания.**

**И:** если правило мешает цели — сказать об этом, а не нарушить молча.
