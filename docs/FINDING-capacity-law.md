# FINDING — закон ёмкости

Дата: 2026-11-12. Статус: **подтверждён 30/30**, худшая ошибка 0.8 организма.

## Формула

Пусть `cells` — число клеток, `n` — число организмов, `M` — ёмкость клетки,
`r` — скорость восстановления, `t = income = 1.0`, `maint = 0.6`.

**Доход истощённой клетки за шаг.** Клетка, с которой выбрали всё, за шаг
восстанавливается до `L = r·M` и отдаёт `y = r·M`. Вывод: `L' = L − taken +
r·(M − L + taken)`; при `taken = L` получаем `L' = r·M`.

**Сколько живёт на истощённой клетке.**

```
j = 0                                если y < maint
j = floor((y − maint) / t) + 1       иначе
```

Первый жилец берёт `t`, второй — остаток `y − t`, третий — `y − 2t` и т.д.
Жилец выживает, если его доля `≥ maint`.

**Размещение.** `n` организмов падают равномерно, число жильцов на клетке
`K ~ Binomial(n, 1/cells)`.

**Выживаемость.**

```
alive(n) = cells · E[min(K, j)]
```

Это **не** ёмкость. Ёмкость (сколько влезает на насыщенном поле) — это
`C_full = cells · j`, и она не равна неподвижной точке `alive(n) = n`.
Путаница разобрана в `docs/FINDING-two-capacities.md`.

## Проверка

При `n = cells` (то есть `K ~ Binomial(cells, 1/cells)`, среднее 1) 30
комбинаций `cells ∈ {10,20,40,80,200} × (M,r) ∈ {(1,0.8),(1.5,0.8),(2,0.8),
(2,0.5),(3,0.6),(4,0.8)}`, по 10 seed'ов:

```
within 2: 30/30  worst |err| = 0.8
```

## Что это НЕ доказывает

- Это не теорема Lean. Это измеренная закономерность на сетке из 30 точек и
  10 seed'ов. Вывод `E[min(K,j)]` предполагает равномерное независимое
  размещение — при `Policy::Stay` и `n = cells` это выполняется, при движении
  нет.
- `j` посчитан из `y = r·M`, то есть из установившегося режима. На первом шаге
  поле полное (`M`), а не `r·M`; транзиент даёт третьего жильца, который
  умирает на шаге 9. В окне 300 шагов это уже не видно, но `alive` в момент
  `step < 10` формула не описывает.
- Ёмкость `C_full = cells·j` и выживаемость `alive(n)` — разные величины.
  `alive(n) = n` не имеет решения при `n ≥ 3`, поэтому определять ёмкость
  через эту неподвижную точку нельзя. См. `docs/FINDING-two-capacities.md`.

## Отброшенные варианты

| формула | результат |
|---|---|
| `cells·(1−1/e)` без ветки | 2/35 |
| `cells·(1−1/e)` с веткой | 24/30 within 2 |
| `j = floor(drained/maint)`, `cells·j` | 9/28 |
| `j = (M − t/r)/t + 1`, `cells·j` | 0/35 |
| `E[min(K,j)]` без множителя `cells` | 0/30 |
| **`cells·E[min(K,j)]`** | **30/30** |

## Ошибка, которая стоила двух заходов

Первая версия давала `pred ≈ 0.9` при любом `cells` — я забыл умножить на
`cells`. Сумма была верна, формула — нет. Проверять надо было порядок
величины: предсказание «0.9 выживших» при 40 организмах не могло быть верным
ни при какой физике.
