# FINDING: ёмкость клетки — закон найден

Дата: 2026-11-12
Эксперимент: `checks/exp24_kmax_floor.py`, прогон
`results/EXP-24/run-2026-11-12T13-03-34.json`, вердикт `passed`.

## Вопрос

EXP-23 показал, что ёмкость задаётся посадкой:
`survivors = Σ по клеткам min(занято, k_max)`. Но `k_max` оставалось
измеренным числом. Откуда оно берётся?

## Ответ

Пусть `M` — уровень, к которому клетка отрастает (параметр `rich`, **не**
финальный уровень поля). Пусть `income` — сколько едок может взять за шаг,
`maintenance` — сколько он тратит за шаг, `regrow` — доля разрыва, на которую
клетка восстанавливается за шаг.

Уровень клетки с `k` едоками подчиняется рекурсии

```
c₀     = M
u_n    = min(k·income, c_n)
c_{n+1} = (c_n − u_n) + (M − (c_n − u_n))·regrow
```

и сходится к `c*`. `i`-й едок в устойчивом состоянии берёт

```
t_i = min(income, c* − (i−1)·income)
```

Тогда

```
k_max = max { k : t_i > maintenance для всех i ≤ k }
C     = cells · k_max
```

## Проверка

`M = 4.0`, `income = 0.8`, `maintenance = 0.6`, `cells = 40`:

| regrow | c* | k_max | предсказано | измерено |
|---|---|---|---|---|
| 0.20 | 0.8000 | 1 | 40 | 40 |
| 0.40 | 1.6000 | 2 | 80 | 80 |
| 0.60 | 2.4000 | 3 | 120 | 120 |
| 0.80 | 3.2000 | 4 | 160 | 160 |
| 0.95 | 3.8316 | 4 | 160 | 160 |

Кросс-проверка с EXP-22 (однородное поле, `regrow = 0.8`):
`M = 2.00 → 80`, `M = 2.25 → 80`, `M = 4.00 → 160`. Все три совпали.

## Три ошибки, которые пришлось исправить

Первые две версии скрипта давали неверное предсказание. Обе ошибки
полезнее самого закона.

### 1. Вход рекурсии — не выход

Первая версия брала финальный уровень поля как начальный уровень рекурсии.
Предсказала `[0, 40, 80, 120, 160]`, измерено `[40, 80, 120, 160, 160]` —
сдвиг на одного едока. Финальный уровень — **выход** рекурсии, а не вход.
Вход — потолок `M = rich`, к которому тянет regrow.

Это тот же класс ошибки, что и подгонка параметра: величина, которую модель
производит, была подставлена туда, где модель её потребляет.

### 2. Порог строгий

Вторая версия использовала `>=`. При `regrow = 0.95` это давало `k_max = 5`
и ёмкость 200, измерено 160. Причина: модель убивает при `energy <= 0`
(`core/src/organism.rs:177`) и обновляет энергию как
`(energy + taken) − maintenance`. Едок, взявший ровно `maintenance`,
приходит в 0.0 и умирает. Выживание требует `taken > maintenance`.

### 3. Плавающая точка

Даже со строгим `>` вторая версия продолжала давать 5. Причина в `f64`:
`3.8 − 3.2 = 0.5999999999999999`, и голое `>` пропускает пятого едока
случайно. Нужен зазор: `t > maintenance + 1e-9`.

Измерение подтвердило это напрямую: мёртвый едок в трассе имеет
`taken: 0.6` — ровно порог, и он мёртв.

## Механизм: ёмкость — это исход гибели, а не свойство поля

При `n = 200`, `regrow = 0.95`:

| шаг | живы | уровень поля |
|---|---|---|
| 10 | 200 | 3.800000 |
| 50 | 200 | 3.800000 |
| 200 | 160 | 3.831579 |
| 3000 | 160 | 3.831579 |
| 20000 | 160 | 3.831579 |

Сначала живы все 200, поле оседает на 3.8 (пять едоков съедают 4.0 за шаг,
regrow от нуля даёт 3.8). Пятый едок получает ровно 0.6, умирает. Остаётся
4 едока, поле поднимается до 3.8316 и там остаётся.

Обратно уже не возвращается: мёртвые не воскресают. Ёмкость — это
**гистерезис**: итог зависит от того, кто умер на переходе, а не только от
текущего состояния поля.

## Что это не доказывает

* Только поля, однородные в конце. Чередующееся поле используется потому,
  что regrow подтягивает бедные клетки к богатому уровню и они перестают
  быть бедными.
* Только `Policy::Stay`. Движущиеся организмы не покрыты.
* Только один seed, `cells = 40`.
* Только устойчивое состояние. Переход не сравнивался.
* Не доказано, что это **единственный** способ получить `k_max`. Показано,
  что эта рекурсия воспроизводит измерение на пяти точках.
