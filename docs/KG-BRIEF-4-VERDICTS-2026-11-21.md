## 3. Судья: числа после исправления бага

В `kappa_sim.joint()` проверка была `0 ≤ a ≤ min(p, 1−p)`; правильная граница — `max(0, 2p−1) ≤ a ≤ p`. Из-за этого
**все строки p = 0.7 молча не исполнялись**. После исправления (300 прогонов, B = 399):

| истинная κ | n=30, p=0.5 | n=50, p=0.5 | n=50, p=0.7 | n=80, p=0.5 |
|---|---|---|---|---|
| 0.55 | 4.5 % | 6 % | ~5 % | 7 % |
| 0.70 | 33 % | 39 % | 37 % | 42 % |
| 0.80 | 60.7 % | 82.7 % | **69 %** | 93 % |

**Вывод, который меняет политику:** при истинной κ = 0.70 вероятность пройти стремится к ~50 % при любом n — порог
стоит ровно на истинном значении. Рычаг — **качество судьи**, а не бюджет пунктов; и смещение маргиналов (≥ 0.15)
делает допуск невозможным в принципе. Поэтому в `judge_policy.json` смещение — отдельный диагноз, а не повод для добора.
