## 1. Решения

| T | решение | проверяемое следствие |
|---|---|---|
| **T-01** | 10 частей и названия **замораживаются владельцем**; определения (`definition`-узлы) пишутся **до** первой разметки | инвариант 10/10: без десяти определений разметка не валидируется; у каждого — «входит / не входит / 2–3 пограничных случая» |
| **T-01a** | пограничные пары фиксируются заранее: **Выбор ↔ Агентность**, **Граница ↔ Порог**, **Индивидуальность ↔ Свои условия** | каждое определение содержит правило разрешения для своей пары, иначе `lines[0]` случаен |
| **T-02** | `lines` только у `claim`; `definition` ссылается через `defines` | `>3` — **предупреждение**; счётчики «узлов» и «инцидентов» никогда в одной колонке |
| **T-03** | у разметки своя provenance: `source_id`, `revision`, `content_hash`, `extraction_method`, `parser_version`, commit, `checked_by`, `triage_status` | 88 = parsed + unparsed; `unparsed` хранит исходное значение |
| **T-04** | `M` структурирован: `from/to/map/kind + assumptions/domain/limitations`; `kind` — закрытый enum | `linear ⊂ affine`: значения `kind` закреплены определением |
| **T-05** | мост направлен; обратный — **только вручную**, ссылкой `inverse_of` | автогенерации обратных нет |
| **T-06** | лестница `draft → complete → exam_ready`; `complete` ≠ истина, `exam_ready` ≠ доказано | допуск к экзамену — по списку полей; правка полюса → **downgrade** моста |
| **T-07** | 2 межкластерных моста — минимальный остов; приёмка партии — тест `connectivity` | `kind` не подгоняется под связность; связность ≠ истинность |
| **T-08** | **другое:** `FINDING-NNN` — стабильная идентичность; тройка `(path, locator, hash)` — **отпечаток** для дедупа | порядок резолва: совпало всё → пропуск; hash совпал → переезд, id сохранить; locator совпал, текст изменён → новая версия + ре-triage; оба изменились → новый узел, старый `superseded`; неоднозначно → очередь |
| **T-09** | `quarantined` при ingest; `accepted` ставит владелец или явно уполномоченный; `rejected` — с причиной, не удаление | каждое изменение статуса — событие с автором и датой |
| **T-10** | повышение только через `admit` (rationale + evidence_ids + actor + версия правил) | `check` проверяет форму, `admit` — эпистемическое решение; candidate не участвует в метриках силы |
| **T-11** | dev-28 у агента, holdout **офлайн** у владельца; один вопрос за раз; журнал предъявлений; агрегированный результат | подробные исправления по holdout агенту не выдаются |
| **T-12** | правило 0.7/0.55 — **предварительное**; протокол симуляции теперь в коде | одна попытка на набор; пограничная зона → добор **новых** предметов, не реролл |

**Три поправки против брифа:** T-01 (определения строго до разметки), T-08 (идентичность ≠ отпечаток), T-12
(не замораживать без симуляции — теперь она есть).

## 2. Наша симуляция судьи (T-12), воспроизводимо

`kg/eval/kappa_sim.py` — правило `κ̂ ≥ 0.70` **и** bootstrap-5 % ≥ 0.55, бинарные вердикты, две оценки, B = 399, 200
прогонов на конфигурацию:

| истинная κ | n=30 | n=50 | n=80 |
|---|---|---|---|
| 0.55 | 4.5 % (наивно 13.5 %) | **7 %** (11.5 %) | 7 % |
| 0.70 | 33 % (56.5 %) | 39 % (46.5 %) | 40.5 % |
| 0.80 | 59.5 % (79 %) | 82.5 % (88 %) | 92 % |

**Что это значит.** Двойное правило действительно строже наивного порога — и **связывающее ограничение это нижняя
граница bootstrap**, а не сам κ. Цена: судья с истинной κ = 0.70 проходит лишь в ~39 % случаев при n = 50. Цифра
«16 %» из брифа воспроизвелась только для **одиночного** порога при n = 30 (13.5 %).

**Следствие для правила:** либо n ≥ 80, либо пограничная зона `κ̂ ∈ [0.60, 0.75)` с добором 30–50 новых предметов; и
запрет реролла, иначе гарантия исчезает. `raw agreement` как гейт отклонён: при перекошенных маргиналах он даёт высокое
согласие случайно.
