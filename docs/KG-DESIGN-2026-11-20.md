# KG-DESIGN-2026-11-20.md — часть 2: варианты, решение и машиночитаемая схема

**Дата:** 2026-11-20. **Продолжение:** [`KG-STUDY-2026-11-20.md`](KG-STUDY-2026-11-20.md) (часть 1 — системы и
принципы). **Задача:** выбрать устройство памяти так, чтобы было удобно **агенту**, а не человеку; с формулами, с
привязкой к экспериментам и текстам, с внешними данными (включая планетарные), и с **картой всего графа** в
машиночитаемом виде.

---

## 1. Пять вариантов из внешнего разбора — и что от них остаётся нам

| вариант | идея | берём | не берём |
|---|---|---|---|
| **1. Claim-graph** | единица — утверждение `subj–pred–obj` + контекст + evidence + confidence | **да, основа**: у нас уже `kg/claims.jsonl` | `subj–pred–obj` как единственная форма: наши утверждения — **числа и законы**, а не триплеты |
| **2. Living map + zoom** | карта всего графа всегда в контексте, детали по запросу | **да**: `kg/meta.json` = карта (сообщества, хабы, счётчики) | ночная перекластеризация как сервис — у нас файл, пересобираемый `build` |
| **3. Executable wiki** | страницы = запросы; «все связи» = один запрос | **частично**: `kg.py` — и есть набор глаголов; Cypher-движок не нужен | внешняя query-БД: файл + Python достаточно для сотен узлов |
| **4. Formal core** | типы компактны → весь DAG в контексте; доказательства ленивы | **да, для формул**: у формулы есть сигнатура (величины, размерности, Lean-имя), тело — по запросу | Lean для всего корпуса: у нас уже есть Lean для законов |
| **5. World model / blackboard** | общий граф-состояние, агенты читают/пишут | **да, как правило**: `supersedes` вместо правки, review-gate = гейт | Graphiti/Hindsight: у нас один агент и git |

**Вывод из разбора (подтверждаю):** не строить «граф науки». Внешние графы (OpenAlex, OpenAIRE, S2, ORKG) — **внешний
слой ссылок**, а свой — **тонкий overlay утверждений** плюс карта и глаголы.

## 2. Решение: один файл узлов, типы, формулы с размерностями, карта

### 2.1. Узлы: `kg/nodes.jsonl` (заменяет `claims.jsonl`, обратная совместимость сохраняется)

```json
{
  "id": "C-001",
  "kind": "claim | formula | experiment | dataset | definition | question",
  "text": "…",
  "context": {"scope": "…", "parameters": "…", "conditions": "…"},
  "epistemic": "hypothesis | established | contested | replicated | refuted | bounded",
  "provenance": "extracted | verified_agent | human_confirmed",
  "evidence": [{"kind": "experiment|literature|formula|result|dataset|prediction",
                "ref": "EXP-…|L-…|F-…|FINDING-…|PDS-…", "strength": "strong|weak"}],
  "relations": [{"type": "supports|refutes|qualifies|extends|replicates|supersedes|same_as|shared_evidence|predicted_by",
                 "target": "C-…|F-…", "note": "…"}],
  "math": {"latex": "…", "lean": "Organ.Plateau", "units": {"D": "dimensionless", "lambda": "1/time"}},
  "data": {"source": "PID (DOI, PDS, USGS)", "license": "…", "accessed_at": "…"},
  "valid_time": {"from": "…", "to": "…"},
  "created_at": "2026-11-20",
  "updated_at": "2026-11-20"
}
```

**Почему так:** одно поле `kind` вместо шести разных форматов; `math.units` — прямой ответ на наши «невозможные
числа»; `data.source` — привязка к планетарным и любым внешним данным через **PID**, а не через файл; `valid_time` —
время, когда утверждение верно (у нас уже есть «дата среза» в литературе).

### 2.2. Карта: `kg/meta.json` — «мета-формула всего графа»

```json
{
  "schema": "kg/2",
  "built_at": "…",
  "counts": {"claims": N, "formulas": N, "experiments": N, "datasets": N},
  "invariants": [
    "every node has non-empty context",
    "every established node has >= 1 evidence",
    "every formula has units for each symbol",
    "no node is referenced by a missing node",
    "ids are never reused"
  ],
  "communities": [{"id": "K1", "label": "цена и бюджет", "hubs": ["C-001","C-002"], "size": 4}],
  "frontier": ["nodes with no evidence", "nodes with only extracted provenance", "refuted nodes still referenced"],
  "hashes": {"graph": "…", "schema": "…"}
}
```

**Смысл:** `meta.json` — то, что **всегда в контексте** (целевой размер 5–15 тыс. токенов). Он отвечает на «что у нас
есть и где фронтир», не требуя читать узлы. Детали — `show`/`expand`.

### 2.3. Глаголы (уже есть, добавим три)

| глагол | что делает |
|---|---|
| `map` | печатает `meta.json` в сжатом виде |
| `find` / `show` / `expand` / `trace` / `contradictions` | как сейчас |
| **`formula F-00N`** | сигнатура: символы, размерности, Lean-имя, где проверено |
| **`chain C-00N`** | цепочка «утверждение → формула → эксперимент → данные» |
| **`check`** | инварианты из `meta.json`, код, не LLM |

## 3. Что это даёт по вашим требованиям

| требование | как выполнено |
|---|---|
| «свои данные научные» | узлы `experiment` + `dataset` с ссылкой на `results/` и PID |
| «планетарные» | `kind: dataset`, `data.source = PDS/NASA/USGS`, `license`, `accessed_at` |
| «формулы с привязкой к экспериментам или текстам» | `kind: formula` + `math` + `evidence` на `EXP`/`L` |
| «математика и машиночитаемая форма в приоритете» | `math.latex` + `math.lean` + `units`, JSONL как канон |
| «мета-формула всего графа» | `kg/meta.json`: инварианты + сообщества + фронтир + хэши |
| «я туда лазить не буду» | всё чтение — через `map/find/show/chain`, markdown генерируется |

---

## 4. Чего сознательно нет (и почему)

1. **Внешней графовой БД** (LadybugDB, Neo4j `ki`): при сотнях узлов Python-обход дешевле и не создаёт второй источник
   истины. Пересмотр — при >10⁴ узлов или если понадобятся регулярные Cypher-запросы.
2. **LLM-извлечения связей из PDF**: по внешнему разбору точность типизированных рёбер 21–53 % — шум опаснее пользы;
   у нас корпус свой и небольшой.
3. **Векторного поиска как основного**: similarity ≠ структура; используем как вспомогательный при поиске дублей.
4. **Временной памяти (Graphiti/Hindsight)**: `valid_time` в узле + `supersedes` даёт 80 % пользы за 0 зависимостей.

## 5. Порядок внедрения

1. **Сейчас:** переименовать `claims.jsonl` → `nodes.jsonl`, добавить `kind` всем узлам, ввести `meta.json` и три
   глагола, инварианты проверять в `check`.
2. **Потом:** импортировать `F-`-формулы и `EXP-`-прогоны как узлы (сейчас они только в `evidence`), т.е. граф станет
   полным, а не «утверждения + ссылки».
3. **Потом:** `dataset`-узлы для внешних данных, начиная с планетарных (PDS/USGS) — сначала метаданные, потом
   извлечение величин.
4. **Позже:** карта сообществ алгоритмом (label propagation), когда узлов станет больше сотни; сейчас — ручные
   `communities` по линиям.
