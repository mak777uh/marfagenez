# FINDING-343: «плато» F-002 — не плато, а снимок на конечном горизонте

**Дата:** 25.11.2026. **Тип:** проверка собственных данных (числа), не измерение.
**Связано:** `docs/UNITS-AUDIT.md` §4, `F-002`, `FINDING-297` (та же схема для `F-001`).

## Что установлено

Запись `F-002` приводит числа 2,02 / 3,28 / 5,80 / 8,68 для `h = 0,90 / 0,95 / 0,98 / 0,99` и называет их
плато. Если это неподвижные точки `D* = δ·T/(1−h)`, произведение `δ·T` обязано быть общим. Оно не общее:

| h | записано | `δ·T` из формулы |
|---|---|---|
| 0,90 | 2,02 | 0,202 |
| 0,95 | 3,28 | 0,164 |
| 0,98 | 5,80 | 0,116 |
| 0,99 | 8,68 | 0,0868 |

Разброс в 2,3 раза. При `δ·T = 0,2` записанные значения совпадают с `D_n = δ·T(1 − h^n)/(1 − h)` при
`n ≈ 33 / 43 / 57` соответственно, а пределы равны 2 / 4 / 10 / 20.

## На каком основании

Арифметика по замкнутой формуле рекуррентности (команда и таблица — в `docs/UNITS-AUDIT.md` §4).

## Что это НЕ доказывает

- Что числа получены ошибкой: это законные значения на конечном горизонте.
- Что `δ·T = 0,2` — то, что реально использовалось: подобрано по совпадению.
- Что запись `F-002` неверна как формула: неверна **подпись** «плато», а не сама рекуррентность.

## Проверка источника (25.11.2026)

Поиск по репозиторию (`grep` по `*.md`, `*.py`, `*.json`, `*.rs`) даёт **единственное** вхождение
чисел 2,02 / 3,28 / 5,80 / 8,68 — саму строку в `docs/ELEPHANT-LITERATURE.md`. Ни скрипта, ни прогона,
ни результата `results/**` с этими пределами нет. Значит числа записаны вручную и **не воспроизводимы**.

В запись добавлена датированная поправка: пределы при `δ·T = 0,2` равны **2 / 4 / 10 / 20**, а если нужен
снимок — указывать `n` и `δ·T`.
