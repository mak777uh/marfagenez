# Ёмкость — обрыв, а не склон

**Дата:** 2026-11-13
**Эксперимент:** `checks/exp32_kmax_law.py` → `results/EXP-32/run-2026-11-12T22-02-09.json`, verdict `passed`

---

## Что было записано раньше

EXP-31 записал закон

```
k_max = 1 + floor((M*r - maintenance - damage) / income)
```

и проверил **одну точку**: при `maintenance = 0.6` он дал `k_max = 2`, и
sighted-популяция на ровном поле дала ровно `2 * 40 = 80`.

Одна точка — не закон. Это ровно та ошибка, которую EXP-21 сделал со
скученностью `(M - income)/maintenance`: подогнал под одно измерение и назвал
законом.

## Что показал прогон

Первая версия EXP-32 взяла формулу EXP-31 дословно и прогнала шесть значений
`maintenance`:

| maintenance | измерено | предсказано | |
|---|---|---|---|
| 0.40 | 80 | 80 | ✓ |
| 0.60 | 80 | 80 | ✓ |
| 1.00 | **0** | 40 | ✗ |
| 1.40 | **0** | 40 | ✗ |
| 1.60 | 0 | 0 | ✓ |

Формула **неверна**. Она считает, сколько *порций* `income` может оплатить
отрастание, но не спрашивает, хватает ли одной порции, чтобы организм выжил.

## Почему

Один организм тратит

```
cost = maintenance + damage*repair = maintenance + 0.02*1.5 = maintenance + 0.03
```

за шаг и может взять не больше `income = 0.8`. При `maintenance = 1.0`:
`cost = 1.03 > 0.8 = income`. **Никакое число порций не помогает** — один
организм не выживает, потому что каждый шаг у него дефицит `0.23`.

Формула этого не видела, потому что `income` в ней стоит и в числителе, и в
знаменателе: она измеряет «сколько порций», а не «выживает ли один».

## Верный закон

```
cost  = maintenance + damage*repair

k_max = 0                                        если income < cost
      = 1 + floor((M*r - cost) / income)          иначе
```

Порог выполнимости: `income = cost`, то есть `maintenance = 0.8 - 0.03 = 0.77`.

## Измерение

Шесть точек, две из них охватывают порог:

| maintenance | cost | income < cost? | k_max | предсказано | измерено |
|---|---|---|---|---|---|
| 0.40 | 0.43 | нет | 2 | 80 | **80** |
| 0.60 | 0.63 | нет | 2 | 80 | **80** |
| 0.75 | 0.78 | нет | 2 | 80 | **80** |
| 0.80 | 0.83 | **да** | 0 | 0 | **0** |
| 1.00 | 1.03 | да | 0 | 0 | **0** |
| 1.40 | 1.43 | да | 0 | 0 | **0** |

6 из 6. Порог зажат между 0.75 и 0.80 — эксперимент говорит, **где** обрыв, а
не только что он есть.

## Что это меняет

Ёмкость — **обрыв**, а не склон. При `maintenance` чуть ниже 0.77 на сорока
клетках живут 80 организмов; при `maintenance` чуть выше — ноль. Не 79, не 40,
не 20. Между 0.75 и 0.80 нет промежуточных значений, которые стоило бы
интерполировать.

Это не «популяция постепенно сокращается при росте расходов». Это
**одновременная смерть всех**, потому что дефицит у каждого одинаковый и
одинаково непокрываемый.

## Что это НЕ доказывает

- Только ровное поле и sighted-политика с настоящим `read_budget = 3`. На
  градиенте EXP-31 нашёл, что sighting теряет (40 против 68 при n = 160) —
  там закон не проверялся.
- Совпадение счёта с формулой **согласуется** с механизмом «дефицит на шаг»,
  но не доказывает, что механизм именно такой. Другие причины могли дать тот
  же счёт на этих шести точках.
- Порог 0.77 выведен из `damage = 0.02, repair = 1.5`. При других значениях он
  сдвинется; проверена только эта пара.
- Не сказано ничего о том, что происходит **между** 0.75 и 0.80 — там может
  быть узкий переходный режим, который сетка 0.05 не разрешает.

## Ошибка, которую поймали

Формулу EXP-31 нельзя было оставлять: она давала 40 там, где измерение даёт 0.
Разница между «одна точка совпала» и «закон верен» — это разница между
EXP-31 и EXP-32. Первая версия EXP-32 упала бы с вердиктом `failed`, и это
был бы правильный вердикт: формула была неверна.

Вердикт `passed` относится **к исправленной** формуле, а не к исходной.
