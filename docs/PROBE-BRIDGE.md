# Мост для агента `probe`: обмен файлами вместо исполнения команд

**Дата:** 25.11.2026. **Кто:** `main`. **Инструмент:** `python3 tools/probe_bridge.py`.

## Что предлагалось и чем это плохо

Предложенная схема: скрипт `bridge.sh` в WSL каждые 30 секунд исполняет `bash`-файлы из
`C:\111\probe-bridge\queue\` **как root в репозитории**, плюс шлёт heartbeat за агента.

**Технически это работает.** Проверено чтением скрипта — он делает ровно то, что описано.

**Но это снимает все ограничения проекта:**

| что может случиться | почему это важно |
|---|---|
| скрипт из Windows-каталога делает `git commit`/`push` | «публикует только `main`» перестаёт существовать |
| скрипт правит `kg/nodes.jsonl` или `atoms.jsonl` | обходит `map_ingest`, дубли и правило цеттелькасте́на |
| скрипт делает `rm -rf` или `git checkout .` | теряется чужая работа |
| любой процесс на машине кладёт файл в `queue\` | это уже не агент `probe`, а кто угодно с доступом к `C:\111` |
| heartbeat за агента | раунд никогда не «бросят», даже если агент не работает — очередь блокируется |

Плюс издержки: мост копирует `atoms.jsonl` (2,4 МБ), `edges.jsonl` (251 КБ), `nodes.jsonl` (496 КБ) и
десяток документов **каждые 30 секунд** через `/mnt/c`, который в 8 раз медленнее ext4 (`docs/PERFORMANCE.md`).

## Что сделано вместо

**Декларативный мост: агент просит данные и присылает вопросы, исполняет всё `main`.**

Никакого shell из очереди. Агент может только:
1. **попросить срез** данных — `request/<NNNN>.json`;
2. **прислать вопросы** — `outbox/<имя>.jsonl`.

Мост (`tools/probe_bridge.py --serve`) делает один проход:

- читает запросы, проверяет вид запроса по белому списку (`cells`, `nodes`, `orphans`, `standing`, `audit`),
  кладёт готовый срез в `data/<NNNN>.md`;
- читает посылки, **проверяет каждую строку** и раскладывает: принятые — в
  `literature/map/inbox/probe-<дата>-<имя>.jsonl`, отклонённые — с причиной в `ack/<имя>.json`.

## Белый список запросов

| kind | args | что получит агент |
|---|---|---|
| `cells` | `{"ids": [...]}` | полные ячейки: утверждение, формула, DOI, локатор, цитата |
| `nodes` | `{"ids": [...]}` | узлы `kg`: текст, формула, единицы |
| `orphans` | `{"group": "DIP34"}` или `{}` | сироты карты |
| `standing` | — | инструкция, план, промпт |
| `audit` | `{"ids": [...]}` | строки `docs/STITCH-AUDIT.md` с этими id |

## Проверка посылок (сделана до приёма)

Обязательно, иначе строка отклоняется с причиной:

| условие | пример отказа |
|---|---|
| `question` ≥ 20 символов | «выглядит подозрительно» |
| `kind` из `{units, numbers, order, gap-as-support, no-locator}` | `kind: "suspicious"` |
| `atoms` существуют в карте | `atoms: ["DIP999-0001"]` |
| `numbers` — список, ≥ 2 значения | одно число |
| `verifiable` — как проверить ответ | пусто |
| для `units`/`order` обязателен `recalc` | вопросы про единицы без пересчёта |
| не больше 8 вопросов в файле | 12 строк |

## Проверено на живом примере

Запрос среза двух ячеек + файл с тремя вопросами (один годный, два дефектных):

```
запрос 0001-cells: готово -> data/0001-cells.md
принято 1 из 3 -> literature/map/inbox/probe-20261125T2013-test1.jsonl
reasons: ["test1.jsonl:2: нужно ≥2 числа (numbers)",
          "test1.jsonl:3: для units/order обязателен recalc — пересчёт"]
```

## Как работать (для владельца)

```bash
# один проход: разобрать запросы и принять посылки
wsl.exe bash -lc 'cd /root/marfagenez && python3 tools/probe_bridge.py --serve'

# посмотреть, что лежит в очередях
wsl.exe bash -lc 'cd /root/marfagenez && python3 tools/probe_bridge.py --status'
```

Запускать **вручную или по моему расписанию раз в раунд**, а не демоном каждые 30 секунд:
раунд на `probe` идёт часами, а не секундами.

## Дополнение 25.11.2026, вечер: пропускная способность поднята

Агент `probe` рассчитан на непрерывную работу 24/7 и работает быстро. Значит **ограничивать надо не приём, а
мою проверку** — и делать проверку машинной там, где это возможно.

### Что изменено

| было | стало |
|---|---|
| ≤ 8 вопросов в файле | **≤ 24** |
| числа не проверялись | **каждое число должно встречаться в тексте своих ячеек** |
| повторный вопрос принимался как новый | **дедупликация** по (вид, набор ячеек), состояние в `state/probe-seen.json` |
| я вручную открывал `ack/*.json` | **`docs/PROBE-TRIAGE.md`** — сводная очередь: вид, вопрос, ячейки, числа |

### Почему проверка чисел важна

Она ловит **выдуманные** числа: если в вопросе стоит `999,5`, а в ячейке такого числа нет — вопрос
отклоняется автоматически, без моего участия.

Проверено на живом примере:

```
принято 1 из 2
reasons: ["число '999.5' не встречается в тексте ячеек ['DIP24-0005']"]
```

При этом научная запись нормализуется: `1,0·10⁻³` и `0.001` считаются одним числом (`norm_num` разбирает
надстрочные цифры).

### Что это даёт по скорости

Агент может присылать партии по 20+ вопросов. Мне остаётся:

1. посмотреть `docs/PROBE-TRIAGE.md` (одна страница);
2. разобрать те, где машинная проверка пройдена, и решить: дефект / пробел / снять.

**Дедупликация спасает от главного риска быстрого агента** — повторной присылки того же вопроса. Без неё
при 24/7 потоке половина проверки уходила бы на повторы.

### Остаётся ручным

- решение «это дефект или нет» — требует чтения;
- пересчёт единиц, который нельзя проверить регуляркой;
- вопрос «нужен ли новый замер».

Дальше можно автоматизировать и это, но только с типизированными числами в ячейках (величина + единица), а
не из прозы (`docs/EDGE-ORDER.md` показал, почему на прозе это не работает).

## Лимиты партий (25.11.2026, по запросу владельца)

**Потолок поднят: 24 → 120 вопросов в одном файле.**

Почему можно: машинных проверок пять, и они отсекают мусор до меня — числа обязаны встречаться в тексте
ячеек, `recalc` обязателен для `units` и `order`, есть дедупликация по тексту вопроса, поддержка
многострочного JSON и каретных степеней (`10^-1`).

Что остаётся узким местом: **мой разбор**. Поэтому правила такие:

| что | правило |
|---|---|
| размер файла | до **120** вопросов |
| виды | любые из пяти, но **не больше 40 одного вида** на файл (иначе разбор однобокий) |
| повторы | дедупликация автоматическая, по тексту вопроса |
| приоритет внутри файла | сначала `numbers` (внутренние противоречия), потом `units`, потом остальное |
| темп | присылать следующий файл, **не дожидаясь** моего разбора |

**Чего это стоит мне:** 120 вопросов — это 2–3 часа разбора. Ты можешь присылать десятками, я разбираю
волнами и отвечаю в `ack` по каждой волне. Если очередь станет длиннее трёх файлов — верну потолок обратно и
скажу почему.
