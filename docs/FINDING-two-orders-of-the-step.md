# FINDING: два порядка в шаге клетки — take-then-regrow vs regrow-then-take

Дата: 2026-11-12. Статус: **решено**, сборка `laws` чистая (0 ошибок, 18320 jobs, 236 теорем).

## Что случилось

Полдня доказывалось ложное тождество. Две формы равновесия считались одной:

```
A = M + t - t/r          (= M - t*(1-r)/r)
B = M - t/r
```

Они **не равны**. Разница ровно `t`:

```
A - B = (M + t - t/r) - (M - t/r) = t
```

При `t = 0.8` это 0.8 — не «погрешность округления», а целая восьмая часть масштаба.

## Почему обе верны — в своём порядке

Порядок операций в шаге клетки определяет, где точка покоя.

**take-then-regrow** (`cellStep`, `Medium/Field.lean`):

```
cellStep M r t c = (c - t) + (M - (c - t)) * r
```

Сначала забираем `t`, потом отрастает доля `r` от остатка. Точка покоя:

```
c* = M - t*(1-r)/r = M + t - t/r
```

**regrow-then-take** (`feedStep`, `Medium/Feed.lean`):

```
feedStep M r t c = c + (M - c) * r - t
```

Сначала отрастает, потом забираем. Точка покоя:

```
c* = M - t/r
```

Проверка (sympy, `c_next(c*) - c* = 0`):

- `cellStep`: `c* = M - t*(1-r)/r` ✓
- `feedStep`: `c* = M - t/r` ✓

## Численная проверка

`M = 2`, `t = 0.8`:

| r | cellStep `M - t*(1-r)/r` | feedStep `M - t/r` | разница |
|---|---|---|---|
| 0.2 | 2 - 0.8·0.8/0.2 = **-1.2** | 2 - 4 = **-2.0** | 0.8 |
| 0.5 | 2 - 0.8·0.5/0.5 = **1.2** | 2 - 1.6 = **0.4** | 0.8 |
| 0.8 | 2 - 0.8·0.2/0.8 = **1.8** | 2 - 1.0 = **1.0** | 0.8 |

Измеренные значения (k = 0.2, 0.5, 2.0 → r = 1/k): 1.960, 1.900, 1.600 — согласуются с `cellStep`
при своих `t`, а не с `feedStep`.

## Что это стоило

~20 патчей доказывали ложное тождество. `ring` / `ring_nf` / `abel` / `nlinarith` после
`field_simp` не закрывали его — потому что оно ложно при `t ≠ 0`, а не потому что тактика слабая.

Симптом, который должен был остановить сразу: `field_simp` давал тождество, расходящееся
на `r^2 * t`. Расхождение с точным множителем — это не «не хватило тактики», это
**неверная формула**.

## Правило, которое отсюда следует

Перед правкой докстринга или формулы — подставить числа и сравнить **численно**, а не
символьно-надеясь. Одна строка `python3 -c "print(A - B)"` дешевле двадцати патчей.

И второе: если два выражения описывают «одно и то же» в разных местах кода — проверить,
не разные ли это **порядки операций**. Порядок в этой модели не косметика, он сдвигает
равновесие на целую `t`.
