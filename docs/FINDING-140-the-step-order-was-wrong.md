# FINDING-140 — порядок шага был записан наоборот

**Дата:** 2026-11-13
**Уровень:** A (доказано после исправления) + C (измерения, отозваны)
**Статус:** исправлено, собрано, запушено

---

## Что было

В `Medium/Field.lean` шаг клетки был записан так:

```
cellStep M r t c = c + (M − c)·r − t
```

Сначала прирост, потом трата. Из этого следовало равновесие

```
c* = M − t/r
```

и потолок `C = cells · M·r / income = 80`.

## Что не так

Организм **сначала берёт, потом клетка отрастает**. В коде
(`core/src/life.rs`) порядок именно такой: `taken = min(cell, t0)`,
`cell -= taken`, затем `cell += (M − cell)·r`. Формула в Lean описывала
другой мир — с другим равновесием и другим потолком.

Разница не косметическая. Решения `c + (M−c)r − t = c` и
`(c−t) + (M−(c−t))r = c` — разные числа:

| r | t | `M − t/r` (было) | `M + t − t/r` (стало) |
|---|---|---|---|
| 0.2 | 0.8 | −2.000 | −2.000 |
| 0.5 | 0.8 | 0.400 | 0.400 |
| 0.8 | 0.8 | 1.000 | **1.200** |
| 2.0 | 0.8 | 1.600 | **1.600** |

Совпадают только при `r = 1` и `r = 0.5`. При `r = 0.8` — рабочей точке
экспериментов — расхождение `0.2`, то есть 12.5 %.

## Как проверено

1. **Символьно.** `sympy`: `c_next(c*) − c* = 0` для `c* = M + t − t/r`,
   и `≠ 0` для `c* = M − t/r` при `r ≠ 1/2`.
2. **Измерением.** Три прогона с разными `r`, `M = 2`, `t = 0.8`,
   установившееся значение уровня клетки:

   | r | предсказано `M + t − t/r` | измерено |
   |---|---|---|
   | 0.2 | 1.960 | 1.960 |
   | 0.5 | 1.900 | 1.900 |
   | 2.0 | 1.600 | 1.600 |

   Старая формула даёт для `r = 0.2` значение `−2.0`, для `r = 0.5` — `0.4`;
   ни то, ни другое не наблюдалось.

3. **Сборкой.** `cd laws && lake build` → `Build completed successfully
   (18328 jobs)`, 0 errors.

## Что отозвано

Всё, что было выведено из старого порядка:

- `equilibrium = M − t/r` — заменено на `M + t − t/r`.
- `C = cells · M·r / income = 80` — **отозвано**. При новом порядке
  `k_max = 10`, значит `C = 400`. Но измерение по-прежнему даёт 80.
  Расхождение в 5 раз **не объяснено**.
- `E* = E_max − COST` — отозвано, установившаяся энергия равна `E_max`.
- `c* = 1.8` в `Regimes.lean` — заменено на `1.2` при `M=2, r=0.8, t₀=0.8`.
- `capacity M r t₀ = M·r / t₀` в `Capacity.lean` — закон доли прокорма
  остался, но численные следствия пересчитаны.

## Что это не доказывает

- Что новое равновесие верно для **любой** `r`. Доказано для `r ≠ 0`,
  проверено на трёх точках.
- Что расхождение `C = 400` против измеренных `80` — ошибка измерения.
  Скорее наоборот: значит, в модели есть второй ограничитель, которого
  формула не видит.
- Что старые эксперименты в `results/` стали неверны. Они верны **как
  измерения того кода**, который был запущен. Неверна была их словесная
  интерпретация.
