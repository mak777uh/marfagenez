# FINDING-208. Окно восприятия: `k = 1` — ровно прежнее правило, и это по построению

**Дата:** 2026-11-17. **Статус:** `passed` (механизм + четыре теста). **Цикл:** 121.

## Зачем

`docs/DESIGN-perception.md` посчитало: у правила соседа **71 % моря без сигнала** (оба соседа
равны), поэтому среда не может вознаградить **поиск**, и «память против зрения» непроверяемо.
Значит нужна пара «восприятие + среда», где сигнал есть. Здесь сделано восприятие.

## Что сделано

`Life::set_sight_radius(k)` / `sight_radius()`: `Sighted` смотрит в `[-k, k]` и шагает к лучшей
клетке. **`k = 0` и `k = 1` исполняют старый код буквально** — ветка окна входит только при
`k > 1`, поэтому все записанные прогоны сохраняют биты **по построению**, а не по удаче.
`hash_golden` проходит.

## Четыре теста (`core/tests/perception.rs`)

1. радиус по умолчанию — 0;
2. **`k = 1` совпадает с прежним правилом бит в бит** (тот же мир, тот же сид, 30 шагов);
3. **окно видит то, что скрыто от соседей**: поле с нулевым доходом (организм не ест, поле
   статично), одно богатое пятно в трёх шагах. Правило соседа видит два равных соседа и стоит —
   **0 ходов**; окно радиуса 3 видит пятно и идёт — **> 0 ходов**;
4. невозможный радиус (1000) отвергается.

## Две неудачные попытки теста — и они поучительны

**Первый тест провалился:** я ожидал, что на «ровном» поле правило соседа не сдвинется. Оно
сдвинулось **4 раза из 5 шагов** — потому что, **съев** клетку, организм делает собственный
пол ниже соседей. То есть **выедание создаёт градиент**, и «ровное» поле не остаётся ровным.

**Второй тест провалился:** сравнение времени достижения острова дало **72 шага против 72**, хотя
`tiebreak` был `Left` — то есть при равенстве соседей правило соседа **дрейфовало влево** и находило
остров за точно известное число шагов. Тай-брейк работал **компасом**.

Оба раза причина была в моём представлении о сцене, а не в коде. Отсюда третий вариант: убрать
питание вообще (доход, содержание и урон = 0), и тогда **единственное, что может сдвинуть
организм, — то, что он видит**.

## Чего это не доказывает

- **Не доказывает, что окно лучше.** Тест показывает только, что окно **видит** то, чего не видят
  соседи. Выигрыш в выживании — отдельный вопрос, и он ещё не задан.
- **Бюджет чтения не покрывает окно:** `k` требует `2k` чтений, бюджет по умолчанию 3; при
  `k = 3` нужно 6. В коде скан **останавливается, когда бюджет кончился** (то же правило, что у
  всех цен), поэтому окно без увеличенного бюджета — это не дальнозоркость, а другой способ
  быть близоруким.
- Один мир, один сид на проверку; в двумерной решётке числа будут другими.

## Что дальше — и это уже не механизм

Ансамбль из 206/207: те же 40+ пунктирных сред, три политики (`Random`, `Memory`, `Sighted` с
`k = 3`) и бюджет чтения, достаточный для окна. Вопрос, который впервые корректен:

> **Когда сигнал для поиска есть у обоих, обгоняет ли окно память?**

Предсказание, которое запишу до прогона: на **редких** островах (период 12) окно должно выигрывать,
потому что память требует, чтобы пятно уже было найдено, а окно находит его с первого прохода; на
**плотных** (период 4) разницы быть не должно, потому что остров виден и одним соседом.
