# Координация агентов: разбор трёх аудитов и итоговый набор исправлений

**Дата:** 25.11.2026. **Что сделано:** три внешних аудита (файл `audit-marfagenez-coordination-2026-11-25.md`
и два разбора в переписке) разобраны построчно, **все ключевые утверждения проверены на нашем коде**
(скрипт-проба ниже), лучшие предложения сведены в один набор, спорные — отклонены с причиной.

---

## 1. Проверка утверждений аудита на реальном коде

Проба `probe_coord.py` (импортирует наш `tools/coord.py`, TZ=Europe/Moscow, 24.11.2026):

| № | утверждение аудита | результат проверки | статус |
|---|---|---|---|
| A | `cmd_stale` считает возраст через `mktime` от UTC-строки, поэтому при `TZ=Moscow` задача сразу «просрочена» | `mktime`: **180 мин** = ровно TTL; `timegm`: **0 мин** | **подтверждено, критично** |
| B | `_overlap` пропускает конфликт `docs/P*.md` ↔ `docs/PLAN-2026-11-24.md` | `[]` — конфликта не видит | **подтверждено** |
| C | пустая рабочая область выключает защиту | `_overlap([], …)` → `[]` | **подтверждено** |
| D | `_protected` обходится через `./…` | `./core/life.rs` → `[]` | **подтверждено** |
| E | `_protected` обходится через `../` | `literature/../core/x` → `[]` | **подтверждено** |
| F | два события одного агента в одну секунду затирают друг друга | 2 события → **1 файл**, остался последний | **подтверждено** |
| G | `close` не требует `verify` | `close` без `VERIFY` вернул **0** (закрыл задачу) | **подтверждено, критично** |
| H | `take` не проверяет, что `maint` берёт только `main` | проверки нет | **подтверждено** |
| I | `release --force` доступен любому агенту | проверки нет | **подтверждено** |
| J | `verify` не требует, чтобы его звал `main` | проверки нет | **подтверждено** |
| K | `add` принимает `accept: true` | проверки нет | **подтверждено** |
| L | «в `.coord/events/` есть файл с переводом строки в имени» | таких файлов нет | **не подтверждено** (артефакт чужой среды) |

**Вывод:** аудит прав по всем механическим дефектам; единственное неверное утверждение — про имя
файла события. Ошибки не косметические: две из них (**A** и **G**) позволяют либо объявить живую работу
мёртвой, либо закрыть задачу без всякой проверки.

## 2. Итоговый вердикт

Архитектура (каталоги состояний + `mkdir` + sha256 карточки + заявка/проверка/закрытие) **верна и
переписыванию не подлежит**. Дыры — в переходах между состояниями и в проверках прав. Достаточно
**десяти локальных правок**, ни одна не требует сети, CI, БД или правок `checks/` и `run.sh`.

## 3. Набор исправлений (сведён из трёх аудитов)

### Уже внедрено в этом цикле (F1–F5)

| № | что | закрывает | как проверено |
|---|---|---|---|
| **F1** | часы: `calendar.timegm` вместо `time.mktime` | A | проба: возраст 0 мин вместо 180 |
| **F2** | области: пустая область = **отказ**, нормализация `normpath`, запрет `..` и абсолютных путей; пересечение по литеральному префиксу **без границы `/`** | B, C, D, E | проба: `docs/P*.md` ↔ `docs/PLAN…` → конфликт; `./core/…` и `../core/…` → защищены |
| **F3** | события: имя `<ts>-<agent>-<pid>`, запись через `O_EXCL` | F | проба: 2 события → 2 файла |
| **F4** | `close` требует `VERIFY.json` с `ok: true` и совпадением sha256 карточки | G | проба: `close` без verify → отказ |
| **F5** | права в коде: `verify`/`close` — только `main`; `release --force` — только `main`; `take` для `kind=maint` — только `main`; `add` отвергает `accept` без `/` и тривиальные (`true`, `:`, `exit 0`) | H, I, J, K | проба: каждый вызов возвращает отказ |

### Следующая очередь (F6–F10) — каждая с проверкой, которая может провалиться

**F6. Двухфазное взятие с единственной commit-точкой.**
Собираем `active/.<id>.<pid>.tmp` (TASK.md + `.claim.json` + `HEARTBEAT.json`), затем один `os.rename`
в `active/<id>`. Пока `rename` не прошёл — задачи не существует. Плюс `recover` (только `main`):
сносит `.*.tmp` старше 5 минут, переносит `active/*` без `.claim.json` в `.coord/graveyard/`,
ломает замки старше 10 минут.
**Проверка:** убить процесс между созданием tmp и rename (`kill -9` в тесте) → в `active/` нет
«полувзятой» задачи; `recover` возвращает каталог в рабочее состояние.

**F7. Общий замок мутаций `.coord/.lock` (mkdir) на время `take`/`add`/`release`/`close`.**
Нужен потому, что проверка областей и `mkdir` — два действия, между ними гонка. Замок держится
миллисекунды; «протухший» (>120 с) ломается по возрасту.
**Проверка:** два параллельных `take` с пересекающимися областями (`&` в bash) → ровно один успешен.

**F8. Heartbeat и различение «медленно / умер».**
`heartbeat ID --agent X` делает `os.utime` на `.claim.json`. `stale` смотрит mtime claim, а не только
`taken_at`. `release --force` отказывает при свежем heartbeat. Дополнительно `boot_id`
(`/proc/sys/kernel/random/boot_id`) в claim: сменился — исполнитель точно мёртв.
**Проверка:** не обновлять heartbeat 35 минут → `stale` показывает задачу; обновить → не показывает.

**F9. Привязка результата к артефактам.**
`finish` строит `DONE.json` сам, с `artifacts: [{path, sha256, bytes}]`, и отказывает, если путь вне
объявленной области. `verify` пересчитывает хэши и **пишет `VERIFY.json`** (команда, код возврата,
хвост вывода). `close` требует зелёный `VERIFY.json`, свежее `finished_at`.
**Проверка:** подменить артефакт после `finish` → `verify` краснеет; `close` отказывает.

**F10. Атомарная запись файлов состояния.**
`atomic_write` (temp + `fsync` + `os.replace` + `fsync` каталога) для `.claim.json`, `DONE.json`,
`VERIFY.json`, `TASK.md`. Особенно важно для `map_ingest.py`: он перезаписывает `atoms.jsonl`
(~1000 ячеек) целиком, и смерть посередине усекает карту.
**Проверка:** `kill -9` во время приёма → `atoms.jsonl` либо старый, либо новый, но валидный JSONL.

### Уточнения, которые стоит взять из аудитов без отдельного кода

- **Один активный раунд на постоянную задачу** (`active/<parent>-*` без `DONE.json` → отказ).
- **Имя раунда** `<parent>-<ts>-<agent>` — снимает коллизию секунд и говорит, кто работал.
- **Закрытые задачи раскладывать по месяцам** `completed/<YYYY-MM>/` — без удаления истории.
- **`list` сортирует по приоритету** (число из карточки), а не по алфавиту: при трёх агентах иначе
  дисциплина выбора исчезает.
- **Таймаут accept — 600 с**, а не 3600: в карточку кладём точечные проверки, полный гейт — дело `main`.
- **`status`** — производный `STATUS.md`: pending/active, возраст, heartbeat, флаги `orphan`/`stale`.
  Восстановление картины после сбоя без чтения десятка каталогов.

## 4. Что отклонено и почему

| предложение | почему отклонено |
|---|---|
| брокер/очередь сообщений, БД, любой внешний сервис | инфраструктуры нет; всё должно работать на файлах и `mkdir` |
| полный baseline-снимок всех файлов области + watchlist на каждом `take` | на нашем дереве это тысячи файлов и сотни мегабайт; секунды превращаются в минуты. Достаточно хэшей **заявленных артефактов** (F9) |
| поколения задач (`gens/`) как обязательный механизм | для трёх **кооперативных** агентов это лишняя сущность: `boot_id` + heartbeat закрывают тот же риск. Оставляем как опцию, если появится некооперативный исполнитель |
| автоматическая оценка «доход на минуту» | метрика без телеметрии даёт фиктивную точность и провоцирует подгонку. Приоритет ставит человек/`main`, `list` только сортирует |
| трекинг «кто что читал» | шум дороже пользы; для восстановления достаточно `events/` + `status` |
| архивирование `completed/` в tar | месячных каталогов достаточно; tar — ручной шаг, не автоматика |
| «пусть агенты договариваются» | нужны механические правила; договорённости не проверяемы |
| `flock`/`fcntl` вместо `mkdir` | `mkdir` атомарен на локальной ФС, а `flock` не переживает смерть процесса предсказуемо и хуже работает на 9p |

## 5. Порядок внедрения

1. **Сейчас:** F1–F5 (сделано, см. §3).
2. **Следующий цикл:** F6 + F7 (взятие) — вместе, потому что оба меняют `cmd_take`.
3. **Затем:** F8 (heartbeat) + F9 (артефакты и `VERIFY.json`) — это закрывает «закрыть без проверки».
4. **Потом:** F10 (атомарная запись) + `status` + сортировка `list` + месячные каталоги.
5. **Проверка всей системы раз в неделю:** три теста на тестовой задаче — здоровый `accept` → 0,
   подложенный дефект → ≠0, `accept: true` → отказ на `add`. Если `true` проходит — приёмка ничего
   не значит.

## 6. Что это меняет в правилах (текст для `.coord/README.md`)

1. **Область обязательна.** Пустая область — отказ брать задачу. Область нормализуется: без `..`,
   без абсолютных путей.
2. **Права проверяются кодом, а не обещанием.** `verify`, `close`, `release --force`, `take` для
   `maint` — только `main`.
3. **Завершение без `VERIFY.json` невозможно.** `close` отказывает.
4. **`accept`-команда должна ссылаться на файл** (содержать `/`); `true`, `:`, `exit 0` — отказ при
   заведении задачи.
5. **Живой исполнитель защищён.** Свежий heartbeat → `release --force` отказ.
6. **Один активный раунд на постоянную задачу.**
7. **События не теряются**: имя содержит агента и pid.
