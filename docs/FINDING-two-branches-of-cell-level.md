# FINDING: две ветви уровня клетки, и почему `0.88` — не `cStar`

**Дата:** 2026-11-13
**Статус:** доказано в Lean, 6 теорем, без `sorryAx`
**Файл:** `laws/Medium/Capacity.lean`, раздел «The starved regime»

---

## Что было непонятно

При параметрах `M = 1.1, r = 0.8, income = 1.0` поле стабилизируется на
**0.88**. В `docs/` это число стояло рядом с формулой равновесия, и я
записывал его как «`c* = M·r = 0.88`». Это была ошибка чтения: `M·r` и `c*` —
**разные выражения**, и при этих параметрах они не совпадают.

## Что на самом деле

Уровень клетки задан как

```
cellLevel(M, r, k, t) = max( M − k·t·(1−r)/r ,  M·r )
```

Две ветви:

| ветвь | когда | значение |
|---|---|---|
| ненасыщенная | `k·t ≤ M·r` | `cStar = M + k·t − k·t/r` |
| голодная | `k·t > M·r` | `M·r` |

При `M = 1.1, r = 0.8, k = 1, t = 1.0`:

```
M·r    = 0.88
cStar  = 1.1 + 1 − 1/0.8 = 0.85
k·t    = 1.0  >  0.88      →  голодная ветвь
```

`max(0.85, 0.88) = 0.88`. **Измеренное 0.88 — это `M·r`, а не `cStar`.**
`cStar` при этих параметрах вообще не достигается.

## Почему это важно, а не косметика

При `M·r = 0.88 < income = 1.0` клетка **не может прокормить никого**:

```
kMaxCount = ⌊M·r / income⌋ = ⌊0.88⌋ = 0
```

Это не «мало еды» — это ровно ноль. Любое стояние на месте в такой среде
означает смерть, и именно поэтому движущийся организм обгоняет стоящего.
Разница между 0.85 и 0.88 — не арифметическая мелочь, а **граница режима**.

## Что доказано

Шесть теорем, все `[propext, Classical.choice, Quot.sound]`:

| теорема | утверждение |
|---|---|
| `starved_level_measured` | `cellLevel 1.1 0.8 1 1 = 0.88` |
| `cStar_below_Mr_measured` | `cStar 1.1 0.8 1 1 = 0.85` |
| `nobody_fed_measured` | `0.88 < 1` |
| `fed_level_measured` | `cellLevel 2 0.8 8 0.2 = 1.6` |
| `fed_level_is_cStar_measured` | `cStar 2 0.8 8 0.2 = 1.6` |
| `starved_branch` | `M·r < k·t → cellLevel M r k t = M·r` |

`starved_branch` — общая форма: она закрывает ту сторону, которую
`cellLevel_eq_cStar` не покрывала. Прежняя теорема требовала `k·t ≤ M·r`;
новой не было, и именно в ней лежал измеренный режим.

## Гипотеза `r < 1`, а не `r ≤ 1`

Первая версия `starved_branch` требовала `r ≤ 1` и не доказывалась. Причина не
в тактике: при `r = 1` поле не регенерирует, и утверждение вырождается.
Правильная гипотеза — `r < 1`. Это записано в LESSONS.md, урок 11.

## Что это не доказывает

1. **Не доказывает**, что измеренные 0.88 получены именно этой формулой —
   только что формула даёт 0.88 при этих параметрах.
2. **Не доказывает** ничего про `k ≥ 2` в голодном режиме. `starved_branch`
   верна для любого `k`, но измерений с `k ≥ 2` при этих параметрах нет.
3. **Не доказывает**, что `M·r` — устойчивое равновесие динамики. Доказано
   только значение `cellLevel`; сходимость к нему не проверялась.
4. **Не объясняет** расхождение `C = 400` против измеренных `C = 80`
   (см. открытый вопрос в `docs/`).

## Защита на будущее

Если число совпало с формулой — проверить, с **какой** формулой. `0.88`
совпадало с `M·r` и не совпадало с `cStar`; я выбрал первое совпадение и
записал его как второе. Правило: **подставлять в формулу, а не узнавать
число**.
