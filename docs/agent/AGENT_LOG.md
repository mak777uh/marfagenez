# AGENT_LOG.md — журнал циклов

**Одна запись на цикл.** Цикл — это «нашёл вопрос → арифметика → прогон →
числа → запись → коммит». Запись пишется **в конце цикла**, перед коммитом.

Правило: если запись не изменила следующее действие — это не запись, а
пересказ. Пересказ не нужен, он уже есть в `git log`.

Формат записи — ровно шесть полей. Все обязательны.

---

## Шаблон

```
### Цикл N — <дата> — <коммит>     <-- шаблон, не запись
- **Вопрос:**
- **Арифметика:** (число до прогона)
- **Что сделано:**
- **Числа:** (что вернул прогон, дословно)
- **Состояние на конец цикла:** (где именно оборвалось — файл:строка,
  что запущено, что не запущено)
- **Что не сработало:** (обязательно; «ничего» — подозрительный ответ)
```

## `void` в `results/` — остаётся (решено 2026-11-15)

Было: 20 записей с вердиктом `void` лежат в версионированном `results/`
рядом с `passed` и `failed`. Вопрос был — место ли им там, или это мусор,
который надо вычистить.

**Решение: остаются.** Оно выводится из контракта, а не назначается:

- `AGENTS.md` §4: `void` — «мы не спросили», и это **знание о дизайне**,
  а не отсутствие знания. Выбросив запись, мы теряем различие между
  «эксперимент поставлен и оказался недействителен» и «эксперимента не
  было». Это ровно тот класс ошибок, из-за которого в проекте появилось
  правило «прогон без записи не был прогоном».
- `AGENTS.md` §5: версионируется `results/`, не версионируются артефакты
  (трассы). `void` — запись, а не артефакт: она маленькая и содержит
  причину.
- Причина в каждой записи заполнена (проверено: 20/20), поэтому запись
  читается без прогона.

**Что при этом нужно:** `void` не должен тихо копиться. Правило —
`void`-запись либо получает перепрогон, который её заменяет, либо живёт с
причиной, которая объясняет, почему перепрогон невозможен (например,
«записано до переноса клампа»). Обе формы сейчас в данных есть.

**Чего это не решает:** что делать с `void`, который нельзя перепрогнать
и который устарел вместе с кодом. Такие записи остаются как история, но
их надо отличать от живых — сейчас в JSON нет поля «устарела вместе с
коммитом X», и это открытый пункт, а не решённый.

  `proportional_never_overdraws_the_reserve` перебирает 216 комбинаций и
  требует `energy >= 0`. То, что организм при этой стратегии голодает, —
  не дефект, а предмет измерения.
- **Тест нашёл дефект в первой версии:** при `repair_cost = 0` бесплатная
  починка не происходила, потому что вся ветка была под условием
  `energy > 0`. Исправлено, случай закреплён тестом
  `proportional_handles_free_repair`.
