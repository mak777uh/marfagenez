# AGENT_STATE.md — где проект сейчас

**Этот файл читает следующий агент первым.** Он отвечает на четыре вопроса:
где мы, что делаем сейчас, что дальше, чего не трогать. Он не дневник —
дневник это `AGENT_LOG.md`.

**Гейт:** этот файл обязан быть закоммичен **в том же коммите**, что
последнее изменение репозитория. Проверяет `run.sh agents` по истории Git,
а не по времени файла: после clone/checkout mtime врёт.

**Обновлять в конце каждого цикла**, перед `git commit`.

## §1 Окружение

**Работать только в WSL.** Единственный живой клон — `/root/marfagenez`.

| | путь | статус |
|---|---|---|
| **WSL** | `/root/marfagenez` | **главный**, здесь прогоны и коммиты |
| Windows | `C:\Users\Admin\Documents\Qoder\2026-10-18\82ab86cd\marfagenez` | **устаревший**, только чтение |

Это **разные объектные базы Git**, а не один смонтированный каталог: коммит,
существующий в одном клоне, в другом даёт `fatal: Not a valid object name`.
`run.sh:18` делает `cd /root/marfagenez`, поэтому любой прогон — из WSL.

**Не править Windows-клон.** Не «синхронизировать» вручную. Источник правды —
remote `https://github.com/mak777uh/marfagenez.git`, ветка `master`.

Инструменты в WSL: `cargo`, `lake` (Lean), `verus` (`/usr/local/bin/verus`),
`node`, `python3`, `powershell.exe` (для `verify_all.js`).

## §3 Текущий вопрос

**Что делает следующий раунд:** закоммитить правки `run.sh` + `AGENTS.md` +
этот файл одним коммитом, затем прогнать `./run.sh all` и убедиться, что он
зелёный без инъекций.

**Почему именно это:** пока `all` красный на чистом дереве, гейт не отличает
«мы сломали» от «мы не доделали». Красный на чистом дереве — это шум, а шум
гейт обесценивает.

- **`results/`** — записи прогонов версионируются. Удалять только файлы,
  созданные текущей инъекцией, **по имени**, не глобом: `rm -f results/*/run-*.json`
  уже однажды снёс 19 закоммиченных записей.
- **Трассы** (`trace-*.json`, 66–177 MB) — артефакты, в `.gitignore`. Семь
  трасс сломали push 2026-11-13 (GH001, >100 MB).
- **`docs/FINDING-*.md`** — не переписывать задним числом. Новая находка —
  новый файл; старая остаётся как была, даже если неверна.
