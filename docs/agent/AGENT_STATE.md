# AGENT_STATE.md — где проект сейчас

**Этот файл читает следующий агент первым.** Он отвечает на четыре вопроса:
где мы, что делаем сейчас, что дальше, чего не трогать. Он не дневник —
дневник это `AGENT_LOG.md`.

**Гейт:** этот файл обязан быть закоммичен **в том же коммите**, что
последнее изменение репозитория. Проверяет `run.sh agents` по истории Git,
а не по времени файла: после clone/checkout mtime врёт.

**Обновлять в конце каждого цикла**, перед `git commit`.

## §1 Окружение

**Работать только в WSL.** Единственный живой клон — `/root/marfagenez`.

| | путь | статус |
|---|---|---|
| **WSL** | `/root/marfagenez` | **главный**, здесь прогоны и коммиты |
| Windows | `C:\Users\Admin\Documents\Qoder\2026-10-18\82ab86cd\marfagenez` | **устаревший**, только чтение |

Это **разные объектные базы Git**, а не один смонтированный каталог: коммит,
существующий в одном клоне, в другом даёт `fatal: Not a valid object name`.
`run.sh:18` делает `cd /root/marfagenez`, поэтому любой прогон — из WSL.

**Не править Windows-клон.** Не «синхронизировать» вручную. Источник правды —
remote `https://github.com/mak777uh/marfagenez.git`, ветка `master`.

Инструменты в WSL: `cargo`, `lake` (Lean), `verus` (`/usr/local/bin/verus`),
`node`, `python3`. `powershell.exe` — только запасной путь для
`verify_all.js`: основной — `node` из WSL.

## §2 Статус задачи

**Сейчас: `сделана`.**

Одна задача, не список. Формат: `не начата` / `в работе` / `заблокирована` /
`сделана`.

- **Задача:** убрать `structure` (`structure ≡ 1 − damage`, C1 из
  `PLAN-NEXT.md` §4) и починить найденный по дороге дефект ремонта.
- **Статус:** `сделана` (2026-11-14).
- **Готово:**
  - `structure` удалён из `core/src/organism.rs` (поле, `structure()`,
    `Organism::new` потерял первый аргумент) и из 6 Python-портов; смерть по
    `structure <= 0` была тем же событием, что `damage >= 1`.
  - **Дефект ремонта.** Старое правило «чини сколько сможешь» было ловушкой:
    `repaired = energy / repair_cost`, и обратное умножение
    `repaired * repair_cost` округлялось вверх до всего резерва. Организм,
    просивший 1e-9 ремонта, платил всё и умирал от голода, сохранив урон.
    Теперь ремонт «всё или ничего»: он выполняется, только если резерв
    покрывает весь урон (`damage * repair_cost < energy`), иначе урон
    переживает шаг. Найдено тестом `damage_accumulates`, который падал на
    `assert!(alive)`.
  - `run.sh do_claims` больше не зависит от `powershell.exe`: сначала
    пробуется `node` из WSL, `powershell.exe` — запасной путь. Раньше в
    окружении без Windows-моста проверка не запускалась вовсе.
- **Проверено:** `./run.sh all` — Rust 194 passed, Lean 290+27 теорем,
  `sorry: 0`, Verus 41 verified, контракт 149 записей / 0 нарушений,
  `verify_all.js` 10/10, `ВСЁ ЗЕЛЁНОЕ`.
- **Не сделано:** `checks/log_check.py` не написан; `docs/UNREPRODUCIBLE.md`

## §3 Текущий вопрос

**Что делает следующий раунд:** прочитать `docs/PLAN-NEXT.md` и начать блок A
(день 1 по §6: A1, A3, A5, D-1, D-2). Блок B ждёт решений владельца D1/D3/D4.
Блок C закрыт частично: C1 (`structure`) решён удалением, а не «сделать
независимой» — независимой организации в модели нет, и производное число,
изображавшее её, было хуже честного отсутствия.

**Почему именно это:** три аудита 2026-11-14 сошлись на одном: модель
отвечает на более узкий вопрос, чем заявлено, и самый дешёвый способ поднять
ценность — закрыть разрыв между заявлением и тем, что меряется, а не
расширять модель.

- **`results/`** — записи прогонов версионируются. Удалять только файлы,
  созданные текущей инъекцией, **по имени**, не глобом: `rm -f results/*/run-*.json`
  уже однажды снёс 19 закоммиченных записей.
- **Трассы** (`trace-*.json`, 66–177 MB) — артефакты, в `.gitignore`. Семь
  трасс сломали push 2026-11-13 (GH001, >100 MB).
- **`docs/FINDING-*.md`** — не переписывать задним числом. Новая находка —
  новый файл; старая остаётся как была, даже если неверна.
