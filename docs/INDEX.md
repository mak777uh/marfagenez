## 3. Куда писать (и куда **не** писать)

| что появилось | куда | правило |
|---|---|---|
| новый **результат** с числом | `docs/FINDING-NNN.md` + строка в `POSITIVE.md` | начинается с `**Слону:**`; история не переписывается |
| **отрицательный** результат | `docs/FINDING-NNN.md` + `docs/ELIMINATED.md` | отрицательный результат — тоже результат |
| **литературный** аналог | `docs/ELEPHANT-LITERATURE.md`, запись `L-NNN` | поле «Проверено»: полный текст / аннотация / вторые руки |
| **формула** из литературы | там же, `F-NNN`, **в наших символах** + перевод | без перевода переменных сравнение недействительно |
| **предсказание** до прогона | `docs/PREDICTIONS.md`, с датой | `WORK-LOOPS.md` §2 шаг 3 |
| **вопрос**, который решает не модель | `docs/QUESTIONS.md`, `Q-NNN` | в пустоту не спрашивать (`AUTONOMY.md` §1.1c) |
| **закрытие линии** | `docs/<ЛИНИЯ>-LINE-CLOSED.md` | что измерено, что ошибки, почему закрыто |
| **разбор внешнего отзыва** | `.dsh-switchman/NOTES-external-review.md` | с тегами и проверкой по коду |
| рабочий скрипт | **не в корень**; удалить после использования | в корне лежат только файлы проекта |

## 4. Соглашения об именах, без которых теряется связь

- `FINDING-NNN.md` — порядковый, **не переиспользуется**; номер только растёт.
- `L-NNN` / `F-NNN` — литература и формулы; ID не переиспользуются.
- `Q-NNN` — вопросы; `§N` — разделы `AGENTS.md`; `§4.x` — разделы `POSITIVE.md`.
- Закрытия линий: `<ЛИНИЯ>-LINE-CLOSED.md`, где линия — `SKIN`, `EXCHANGE`, `ORGANISATION`, `HISTORY`, `CHOICE`.
- Датированная поправка — **внутри** старого файла, отдельным блоком, не заменой текста.

## 5. Что проверить перед любым коммитом

```bash
wsl -e bash /root/marfagenez/run.sh all      # ожидается «ВСЁ ЗЕЛЁНОЕ»
```

Гейт проверяет **форму**: числа в документах против дерева, наличие обязательных полей, непрерывность журнала
циклов. Он **не** проверяет, верна ли физика — это отдельная работа (см. `LESSONS.md`).
