# DESIGN-LEAN-SYNTHESIS.md — как собрать наресерченные формулы в один конструкт на Lean

**Дата:** 2026-11-20. **Основание:** `ZOOM-OUT-2026-11-20.md` (три структуры), реестр `F-001`…`F-021`.
**Зачем:** Lean у нас уже есть; он позволяет не «написать формулу», а **доказать, что из одного следует другое**. Это
и есть сборка слона математикой.

---

## 1. Что должно быть в конструкте

Три структуры из отдаления дают три слоя, и Lean нужен **не для пересказа**, а для **связей между ними**:

```
слой A (накопление с порогом):  μ(D), H(T) = ∫μ,  S(T) = exp(−H)
слой B (бюджет):                income = maintenance + repair + store,  приоритет поддержания
слой C (организация):           замкнутость и самоподдержание как условия на множества видов
```

**Связи, которые надо доказать:**

| связь | утверждение | откуда |
|---|---|---|
| `A → B` | при приоритете поддержания допустимая доля починки монотонно падает с внешней смертностью | `L-058`, `P-005` |
| `B → A` | если починка оплачивается из бюджета, стационарный груз конечен ровно при «штраф затухает» | `F-003`, `F-002` |
| `A × C` | смерть как **канал удаления** меняет **тип** перехода, не масштаб | `L-023`, `L-024` |
| `B × C` | цена границы = двойственная переменная ограничения на мембрану; кусочно-постоянна | `L-050` |

## 2. Что формализуемо **сейчас** (алгебра, без асимптотик)

Это важно: асимптотики (`D* ~ (1−h)^(−1/2)`) в Lean дороги и почти всегда требуют теории пределов и порядков.
**Алгебра и монотонность — дешевы и дают больше.**

### T-1 · Единственность положительного корня (нет складки)

```
для λ > 0, μ₀ > 0, δ > 0, h < 1:
  уравнение λ·D² + μ₀·D = δ/(1−h) имеет ровно один корень D > 0
```

**Почему это важно:** это **формальное** утверждение «это не бифуркация» (`SYNTHESIS-2026-11-20.md` §1.2).
Сейчас оно у нас только словами. В Lean — `nlinarith` по дискриминанту и знаку ветвей.

### T-2 · Порог `h < 1` как граница конечности груза

```
для фиксированных λ, μ₀, δ:  (∃ D > 0, λD² + μ₀D = δ/(1−h))  ⟺  h < 1
```

**Почему:** это наш порог **без** слова «критичность», и он верен **по построению** — что честно и записывается.

### T-3 · Монотонность оптимальной доли починки по внешнему риску

```
если риск r растёт, а доход фиксирован,
то оптимальная доля дохода в починку не возрастает
```

**Почему это ценно:** это `P-005` в формальной форме, и это **единственное** место, где «выбор» становится
доказуемым, а не измеренным.

### T-4 · Инвариант вещества

```
Σ(поле + организм + отход) сохраняется шагом
```

**Почему:** без этого третья часть слона не проверяема (`ZOOM-OUT` §3). Это же — условие для `B×C`.

## 3. Что **не** формализуем и почему (честно)

1. **Асимптотический показатель** `−1/2` — требует теории пределов; выгоднее измерить прогоном и записать в
   `POSITIVE` как измеренное, а не доказанное.
2. **Гомпертц из избыточности** — нужно комбинаторное определение `k`-из-`n` отказа; формализуемо, но это отдельный
   модуль и отдельная линия.
3. **«Организация» в смысле COT** — требует теории множеств с замыканием по реакциям; сделать можно, но сначала
   надо решить, что считаем видом.

---

## 4. Порядок

1. **T-1 и T-2** — один модуль, алгебра, `nlinarith`; даёт формальный ответ на «складка или нет».
2. **T-4** — инвариант в Rust-ядре + теорема о сохранении; открывает третью часть слона.
3. **T-3** — монотонность; требует аккуратной постановки (что именно оптимизируется).
4. Только потом — асимптотики, если понадобятся.

**Правило:** в Lean идёт то, что **уже измерено** или **является алгеброй**; Lean не место для гипотез.
