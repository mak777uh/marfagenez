# `F-030`: метрики открытости — операциональны ли они

**Дата:** 25.11.2026. **Агент:** `main`. **Воспроизведение:** `python3 tools/openness_metrics.py`.

## Что предлагает узел

```
изменение (novelty):  расстояние Левенштейна между поколениями
разнообразие:         энтропия Шеннона по типам
сложность:            колмогоровская (аппроксимация сжатием)
```

Вопрос раунда не «правильные ли это метрики», а **считаются ли они** на наших данных. Метрика, которую нельзя
посчитать, — не метрика.

## Числа

| метрика | значение на карте |
|---|---|
| энтропия по `kind` | **2,124 бит** при 7 типах (максимум 2,807) |
| энтропия по `domain` | **4,808 бит** при 40 доменах (максимум 5,322) |
| сложность (сжатие) | 2 450 007 → **620 272 байт**, отношение **0,253**; **556** сжатых байт на ячейку |
| новизна по истории | 39 шагов, **29 с приростом**, в среднем **6,2 ячейки**, максимум **43** |

## Что считается, а что нет

**Считаются:** энтропия по типам и по доменам — прямо по карте; сжатие — как приближение колмогоровской
сложности (zlib, уровень 9).

**Не считается как задумано:** **расстояние Левенштейна между поколениями**. У карты нет «поколений»: она
растёт непрерывно, и «поколение» пришлось бы определять произвольно (по коммитам? по дням?). Поэтому новизна
измерена **приростом ячеек за коммит** — это операциональная замена, а не та же величина.

**Практическое следствие:** из трёх предложенных метрик одна требует переформулировки. Это не придирка:
если оставить «Левенштейн между поколениями» в узле, читатель будет искать величину, которой нет.

## Что числа говорят о самой карте

- **Энтропия по доменам 4,81 из 5,32** — карта распределена по 40 доменам довольно ровно, без одного
  доминирующего.
- **Сжатие 0,253** — высокая избыточность: формулировки ячеек похожи (что ожидаемо для одного автора и одного
  шаблона записи). Это ограничение: «колмогоровская сложность» частично меряет наш шаблон, а не содержание.
- **Средний прирост 6,2 ячейки за коммит** совпадает с порядком партий агентов (5 ячеек) — то есть история
  роста отражает именно работу агентов, а не «естественный» рост.

## Опровергающее условие

Если бы какая-то метрика не посчиталась на данных (например, энтропия вырождена при одном типе), инструмент
вернул бы 1 и напечатал «НЕОПЕРАЦИОНАЛЬНО». Сейчас все три посчитались, но одна — в переформулированном виде.

## Что осталось

- **Переформулировать новизну в узле** `F-030`: «прирост за шаг» вместо «Левенштейн между поколениями», с
  определением шага (коммит). Это правка данных, отдельным раундом.
- Проверить, не является ли сжатие в основном мерой шаблона: сравнить сжатие с перемешанными полями.

## Исправление 25.11.2026: новизна переформулирована в данных

Формулировка в корпусе (`docs/ELEPHANT-LITERATURE.md`, источник узлов) была

```
изменение (novelty):  расстояние Левенштейна между поколениями
```

стала

```
изменение (novelty):  прирост числа ячеек за шаг (коммит);
                      Левенштейн между поколениями НЕ ИСПОЛЬЗУЕТСЯ — у карты нет поколений,
                      она растёт непрерывно (проверено: docs/FORMULA-OPENNESS.md)
```

`kg/` пересобран (`migrate.py` → `kg.py build` → `regress.py`), эмбеддинги обновлены.

**Почему это правка данных, а не косметика:** метрика, которую нельзя посчитать, будет искаться читателем и
не найдётся. Теперь в узле стоит величина, которая **считается** (`tools/openness_metrics.py`: 39 шагов,
29 с приростом, в среднем 6,2 ячейки), и прямо сказано, чего не делаем.

**Что не изменилось:** две другие метрики (энтропия по типам и сжатие) остались как были — они считаются.
