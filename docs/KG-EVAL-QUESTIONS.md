# KG-EVAL-QUESTIONS.md — круг вопросов с контекстом (заморожено до импорта)

**Дата:** 2026-11-20. **Правило:** вопросы и gold-множества **не меняются** после начала импорта; новая версия — новый
файл с датой. Иначе метрика подгоняется задним числом.

**Формат вопроса.** `context` — зачем он нужен базе; `gold` — какие узлы обязаны появиться; `must say` — что должно быть
сказано словами (проверяется человеком/моделью); `budget` — потолок токенов ответа.
**Метрики:** покрытие gold (recall), доля лишних узлов (1 − precision), число открытых файлов (**должно быть 0**),
токены. Прогон — каждый круг; **два круга стагнации ⇒ пересмотр схемы**.

---

## A. Содержательные (15)

### E-01 · Цена удержания
**context.** Основной критерий постановки: агент должен отвечать одним `expand`, не открывая markdown. Цена — центральное
понятие нашего корпуса и главный мост к литературе.
**gold.** `C-001`, `C-002`, `F-023`, `EXP-SHADOW-PRICE`, `EXP-PRICE-KINKS`, `FINDING-317`, `FINDING-318`, `L-062`
**must say.** цена равна нулю ровно тогда, когда ограничение не связывает; излом в точке, где перестаёт связывать лучшая
альтернатива (`a = I − s − r_max`); это **теневая** цена, а не наблюдаемая.
**budget.** ≤ 1200.

### E-02 · Порог складки
**context.** Проверка моста (`P1`): наш «полюс параметра» и чужой «порог» — разные объекты, пока не выписан alignment-claim.
**gold.** `F-025` (√ как масштаб складки), `L-023`, мост `A↔B` (ожидается, **сейчас отсутствует**)
**must say.** `√` у порога — универсальный масштаб складки, не наше открытие (claim отозван, `FINDING-316`).
**budget.** ≤ 800.

### E-03 · Замыкание
**context.** Различает цепь / частичное / цикл; мера должна быть воспроизводима без чтения кода.
**gold.** `C-003`, `EXP-CLOSURE-MEASURE`, `FINDING-319`, `L-060`
**must say.** значения 0.25 / 0.75 / 1.0 для трёх топологий; контроль в первом прогоне был **неверным** (ожидалось 0.75,
верно 1/N).
**budget.** ≤ 900.

### E-04 · Порог Πλ ≤ 1/6
**context.** Единственное утверждение с двумя независимыми локаторами — проверка того, что провенанс поднят честно.
**gold.** `C-004`, `L-051`, `F-019`
**must say.** две ссылки (PLOS figures + ASU chapter); извлечённое ≠ установленное; статус поднят **после** проверки, а
не по уверенности модели.
**budget.** ≤ 700.

### E-05 · Опровергнутая формула
**context.** База обязана помнить, что мы **отбросили**, иначе агент повторит ошибку.
**gold.** `C-007`, `L-081`
**must say.** `1/(m+1)` неверно; правильный показатель `1/k`; показатель привязан к типу, не к числу каналов.
**budget.** ≤ 700.

### E-06 · Цена ремонта и потолок
**context.** Проверка, что «невозможные числа» ловятся до записи, а не после.
**gold.** `F-001`, `FINDING`-потолок, эксперименты по ёмкости
**must say.** `c* = M − t(1−r)/r`, а не `M − t/r`: **порядок операций** был ошибкой (FINDING-140).
**budget.** ≤ 900.

### E-07 · Память против зрения
**context.** У нас есть A-уровень (Lean) и C-уровень (симуляция) об одном и том же — база должна их **не** склеивать.
**gold.** эксперименты памяти, `FINDING` по memory/remember, Lean-модули `Medium`
**must say.** память не экономит ни одного чтения; выигрыш даёт обратная связь из мира, а не слот памяти.
**budget.** ≤ 1000.

### E-08 · Что мы **не** утверждаем
**context.** Негативные границы — часть знания; агент обязан их выдавать.
**gold.** `NOT-CLAIMED.md` (как `basis: stipulative` или `question`), `docs/ELIMINATED.md`
**must say.** «ребёнок» — причина дизайна, не предмет; `f64` не доказан; Verus доказывает **копии**.
**budget.** ≤ 800.

### E-09 · Где кончается применимость формулы
**context.** Проверка `context` как объекта с интервалами, а не прозы.
**gold.** формулы с `cases`, `CTX-*`
**must say.** `med ≈ 15·feed/kill` только при `D_X = 0.01`; за границей формула ложна.
**budget.** ≤ 700.

### E-10 · Что читала наука про теневое ценообразование
**context.** Мост к литературе должен быть переходом, а не списком ссылок.
**gold.** `L-062`, `C-001`, `C-002`
**must say.** двойственные переменные LP = химические потенциалы (утверждение авторов); наша цена — **аналогия**,
`analogous_to`, не `same_as`.
**budget.** ≤ 900.

### E-11 · Репликация vs повтор
**context.** Q17: три тира, иначе «мы повторили» звучит громче, чем есть.
**gold.** прогоны с ≥3 сидами; определение термина `T2`
**must say.** тот же сид — целостность, не репликация; репликация = другая реализация **или** согласие Lean и прогона.
**budget.** ≤ 700.

### E-12 · Что сломается, если изменить шаг клетки
**context.** Проверка зависимостного устаревания (`P3`): правка кода должна помечать зависимые утверждения.
**gold.** `FINDING-140`, все прогоны с `code_hash` до правки
**must say.** отозваны числа при старом порядке; какие именно — перечислить, а не «много».
**budget.** ≤ 1000.

### E-13 · Откуда взялась мера замыкания
**context.** Проверка цепочки `claim → formula → experiment → data` без открытия файлов.
**gold.** `C-003`, `EXP-CLOSURE-MEASURE`, `run-*.json`, `FINDING-319`
**must say.** мера — свойство графа, не динамики; контроль сработал неверно в первом прогоне.
**budget.** ≤ 900.

### E-14 · Согласованы ли наши законы между собой
**context.** Шесть законов + Lean; база должна уметь показать пересечения, а не «всё ок».
**gold.** `C-001…C-008`, `F-001…F-031`, `checks/consistency.py`
**must say.** какие пары законов используют один символ с разными единицами (если есть) — это ищет размерностный чекер.
**budget.** ≤ 1000.

### E-15 · Самое слабое место корпуса
**context.** База должна уметь сказать, где она тонка (`frontier`, `without_evidence`), а не только хвалить себя.
**gold.** `meta.frontier`: `without_evidence`, `extracted_only`
**must say.** 27 узлов без свидетельств и 113 только `extracted`; из 88 литературных записей полный текст читался **один раз**.
**budget.** ≤ 700.

## B. Негативные контроли (5) — правильный ответ «мы этого не знаем»

### N-01 · Оптимальная доля ремонта
**context.** Классическая ловушка: правдоподобное число выглядит как результат.
**must say.** «не знаем»; в корпусе нет измерения оптимума; любое число — выдумка.

### N-02 · Влияет ли размер мира на цену удержания
**context.** Проверка, что агент не путает **неизмеренное** с **опровергнутым**.
**must say.** «не измеряли»; `not_tested`, не `refuted`.

### N-03 · Сколько стоит починка в живых системах
**context.** Мост `B×C` не выписан — агент обязан это заметить.
**gold.** ожидается `Gap` `B×C`
**must say.** «моста нет»; числа из биологии не переносятся без отображения параметров.

### N-04 · Доказано ли, что модель описывает реальный мир
**context.** Проверка границы Lean: теорема о `ℝ` не подтверждает мир.
**must say.** «нет»; Lean доказывает **внутри модели**; `world`-утверждений у нас нет.

### N-05 · Есть ли у нас полный текст по L-051
**context.** Проверка честности провенанса: статус записи не должен выдаваться за прочитанный текст.
**must say.** «нет, читались фрагменты/аннотация»; в реестре один полный текст (`L-007`).

## C. Как считать

| метрика | цель |
|---|---|
| покрытие gold (recall) | ≥ 0.8 на A, **1.0 на B** |
| лишние узлы | ≤ 0.2 |
| открытых файлов | **0** |
| токены | ≤ 15k на карту + ответ |
| негативные контроли | **5/5** «не знаем», без выдуманных чисел |

**Стоп-правило:** два круга без роста recall ⇒ сначала чинить схему/`context`, не добавлять узлы.
