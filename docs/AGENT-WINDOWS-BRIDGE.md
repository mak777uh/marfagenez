# Как подключить агента с доступом только к Windows и GitHub

**Дата:** 26.11.2026. **Задача:** внешний агент умный и быстрый, но не имеет доступа к WSL, где живёт
репозиторий. Как дать ему работу, не ломая историю и проверки.

## Три возможных канала — и почему выбран третий

| канал | как | плюсы | минусы |
|---|---|---|---|
| **A. GitHub (ветка + PR)** | клонирует репозиторий в Windows, работает в ветке, пушит | полноценная история, ревью через PR | конфликты в генерируемых файлах (`kg/nodes.jsonl`, `results/`); я не могу мержить, пока у меня локальные незапушенные правки; агент не может прогнать `run.sh` |
| **B. Прямой доступ к файлам WSL** (`\\wsl.localhost\Ubuntu\root\marfagenez`) | правит файлы прямо в ext4 | мгновенно | медленный 9p, ломает права, агент видит и может сломать `atoms.jsonl`; никакой изоляции |
| **C. Windows-обменник + я публикую** | кладёт файлы в `C:\111\graph-bridge\outbox\`, мой `--watch` их забирает | изоляция, валидация до применения, ноль конфликтов, история только из моей руки | нужен мой запущенный мост; задержка до 30 с |

**Выбран C** по одной причине: у нас правило «новые ячейки не правятся руками». Кто бы ни был автором,
файл проходит один и тот же `map_ingest` с проверками контракта, дублей и сирот. Автор не может обойти
проверку, потому что не имеет прямого доступа к `atoms.jsonl`.

## Как это устроено

```
агент (Windows)                     я (WSL)
C:\111\graph-bridge\outbox\*.atoms.jsonl   →  tools/win_bridge.py --serve
C:\111\graph-bridge\outbox\*.edges.jsonl        ├─ валидация (atom, statement, works, kg_ref)
C:\111\graph-bridge\outbox\*.questions.jsonl    ├─ dry-run map_ingest
                                                 ├─ применение (только если dry-run зелёный)
C:\111\graph-bridge\ack\<имя>.json       ←  └─ отчёт: что принято, что отклонено и почему
C:\111\graph-bridge\STATE.md              ←  снимок: числа карты, очередь DOI, правила, план
```

**STATE.md** пересобирается при каждом проходе. В нём: размеры карты, состояние проверок, очередь
источников, копии плана и конвенций единиц. Агент читает его **вместо** репозитория — видит контекст, не
имея доступа к WSL.

## Что агенту можно, а что нельзя

| можно | нельзя |
|---|---|
| новые ячейки `<имя>.atoms.jsonl` (3–5 за партию) | править `atoms.jsonl`, `edges.jsonl`, `kg/`, `results/` |
| связи `<имя>.edges.jsonl` (обязательны) | пушить в `master`, переписывать историю |
| вопросы к числам `<имя>.questions.jsonl` | ставить `analogous` без обоснования |
| читать `STATE.md`, `PLAN.md`, `UNITS.md` | выдавать реконструкцию за цитату |

## Требования к ячейке (проверяются до применения)

1. `atom` начинается с `WIN-` и уникален;
2. `statement` ≥ 40 символов, с числами и единицами;
3. `kind` — `measurement` / `claim` / `definition` / `gap`;
4. `confidence` — `high` / `medium` / `low`;
5. `works[0]`: **doi + locator + quote** — все три, локатор на раздел/таблицу/уравнение;
6. `kg_ref` — на какой узел `kg/` ложится;
7. **связь** в `.edges.jsonl` — иначе `map_ingest` откажет (правило цеттелькасте́на).

## Чем агенту полезнее всего заниматься

**Очередь `docs/L-DOI-GAPS.md` — 40 узлов `L-*`, чьих источников нет в карте.** Это настоящий рычаг
покрытия: пока работы нет в карте, `S`-пара для узла невозможна физически.

Партия = **один DOI**, 3–5 ячеек с локаторами и цитатами, `kg_ref` на соответствующий `L-*`.
Он умеет искать по открытому вебу и быстро читать аннотации — это его сильная сторона.

## Что остаётся за мной

- прогон `map_ingest`, `kg/`, эмбеддингов и гейта;
- решение по спорным вердиктам и уровню (`level D` до проверки полного текста);
- коммит и push — **история пишется только из WSL**, поэтому её нельзя разветвить.

## Проверено на практике

26.11.2026 канал прогнан целиком: файл из `outbox\` прошёл валидацию, `dry-run`, применение и появился в
карте вместе с ребром; затем тестовая ячейка удалена (`docs/MAP-ERRATA.md`). Отказ тоже проверен: партия без
связи не применилась, файл остался в `outbox\` и после исправления прошла.

## Запуск

```bash
cd /root/marfagenez
python3 tools/win_bridge.py --watch 30     # постоянный приём
python3 tools/win_bridge.py --state        # только обновить STATE.md
```
