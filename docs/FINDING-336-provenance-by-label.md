# FINDING-336 — метка «читал полный текст» сама делала узел свидетельством

**Дата:** 2026-11-21. **Основание:** внешний разбор брифа и проверка кода; `kg/migrate.py::literature()`.

## Что было

В `kg/migrate.py` происхождение узла литературы выбиралось по подстроке в тексте реестра:

```python
chosen = "verified_agent" if "полный текст" in level.lower() else "extracted"
"provenance": chosen,
"evidence": [{"kind": "literature", "ref": "docs/ELEPHANT-LITERATURE.md",
              "strength": "strong" if chosen == "verified_agent" else "weak"}],
```

Ни файла, ни хеша, ни локатора фрагмента не требовалось: единственная ссылка на свидетельство — сам реестр.

## Числа

`python3 kg/kg.py map` до правки: в `nodes.jsonl` **4** узла `verified_agent` со `strength: strong`.
`grep -n 'Проверено' docs/ELEPHANT-LITERATURE.md` по этим записям:

| запись | что сказано в реестре | что получил граф |
|---|---|---|
| `L-001` | «полный текст **не читал**» | `verified_agent`, `strong` |
| `L-007` | «полный текст» — читал | `verified_agent`, `strong` |
| `L-060` | «полный текст arXiv-версии», файл в `papers/` | `verified_agent`, `strong` |
| `L-066` | «полный текст **не открылся**» | `verified_agent`, `strong` |

То есть **половина** «сильных» свидетельств была ложной по собственному тексту записи: две записи прямо
говорили, что текст не читали.

## Что исправлено

Происхождение теперь зависит от **артефакта**: функция `literature_artifact(body)` ищет в теле записи
arXiv-id или DOI и проверяет, есть ли файл с этим идентификатором в `papers/`. Нет файла — `extracted`,
`strength: weak`. Путь артефакта и исходная формулировка уровня сохраняются в `data.artifact` и
`data.registry_level`.

После пересборки: `verified_agent` — **1** узел (`L-060`, единственный с файлом в `papers/`); три записи
опустились до `extracted`. Это консервативная интерпретация: «полный текст» больше не заявление, а следствие
наличия текста.

**Слону:** напрямую ни одной линии не касается, но касается всех: линия считается поддержанной
литературой только тогда, когда текст источника есть в репозитории. Пока метка заменяла текст, любая
линия могла получить «сильное» свидетельство из одной строки в реестре.

## Что это не доказывает

- Что `L-007` не читали: файла нет, но текст мог быть прочитан в браузере. Мы не утверждаем «не читал», мы
  утверждаем «в репозитории нет свидетельства».
- Что `L-060` прочитан целиком: файл есть, но граф не знает, какие разделы исследованы. Это следующий шаг
  (поле `inspection`), а не следствие правки.
- Что другие уровни (аннотация/фрагмент) проверены: их пока никто не сверяет.

## Команда

    cd kg && python3 migrate.py && python3 kg.py build && python3 kg.py map | grep verified
