# Инструкция внешнему агенту: работа с картой через Windows-обменник

**Кому:** агенту с доступом к Windows и открытому вебу, **без доступа к WSL**.
**Дата:** 26.11.2026. **Версия:** 1.

---

## 1. Что ты делаешь, одним абзацем

Ты пополняешь **литературную карту** проекта: для конкретного источника (DOI) вносишь 3–5 **ячеек** — коротких
утверждений с числами, единицами, **локатором** и **дословной цитатой**. Ячейки проходят машинную проверку и
попадают в карту. Твоя ценность — **не пересказ, а точные числа с местом в тексте**, по которым потом можно
сверить узел графа знаний.

Работа идёт через каталог `C:\111\graph-bridge\`. Доступа к репозиторию у тебя нет и не нужно.

## 3. Формат файлов

Партия — это **один DOI** и три файла с одинаковым именем:

```
outbox\L-041-nemoto.txt.atoms.jsonl       ← новые ячейки, по одной на строку
outbox\L-041-nemoto.txt.edges.jsonl       ← связи этих ячеек с существующими
outbox\L-041-nemoto.txt.questions.jsonl   ← (необязательно) вопросы к числам
```

### 3.1 Ячейка (`.atoms.jsonl`)

```json
{"atom": "WIN-041-01",
 "statement": "У E. coli в ретентостате при снижении μ до <8·10⁻⁴ ч⁻¹ удельное потребление глюкозы сходится к m_S = 0.039 ± 0.003 ммоль/(г·ч).",
 "kind": "measurement",
 "confidence": "medium",
 "domain": "micro.bioenergetics",
 "formula": "m_S = 0.039 ± 0.003 ммоль/(г·ч) при μ < 8·10⁻⁴ ч⁻¹",
 "works": [{"doi": "10.1186/s12934-016-0501-z",
            "locator": "Results, «Retentostat culture», Table 2",
            "quote": "The average specific glucose-consumption rate converged to 0.039 ± 0.003 mmol g X −1 h −1"}],
 "kg_ref": ["L-041"],
 "notes": "Прямое измерение при near-zero росте, а не экстраполяция из хемостата."}
```

| поле | обязательно | что это |
|---|---|---|
| `atom` | **да** | идентификатор, начинается с `WIN-`, уникален: `WIN-<номер узла>-<NN>` |
| `statement` | **да**, ≥40 символов | что измерено/показано, **с числами и единицами** |
| `kind` | **да** | `measurement` / `claim` / `definition` / `gap` |
| `confidence` | **да** | `high` / `medium` / `low` (см. §6) |
| `domain` | **да** | домен карты, например `bio.membrane`, `micro.bioenergetics` |
| `formula` | нет | если в источнике есть формула — записать её и единицы |
| `works[0].doi` | **да** | DOI источника |
| `works[0].locator` | **да** | **где именно**: раздел, таблица, уравнение, страница |
| `works[0].quote` | **да** | **дословная** подстрока текста, без перевода и пересказа |
| `kg_ref` | **да** | на какой узел графа знаний ложится: `L-041` из очереди |
| `notes` | нет | оговорки: метод, условия, где числа не сходятся |

### 3.2 Связь (`.edges.jsonl`) — обязательна

```json
{"from": "WIN-041-01", "to": "FAST-S2M-01", "type": "refines", "note": "тот же штамм, прямое измерение вместо экстраполяции"}
```

**Каждая новая ячейка должна иметь хотя бы одну связь**, иначе партия не примется (правило карты).

| тип | когда ставить |
|---|---|
| `refines` | уточняет существующую ячейку (тот же объект, более точное условие) |
| `supports` | независимо подтверждает то же самое |
| `contradicts` | прямо противоречит **при тех же условиях** |
| `requires` | без этого не работает (механизм или параметр) |
| `analogous` | **перенос из другой области** — только с обоснованием в `note`, не больше одной на партию |

**Перед `contradicts` проверь условия:** другая доза, другой диапазон, другой метод — это НЕ противоречие.

### 3.3 Вопрос к числу (`.questions.jsonl`, необязательно)

Если видишь, что числа в существующей ячейке не сходятся, но не можешь это доказать без полного текста:

```json
{"question": "DIP24-0007: 739·10⁻⁶ см/с × 0,1 / 60 даёт 1,23·10⁻⁹ м/с, а в ячейке 1,23·10⁻⁸ — где потерян порядок?",
 "atoms": ["DIP24-0007"], "kind": "numbers",
 "numbers": ["739e-6", "0.1", "60", "1.23e-8"],
 "recalc": "739e-6 × 0.1 / 60 = 1.23e-6 см/с = 1.23e-8 м/с",
 "verifiable": "пересчётом единиц длины"}
```

Все числа должны **встречаться в тексте ячейки** — иначе вопрос отклоняется машинно.

---

## 4. Что проверяется автоматически (причина отказа)

| проверка | отказ |
|---|---|
| `atom` начинается с `WIN-` и не занят | «должен начинаться с WIN-» / «уже есть в карте» |
| `statement` ≥ 40 символов | «короче 40 символов» |
| `works[0]`: doi + locator + quote | «works[0].locator обязателен» |
| `kg_ref` заполнен | «kg_ref обязателен» |
| `kind` и `confidence` из списков | «confidence должен быть high / medium / low» |
| у ячейки есть связь | «N новых ячеек без единой связи» |

**Отказ не теряет партию:** файл остаётся в `outbox\`, ты исправляешь и кладёшь снова под тем же именем.

## 5. Как выбрать источник

1. Открой `STATE.md`, раздел «Очередь: источники, которых в карте нет» — там узлы `L-*` с DOI.
2. Возьми **один** DOI. Не бери два за раз: партия = один источник.
3. Найди источник в открытом вебе. Нужны **аннотация + числа**; полный текст — если открыт.
4. Если доступа нет — напиши это в `notes` и возьми следующий DOI. **«Нет доступа» — нормальный результат.**
5. Внеси **3–5 ячеек**: разные числа одного источника, а не пересказ одной фразы.

**Не бери** узлы, у которых в `STATE.md` помечено «опровергнут» (`refuted`): там `S`-пара не нужна по устройству.

---

## 6. `confidence` — как ставить

| значение | когда |
|---|---|
| `high` | номер и числа **из таблицы статьи**, локатор точный, цитата дословная |
| `medium` | числа из аннотации/текста, но без таблицы; или единицы приходится пересчитывать |
| `low` | число восстановлено пересчётом из чужих чисел; или источник только вторичный |

**Правило:** `high` без таблицы и точного локатора не ставить. Моё доверие к `high` выше, и ошибка в нём дороже.

## 8. Чего делать нельзя

- править `atoms.jsonl`, `edges.jsonl`, `kg/`, `results/` — только **новые файлы в `outbox\`**;
- пушить в GitHub `master` и переписывать историю;
- ставить `analogous` без обоснования в `note`;
- выдавать пересказ за цитату: `quote` — **дословная подстрока**;
- придумывать числа: `numbers` сверяются с текстом ячейки машинно;
- ставить `contradicts` между работами с разными условиями (доза, диапазон, метод, температура);
- дробить один источник на много партий по одной ячейке — 3–5 за партию.

## 9. Чек-лист перед отправкой

1. `atom` уникален и начинается с `WIN-`?
2. В `statement` есть **число и единица**?
3. `locator` указывает на **место** (раздел/таблица/уравнение), а не на «статью»?
4. `quote` — **дословная** подстрока (без перевода)?
5. `kg_ref` — тот узел, который действительно закрывает источник?
6. У каждой ячейки есть **связь** с существующей картой?
7. `confidence` не завышен?
8. Числа не противоречат друг другу в пределах ячейки? (сложить, поделить, проверить порядок)

## 10. Как измеряется твоя польза

| результат | вес |
|---|---|
| ячейка с табличным числом, точным локатором и связью | **1,0** |
| ячейка из аннотации, числа верны, но без таблицы | 0,5 |
| вопрос, который вскрыл реальное расхождение в существующей ячейке | **1,0** |
| ячейка отклонена (нет локатора/цитаты/связи) | 0 |
| ячейка, где число не сходится с собственным текстом | **−0,5** |

**Лучшее, что можно сделать:** найти в существующей ячейке карты число, которое не сходится с соседними
числами той же ячейки. Такие находки правятся мной и попадают в `MAP-ERRATA.md`.

## 11. Если что-то не так

- `outbox\` пуст, а ответа нет → мост не запущен: сообщи владельцу, **не пересылай** файл.
- непонятно, к какому узлу относится источник → посмотри `STATE.md`, раздел очереди; если сомнение
  остаётся, поставь **самый близкий** узел и напиши сомнение в `notes`.
- партия отклонена дважды по одной причине → пришли владельцу файл целиком, разберём вместе.

## 12. Второй канал: предложения для графа знаний (`kg/`)

Кроме ячеек литературной карты, ты можешь присылать **предложения для графа знаний**. Файл —
`outbox\<имя>.kg.jsonl`, **три типа строк**, ничего больше:

```json
{"kind":"node","tmp":"n1","type":"literature","text":"...","quote":"дословно",
 "source":{"doi":"...","level":"abstract_read"},"lines":["vybor"],"context":{"scope":"..."}}
{"kind":"edge","from":"n1","to":"F-016","type":"extends","note":"почему именно так"}
{"kind":"check","id":"F-006","quote":"дословно","verdict":"supported",
 "source":{"url":"...","level":"fragment_read"}}
```

| поле | допустимые значения |
|---|---|
| `type` узла | `literature` / `claim` / `formula` / `definition` / `gap` / `correspondence` |
| `lines` | `granica, obmen, svoi-usloviya, organizaciya, proshloe, smert, porog, vybor, individualnost, agentnost` |
| `type` ребра | `qualifies, tested_in, stated_in, extends, analogous_to, normalizes_to, refutes, refuted_by, supports, derived_from, bridges, maps_to` |
| `source.level` | `metadata_only` / `abstract_read` / `fragment_read` / `full_text_examined` / `secondary_only` |
| `verdict` | `supported` / `contradicted` / `not_found` |

**Идентификаторы назначаю я.** В строке пиши `tmp` (`n1`, `n2`…), в `edge` ссылайся на `tmp` того же файла
или на существующий id (`F-016`, `C-005`, `L-023`).

**Лимит: 50 строк в файле.**

### С чего начинать — цикл A (самое ценное)

В графе **136 узлов «только извлечено»**: им не хватает **цитаты и вердикта**. Это самый дешёвый вклад:

```
{"kind":"check","id":"F-006",
 "quote":"If Πλ>1/6, the doubling time of a lineage never attains equilibrium",
 "verdict":"supported",
 "source":{"doi":"10.1371/journal.pgen.1001076","level":"abstract_read"},
 "note":"порог подтверждён аннотацией"}
```

Список целей — в `STATE.md`, разделе про `kg`. **Порядок работы: сначала `check`, потом `edge`, потом `node`.**

### Что произойдёт с принятым

- `check` → `docs/KG-CHECKS.jsonl`: я проверяю цитату и двигаю фронтир; `not_found` уходит в `LITERATURE-GAPS`;
- `node`/`edge` → `docs/KG-INBOX.jsonl`: очередь предложений, сливаю я;
- отчёт — `ack\<имя>-kg.json` с причинами отказа по каждой строке.

**`epistemic` ты не ставишь никогда** — это правило графа: `established` получается только через наши
проверки, и агент не может его выставить даже случайно.
