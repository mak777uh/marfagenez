# DECISION-superagent.md — нужен ли нам `dsh-superagent`

**Дата:** 2026-11-20. **Повод:** владелец предложил https://github.com/deepseek-ai/dsh-superagent-prototype
(MIT, «research prototype, not an official DeepSeek product»).

**Короткий ответ:** как **зависимость — нет**. Как **источник правил — да**, и четыре правила забраны.

---

## 1. Что это

Бандл для DeepSeek Harness: проактивный агент **для одного GitHub-репозитория**. Слушает GitHub (и, опционально,
Feishu), по запросу заводит рабочий элемент, работает над ним **в своей сессии и своём каталоге**, отвечает в исходной
беседе — например, пулл-реквестом. Веб-панель показывает, **что ждёт человека**.

Философия (дословно): **«take as little human attention as possible, and give as much value as possible»** — каждый
элемент судится по цене внимания, которое он стоит.

---

## 2. Почему это нам **не** подходит как система

| наше положение | их предположение |
|---|---|
| один автор, работа идёт прямо в `master` под гейтом | команда, issue, PR-процесс, панель |
| арбитр — `run.sh all` и записи `results/` | арбитр — человек, читающий PR |
| бандл ставит и настраивает агент (GitHub App, токены, панель, pnpm-сборка) | у нас нет ни одного из этих слоёв |
| ценность — **научная**: число, вердикт, граница применимости | ценность — **пропускная способность** по задачам репозитория |
| каждый файл проверяется гейтом | панель и сессии гейтом не проверяются |

**Главное:** их цель — **больше сделать без человека**. Наша узкая точка в этой сессии была не пропускная
способность, а **выбор метрики и литература**. Мы дважды теряли циклы на «нулёвых» числах и один раз — на масштабе
`N`; никакая оркестрация этих ошибок не поймала бы.

**Добавочно:** сами авторы пишут «may still contain bugs… review and adapt». Второй источник истины, который гейт не
видит, — прямой риск для репозитория, где весь смысл в проверяемости.

---

## 3. Что забрано (и уже применено)

| правило из `docs/000-philosophy.md` | как применено у нас |
|---|---|
| **«It acts only when asked, or when a written rule allows it»**; проактивная работа начинается в режиме, который **только записывает**, что агент сделал бы | `WORK-LOOPS.md` §10: линия вне плана пишется как «предложение» в `QUESTIONS.md`, а не запускается сразу |
| **«It speaks only when a person must act or can use a result»** | `WORK-LOOPS.md` §10: доклад владельцу — одна страница; длинный разбор — в файл |
| **«It asks one concrete question at a time, in a structured form»** | `WORK-LOOPS.md` §10: спрашивать **одним** вопросом; очередь `Q-` остаётся очередью, но к владельцу идёт первый |
| **«It stops by impact, not by effort»** | совпало с `WORK-LOOPS.md` §5 (четыре класса импакта) — оставлено как есть |
| **«A panel that shows only what needs a person. A healthy state takes no space»** | `AGENT_STATE.md` §2: если ждать нечего — так и писать, а не перечислять сделанное |

**Не забрано:** домен (Source/Item), авторизация по списку людей, пул-реквесты, панель, доставка сообщений —
у нас нет субъектов, которых это защищает.

---

## 4. Когда пересмотреть

1. Если появится **команда из нескольких человек** с issue-потоком — тогда их модель авторизации станет релевантной.
2. Если работа станет **дефицитной по пропускной способности** (много одновременных линий), а не по идеям.
3. Если понадобится **проактивность** (агент сам заводит линии) — тогда взять их правило «сначала только записывать».

**До этого — не подключать.** Решение зафиксировано, чтобы следующий агент не переоткрывал вопрос.

---

## 5. Чему всё-таки стоит поучиться у их документации

1. **Нумерованные документы, читаемые по порядку**: каждый строится только на предыдущих. У нас это частично —
   `INDEX` шаги 1–5, но дальше нумерация не держится.
2. **«Few concepts, few settings»**: у нас много понятий (`q`, `damage`, `stock`, `gate`, `β`, `h`) — стоит один раз
   свести их в таблицу обозначений (в `AGENT_STATE.md` §6 уже есть начало).
3. **Цена внимания как критерий**: сильный фильтр для отчётов. Применён в §10.
