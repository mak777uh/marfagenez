## 2. Что хорошо (и это стоит сохранить)

1. **`AGENTS.md` — 155 строк, шесть правил, у каждого проверка.** Это лучший файл репозитория: короткий, без воды,
   каждое правило машинно проверяемо. Новый агент входит за десять минут.
2. **Гейт как единственный критерий готовности.** «ВСЁ ЗЕЛЁНОЕ» — одна команда, без толкования.
3. **Числа в документах сверяются с деревом** — редкость; именно это поймало несколько моих ошибок.
4. **Обязательное «что это не доказывает»** — снижает соблазн переобещать.
5. **Реестр литературы с ID и полем «Проверено»** — новый агент не спутает «вторые руки» с источником.

## 3. Главная проблема: материалы есть, но их **не находят**

Проверено фактически: `grep -c 'ELEPHANT-LITERATURE|SEARCH-PLAN|BRIEF-for-models'` дал
**0 в `README.md`**, **0 в `AGENTS.md`**, **1 в `WHERE-WE-ARE.md`**. То есть агент, который начинает с README или
AGENTS — а начинает он всегда с них, — о существовании трёх главных справочников **не узнаёт**.

Это тот же класс дефекта, что «гейт, который не может провалиться»: **файл, которого не видно из точки входа, не
существует**. Исправлено: `docs/INDEX.md` + строка навигации в `AGENTS.md` + абзац в `README.md`.

## 4. Структура: что мешает, по убыванию

**4.1 `AGENT_STATE.md` — 3352 строки.** Файл называется «состояние», а содержит историю за все циклы. Новый агент
либо не прочтёт его, либо утонет. **Предложение:** `AGENT_STATE.md` — не больше 200 строк «сейчас»; история — в
`docs/agent/AGENT-HISTORY.md`. Требует аккуратности: файл читают проверки.

**4.2 Имена в `.dsh-switchman/`.** `RESEARCH-BRIEF.md`, `-2-справочник-слона`, `-3-дизайн-экспериментов`,
`-4`, `-4-площадки-и-критерий`, `-5`, `-6`, `-emergence` — по имени нельзя сказать, что актуально. **Предложение:**
`RESEARCH-BRIEF-INDEX.md` с датой и статусом каждого.

**4.3 `docs/` без индекса по линиям.** 300+ файлов; связь «находка → линия» держится только на названии закрытия.
**Предложение:** в `INDEX` таблица «линия → номера находок → файл закрытия» (это можно сгенерировать скриптом).

**4.4 Разделы `POSITIVE.md` 4.1–4.3** без «Команды»: карточка без команды нарушает контракт самого файла.

## 8. Один вывод для следующего агента

Репозиторий силён **контрактом** и **числами**, и слаб **входом**: материалы писались «для себя», и каждый новый
файл требовал знания, что он существует. `docs/INDEX.md` закрывает это, но правило на будущее такое:

> **Новый справочный файл не считается созданным, пока на него нет строки в `docs/INDEX.md` §2.**

Это дешёвое правило, и оно ровно того же типа, что остальные шесть: проверяемое.
