# FINDING: `alternating` — не перемежающееся поле. Оно выравнивается за 6 шагов

Дата: 2026-11-12. Статус: **измерено**, причина найдена в коде.

## Что измерено

`--field alternating --rich 2.0 --poor 0.2 --regrow 0.8`, 10 клеток, 8 организмов,
6 шагов, `--policy stay` (`results/stay/trace-stay-1794496477.json`):

```
step 1: 2.0000 1.6000 2.0000 1.6400 1.6800 1.6000 2.0000 1.6000 1.8400 1.6400
step 2: 2.0000 1.6000 2.0000 1.9280 1.6160 1.7600 2.0000 1.7600 1.8080 1.9280
step 3: 2.0000 1.6000 2.0000 1.9856 1.6032 1.7920 2.0000 1.7920 1.8016 1.9856
step 4: 2.0000 1.6000 2.0000 1.9971 1.6006 1.7984 2.0000 1.7984 1.8003 1.9971
step 5: 2.0000 1.6000 2.0000 1.9994 1.6001 1.7997 2.0000 1.7997 1.8001 1.9994
step 6: 2.0000 1.6000 2.0000 1.9999 1.6000 1.7999 2.0000 1.7999 1.8000 1.9999
```

Клетки 3, 5, 7, 9 стартовали с `poor = 0.2` и ушли в 2.0 / 1.8 / 1.8 / 2.0.
Перемежающегося поля больше нет.

## Причина

`core/src/field.rs`:

```
41:    max_resource: f64,                 // ОДИН предел на всё поле
74:    let mut f = Self::new(cells, rich, regrow)?;   // max_resource = rich
76:    f.cells[i] = if i % 2 == 0 { rich } else { poor };
177:   *c += (self.max_resource - *c) * self.regrow;  // растёт к rich, не к своему
```

У поля нет предела **на клетку**. `regrow_all` тянет каждую клетку к
`max_resource = rich`. Бедная клетка не может удержать свой уровень.

Арифметика: бедная клетка 0.2 при `r = 0.8` тянется к 2.0:
`0.2 → 1.64 → 1.928 → 1.9856 → 1.9971 → 1.9994 → 1.9999` — шесть шагов.

## Что это ломает

Все прогоны с `--field alternating` (а это дефолт `trace.rs:39`) мерили
**однородное** поле, а не перемежающееся. В частности:

- «alternating теряет больше, чем gradient (4 против 2 при n = 80)» —
  сравнивались однородное поле и настоящий градиент;
- «sighted выравнивает поле, разброс 3 → 1» — выравнивание делал `regrow_all`,
  а не организм;
- «при k_max = 1 (M = 1.0) движение бесполезно: alternating и uniform оба 40» —
  оба поля были одним и тем же полем.

`gradient` тоже затронут: он строится через `Self::new(cells, high, regrow)`,
поэтому каждая клетка тянется к `high`, и градиент тоже сползает вверх к
`high`. Он сползает медленнее (низ лежит ниже, путь длиннее), но сползает.

## Установленное заодно (и это подтверждает порядок take→regrow)

Клетка с `k` организмами держится на `M − k·income·(1−r)/r`:

| k | предсказано | измерено на занятых клетках |
|---|---|---|
| 1 | 1.8000 | 1.8000 |
| 2 | 1.6000 | 1.6000 |

Совпадение точное. То есть `cellStep = (c − t) + (M − (c − t))·r` и
`c* = M − k·income·(1−r)/r` — верны, и crowding-«аномалия» была моей
арифметической ошибкой (я забыл, что `regrow_all` идёт внутри шага).

## Что делать

1. Хранить предел на клетку: `ceil: Vec<f64>` рядом с `cells: Vec<f64>`;
   `regrow_all` тянет `cells[i]` к `ceil[i]`.
2. Тест: после 100 шагов `alternating(10, 2.0, 0.2, 0.8)` сохраняет
   соотношение бедных и богатых клеток.
3. Перемерить всё, что опиралось на `alternating`.
