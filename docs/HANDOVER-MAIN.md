## 1. Что вообще происходит

Есть проект **`marfagenez`** — попытка формально описать «жизнь как поддержание целости»: энергия, повреждения,

**Репозиторий:** [https://github.com/mak777uh/marfagenez](https://github.com/mak777uh/marfagenez) — читать можно откуда угодно, **писать и пушить только из WSL**.

## 4. Как запускать каналы (это должно работать всегда)

```bash
cd /root/marfagenez
python3 tools/probe_bridge.py --watch 30     # вопросы агента probe
python3 tools/win_bridge.py   --watch 30     # внешний агент: карта + kg
```

Оба — **циклы с паузой 30 с**: файл, положенный агентом, обрабатывается в течение ~30 секунд.

| команда | что делает |
|---|---|
| `python3 tools/probe_bridge.py --status` | состояние каталогов моста `probe` |

## 5. Как проверять работу агентов (главное)

### 5.1 Партия `fast`

1. DOI существует и совпадает с заявленным;
2. **локатор** указывает на место (раздел, таблица, уравнение), а не «статья»;
3. цитата — дословная подстрока (проверять программно, если есть текст);
4. `kg_ref` — **тот** узел, а не «похожая тема»;
5. `--edges` передан, новых сирот нет;
6. «не нашлось» принимается как результат, «похожее нашлось» — нет.

Приём: `python3 tools/map_ingest.py <atoms> --edges <edges> --report /tmp/ing.md`, затем
`kg/migrate.py` → `kg/kg.py build` → `kg/regress.py` → `tools/build_embeddings.py` → проверки.

### 5.2 Вопросы `probe` — адъюдикация

Формат вердикта: `{"verdicts": [{"id": 1, "atom": "...", "verdict": "...", "score": 1.0, "check": "...", "fix": "..."}],
"score_total": N}` в `C:\111\probe-bridge\ack\roundN-verdict.json`.

Шкала: **1,0** — дефект, меняющий смысл; **0,5** — неполная запись при верном числе или доказанное натяжение;
**0** — тревога снята.

**Правила, выученные на ошибках:**
- проверять `p` по `SE` средних можно **только для независимых** групп; при `ANCOVA`/парном тесте — нельзя;
- перед вопросом агент должен **прочитать `notes`** — половина ответов там;
- если правка одного поля создаёт противоречие с соседним — **перечитать ячейку целиком**;
- «среднее» вне диапазона компонент — почти всегда ошибка формулировки (проверено на `FAST-S2F-01`).

### 5.3 Предложения внешнего агента (`kg`)

`tools/kg_inbox.py --serve <файл>.kg.jsonl` — preflight из пяти проверок: JSON → тип ребра и существование
концов → поля узла и `lines ⊆ 10` → дубли текстов → `verdict` и запрет `supports` для опровергнутого.
Принятое: `docs/KG-INBOX.jsonl`, `docs/KG-CHECKS.jsonl`. **Слияние делает человек-агент (`main`).**

### 5.4 Общее правило

**Проверка, которая не проверена на корректных данных, скорее всего не работает.** У меня было **три** бага в
валидаторе моста, и все три отвергали правильные партии агента.

## 6. Гейт и проверки

```bash
bash run.sh all        # полный гейт, ~15 минут, 12 разделов
bash run.sh exp        # быстрый: проверки + эксперименты
```

Зелёный гейт печатает **«ВСЁ ЗЕЛЁНОЕ»**. Если красный — **не смотреть на последнюю строку**: `run.sh`
накапливает код через `|| rc=$?`. Точка отказа — в `/tmp/marfagenez-run-trace.log`, строка
«последний провалившийся шаг».

Отдельные проверки, которые чаще всего краснеют:

| проверка | о чём |
|---|---|
| `checks/map_contract.py` | состав карты и рёбер |
| `tools/map_orphans.py --strict` | сироты против потолка `docs/MAP-ORPHANS-BASELINE.json` |
| `tools/map_duplicates.py --strict` | дубли (объявлять в `docs/MAP-DUPLICATES.json` с причиной) |
| `tools/units_symbol_audit.py --strict` | символы формул без единиц |

## 8. Правила, которые нельзя нарушать

1. **Историю не переписывать**: правки — датированными дополнениями; старый текст — в `MAP-ERRATA.md`.
2. **Журнал до коммита**, иначе `log_check` краснеет.
3. **Не удалять ячейки карты** и не править `atoms.jsonl`/`edges.jsonl` руками — только через `map_ingest`
   / `map_correct`.
4. **`kg/nodes.jsonl` — генерируемый**: правится корпус (`docs/ELEPHANT-LITERATURE.md`), потом `migrate.py`.
5. **Своё не выдавать за источник**: восстановленное из чисел помечать «наша реконструкция».
6. **Ничего не удалять на `C:`** без разрешения владельца (`C:\111`, `Downloads`, `lean`, `.rustup` — рабочие).
7. **Длинные тексты — только через файл-скрипт**, не через shell-heredoc (три раза терялись слова).
8. **Не запускать второй watcher**, не пушить из агентов, не ставить `epistemic` из инбокса.

## 9. Ресурсы: память и диск (это уже один раз остановило работу)

Симптом: `C:` заполнен до мегабайт → WSL не стартует (`ERROR_SHARING_VIOLATION`, «не удалось расширить vhdx
swap»), гейт падает **не из-за кода**.

**Диагностика и лечение (проверено 26.11.2026):**

```powershell
# 1. остановить WSL
wsl --shutdown
# 2. снять признак разреженности — иначе diskpart откажется
fsutil sparse setflag "C:\Users\Admin\AppData\Local\wsl\{...}\ext4.vhdx" 0
# 3. сжать
diskpart
  select vdisk file="C:\...\ext4.vhdx"
  attach vdisk readonly
  compact vdisk
  detach vdisk
```

Результат того раза: `68,7 ГБ → 42,3 ГБ`, `C:` 1,1 МБ → **27 ГБ**.
`Optimize-VHD` не работает (нет модуля Hyper-V). В `.wslconfig` стоит `swap=0` — swap-файл жил на `C:` и не
мог расшириться.

**Профилактика:** `df -h /mnt/c` раз в ~10 раундов; Temp чистить; **не писать крупное в WSL** (оно на `C:`).
