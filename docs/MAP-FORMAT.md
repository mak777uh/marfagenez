# MAP-FORMAT — атомарные ячейки смысла и связи

Формат карты. Он оптимизирован **под работу агента**, а не под чтение человеком (решение владельца
2026-11-22). Владельцу по запросу делаются объяснения и визуализации, но источник правды — этот формат.

## 1. Зачем атомы, а не конспекты

Одна статья обычно утверждает несколько независимых вещей. Если хранить её конспектом, связи получаются
«работа ↔ работа», и всё, что две работы говорят об одном механизме, слипается в один узел. Поэтому единица
хранения — **одно утверждение**, а работа — это ссылка, а не узел.

## 2. Ячейка (атом)

```json
{
  "atom": "A-0042",
  "statement": "Скорость удаления повреждения падает, когда груз повреждения ингибирует сам аппарат удаления.",
  "domain": "bio.ageing",
  "kind": "mechanism",
  "mechanism": "повреждение снижает каталитическую активность ремонтной системы",
  "formula": "dR/dt = sigma*u_R*M - gamma_R*R - iota*D*R",
  "symbols": {"R": "ремонтоспособность", "D": "груз повреждения", "iota": "константа ингибирования"},
  "conditions": ["in vitro", "постмитотические фибробласты", "липофусцин как груз"],
  "requires": ["A-0007"],
  "contradicts": [],
  "works": [
    {"doi": "10.1096/fj.99-0843com", "locator": "L-106", "quote": "proteasome activity decreased with lipofuscin load", "access": "abstract"}
  ],
  "confidence": "medium",
  "tags": ["repair", "second-order", "lipofuscin"],
  "notes": "Наблюдение in vitro; перенос в клетку не проверен."
}
```

**Обязательные поля:** `atom`, `statement`, `domain`, `kind`, `works` (непустой), `confidence`.
**`kind`:** `mechanism`, `formula`, `condition`, `contradiction`, `gap`, `definition`, `measurement`.
**`confidence`:** `high` — есть формула или измерение и текст-цитата; `medium` — только аннотация или
вторичный источник; `low` — по названию/обзору, требует проверки.

## 3. Правила, без которых формат бесполезен

1. **Одно утверждение на ячейку.** Если в `statement` есть «и» между независимыми механизмами — это две ячейки.
2. **Цитата важнее пересказа.** `quote` — дословный фрагмент; если его нет, `access` не может быть `fragment`.
3. **`access`:** `abstract` (видели аннотацию), `fragment` (видели фрагмент текста), `full` (читали целиком).
4. **Нет локатора — нет ячейки.** Работа без DOI/arXiv/PMID допустима только как `book` с ISBN или URL
   репозитория, и тогда `confidence` максимум `medium`.
5. **`conditions` обязательны**, если утверждение получено в конкретной системе: «in vitro», «дрожжи»,
   «численная модель», «обзор». Иначе карта будет переносить частное на общее.
6. **`contradicts` — только с двумя локаторами.** Противоречие без второй стороны — это `gap`, а не связь.
7. **`gap`-ячейка** описывает отсутствие: «в найденном нет модели, где …», с полями `searched` (каналы,
   запросы, даты) и `scope` (что именно просмотрено). Такая ячейка не может иметь `confidence: high`.

## 4. Рёбра

| ребро | смысл | пример |
|---|---|---|
| `requires` | один механизм невозможен без другого | цена границы требует потока |
| `contradicts` | два утверждения не могут быть верны одновременно в одной области | «ремонт постоянен» против «ремонт деградирует» |
| `generalizes` | частный случай обобщается | численная модель → аналитический предел |
| `measures` | работа измеряет величину из формулы | липофусцин → `iota` |
| `derives` | формула следует из другой | `Π₂·Π₄>1` из τ_R и T_div |
| `analogous` | структурное сходство между областями | автопоэзис ↔ fault-tolerant system |
| `refines` | уточняет, не отменяя | асимметрия уточняет сегрегацию |

`analogous` — самое ценное для владельца и самое опасное: он не делает выводов, только указывает на сходство,
и всегда требует пометки, **чем** сходство ограничено.

## 5. Как проверять карту

Проверки, которые не требуют человека:

- у каждой ячейки есть работа и `access`, согласованный с наличием `quote`;
- доля `high` без формулы или цитаты — ноль;
- `analogous`-рёбра не превышают трети рёбер (иначе карта превращается в метафоры);
- у `gap`-ячеек есть `searched` и `scope`;
- ни одна работа не имеет больше N ячеек без `quote` (иначе «работа-конспект»).

## 6. Расположение

- `literature/map/atoms.jsonl` — ячейки, по одной на строку;
- `literature/map/edges.jsonl` — рёбра `{from, to, type, note}`;
- `literature/map/coverage.json` — сколько ячеек в каждой области и чего не хватает;
- `docs/MAP.md` — генерируемая сводка по областям (для объяснений владельцу).

Формат может меняться, но только датированной записью и с миграцией существующих ячеек.
