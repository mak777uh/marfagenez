# FINDING-321 — экзамен теперь умеет сказать «недействителен»

**Дата:** 2026-11-21. **Основание:** внешний разбор (§5 «Сам экзамен может выдавать ложноположительный результат») и
правка `kg/eval/score.py`.

## Что было

`score.py` печатал отчёт по тем прогонам, которые узнал, и возвращал `0`. Если агент ответил на 4 вопроса из 28 — отчёт
всё равно формировался. Цели из `questions.json` (`recall ≥ 0.8`, `precision ≥ 0.8`, три сида, отрицательные вопросы)
печатались, но не проверялись. `rubric_pending` (assert-пункты, которые может оценить только судья) в отчёт не попадал.
`expected_absent` входил в `allow`, поэтому ссылка на несуществующий объект не стоила ничего.

## Что стало

Три исхода, и код возврата следует вердикту:

| вердикт | когда | код |
|---|---|---|
| **INVALID** | покрытие неполное, дубли, неизвестные id; либо всё измеримое в порядке, но assert-пункты не оценены (нет судьи) | 1 |
| **FAIL** | покрытие полное, но цель не достигнута: recall, precision, бюджет токенов, открытые файлы, reject-пункт, незаземлённое число, цитирование отсутствующего | 1 |
| **PASS** | полное покрытие, все цели, судья оценил assert-пункты | 0 |

Дополнительно: `expected_absent` больше **не** входит в `allow`; цитирование отсутствующего считается в
`absent_cited_total` и попадает в причины. `rubric_pending` теперь в отчёте.

## Числа

`checks/eval_verdict.py` — три подложенных случая:

| случай | ожидалось | получено |
|---|---|---|
| демо-прогоны (4 ответа из 84) | INVALID | INVALID |
| полный набор (84) без ссылок | FAIL | FAIL |
| полный набор + один дубль | INVALID | INVALID |

Демонстрационный набор `kg/eval/demo-runs.json` теперь даёт **INVALID**: он содержит 4 ответа из 84 и три намеренные
ошибки. Раньше он «проходил».

**Слону:** экзамен перестаёт быть ритуалом: неполный ответ больше не «проходит». Это не про слона напрямую, но без этого любое утверждение о слоне опиралось бы на экзамен, который умеет только соглашаться.

## Что это значит

- **Зелёный отчёт больше ничего не обещает.** Обещает только `PASS` и код 0.
- **Пропуск вопросов не сходит с рук:** частичный экзамен — не меньший экзамен, а недействительный.
- **Без судьи экзамен не может быть сдан:** assert-пункты — половина рубрики, и их отсутствие теперь видно.

## Чего это не доказывает

- Что **gold** правильный: экзамен проверяет полноту и метрики, а не истинность эталонов.
- Что `questions.json` скрыт от агента: файл лежит в том же репозитории; изоляция — задача holdout, не скорера.
- Что частичные прогоны не нужны: для отладки есть `--report-only`, который печатает отчёт и не притворяется вердиктом.

## Команда

```bash
python3 kg/eval/score.py kg/eval/demo-runs.json && echo PASS || echo "не сдан"
python3 checks/eval_verdict.py
```
