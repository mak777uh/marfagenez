## 3. Пять проверок по приоритету

### 3.1 `units` — единицы не переводятся (самое дорогое)

**Как искать:**
```bash
python3 tools/units_symbol_audit.py                    # символы без единиц
python3 tools/map.py zoom --atom <ID>                  # смотреть поле formula и текст
```

**Что искать:** две ячейки об одном, но одна в `см/с`, другая в `мкм/с`; одна в `Дж/м²`, другая в
`пДж/мкм²`.

**Реальный пример из наших данных:**
> `DIP24-0005`: «гидравлическая проницаемость 1,0·10⁻³ см/(с·осмоль)»
> `DIP24-0011`: «осмотическая проницаемость 71,9»
>
> Вопрос: 71,9 — это в тех же единицах или в мкм/с? Если в мкм/с, после пересчёта величины сопоставимы.

**Почему это важно:** мы уже поставили ребро `refines` между ценами, различающимися в 10⁶ раз. Разные
единицы — первый шаг к такому.

### 3.2 `order` — порядки врозь

**Как искать:**
```bash
python3 tools/edge_order_audit.py     # шумный: читать глазами, а не верить списку
```

**Что искать:** величины «одной природы», различающиеся в 10²–10⁶ раз.

**Реальный пример:**
> кутикула: 2,95–27,4 г/м² × 1,58–2,67 г глюкозы/г × 15,56 кДж/г = **72 519–1 138 246 Дж/м²**
> мембрана: 0,12 пДж/мкм² = **0,12 Дж/м²**
>
> Отношение 6·10⁵–9,5·10⁶. Это разные величины, а не разные единицы.

**Правило:** пересчитай обе в одну единицу и **покажи пересчёт** в вопросе. Без пересчёта вопрос не годится.

### 3.3 `numbers` — одно и то же с разными числами

**Как искать:**
```bash
python3 tools/map_duplicates.py        # пары с общим DOI
python3 tools/map.py zoom --atom <ID>
```

**Что искать:** две ячейки про одну величину, значения расходятся; или в ячейке число, противоречащее
соседней.

**Реальный пример:**
> `L-012` (узел): «κ идёт на поддержание, остальное — на рост и размножение»
> `DIP28-0001` (источник): «κ — на поддержание **и рост**, (1−κ) — на зрелость, созревание, размножение»

**Почему это дефект:** рост переставлен из одной ветви в другую — это меняет смысл правила DEB.

### 3.4 `gap-as-support` — пробел выдан за опору

**Что искать:** ячейка утверждает «не найдено / не измерено», а на неё ссылаются как на подтверждение.

**Как проверить:** найди в `docs/STITCH-OVERRIDES.json` пары, где у узла вердикт `S`, а ячейка — `kind: gap`.
Если такая пара есть — это ошибка: пробел не может быть опорой.

**Реальный пример:** `B26-01-0009` — «существование скачков двойственной переменной остаётся открытым», а
на него ссылался узел, **утверждающий**, что цена ломается.

**Класс встречался 13 раз** — это самый частый дефект в наших данных.

### 3.5 `no-locator` — число без источника

**Что искать:** в `statement` есть число, а в `works` нет `locator` (раздела/таблицы/уравнения).

**Как искать:**
```bash
python3 tools/locator_audit.py          # список для чтения
```

## 4. Формат вопроса (обязательный)

```json
{"question": "DIP24-0005 и DIP24-0011: 1,0·10⁻³ см/(с·осмоль) против 71,9 — разные единицы длины или разные величины?",
 "atoms": ["DIP24-0005", "DIP24-0011"],
 "kind": "units",
 "numbers": ["1.0e-3", "71.9"],
 "recalc": "1,0·10⁻³ см/(с·осмоль) = 1,0·10⁻⁵ м/(с·осмоль); 71,9 мкм/с = 7,19·10⁻⁵ м/с — порядок сходится",
 "verifiable": "да, разные единицы | нет, одна величина после пересчёта"}
```

Обязательные поля: `question`, `atoms` (≥1), `kind`, `numbers` (≥2 значения или одно значение + единица),
`verifiable`.

`recalc` — если вопрос про единицы или порядки, **покажи пересчёт**.

`kind` строго из списка: `units`, `numbers`, `order`, `gap-as-support`, `no-locator`.

**Плохой вопрос:**
```json
{"question": "DIP24-0005 и DIP24-0011 выглядят подозрительно", "atoms": ["DIP24-0005"], "kind": "units"}
```
Не годится: нет второго числа, нет проверяемого ответа, непонятно, что именно проверять.

## 5. Как измеряется твоя польза

| исход | балл |
|---|---|
| нашли и **исправили** дефект записи | **1** |
| доказали, что данных нет и нужен новый замер | **0,5** |
| проверили — расхождения нет (сняли ложную тревогу) | **0** |

`main` ведёт счёт в журнале после каждой партии.

**Ориентир:** 1 полезное попадание из 14 (мой опыт с шумным `edge_order_audit`) — это плохо. Лучше
**3 точных вопроса**, чем 6 «на всякий случай».

## 6. Как `main` проверяет раунд (чтобы ты понимал критерий)

1. Открывает `probe-<дата>.jsonl` и по каждому вопросу делает **одно** из:
   - подтверждает и исправляет данные (`kg/migrate.py`, текст узла, единицу);
   - подтверждает, что данных нет — пишет в `docs/STITCH-S-READ.md` как пробел;
   - закрывает как «расхождения нет» с причиной.
2. Считает баллы по §5, пишет в журнал циклов.
3. Отвечает тебе письмом: что взято, что отклонено и почему.

**Отклоняется сразу:** вопрос без чисел; без проверяемого ответа; про «похожесть» без пересчёта;
предложение поставить связь.

## 9. Чего делать нельзя

| запрет | почему |
|---|---|
| `git add/commit/push` | публикует только `main` |
| править `literature/map/atoms.jsonl`, `edges.jsonl`, `kg/nodes.jsonl` | приём и граф — только через `main` |
| править `checks/`, `run.sh`, `AGENTS.md` | защищённые зоны |
| запускать `bash run.sh all` | `results/` — общий ресурс |
| `pip install`, `apt`, менять окружение | воспроизводимость |
| создавать `docs/FINDING-*.md` | номера выдаёт `tools/new_finding.py` |
| писать в `inbox/fast-*.jsonl`, `inbox/lit-*.jsonl`, `inbox/ver-*.jsonl` | чужие области |
| ставить связи и вердикты | это не твоя работа |

## 10. Если что-то не работает

| симптом | что делать |
|---|---|
| `coord take` говорит «задача уже взята» | это ты в прошлом раунде: `python3 tools/coord.py finish <каталог> --agent probe` |
| инструмент печатает много и непонятно | это список для чтения, а не приговор: проверяй глазами |
| не можешь писать в репозиторий | пришли в чат содержимое `probe-<дата>.jsonl` и `RESULT.md` — `main` положит файл |
| не понял, как читать ячейку | `python3 tools/map.py zoom --atom <ID>` — там всё: statement, формула, DOI, локатор, цитата |
| сомневаешься, дефект это или нет | пиши вопрос: «проверить, дефект ли». Ноль баллов за снятие — нормально |
