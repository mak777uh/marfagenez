# Несогласованные числа: где они и какая версия верна

Файл существует, чтобы через месяц никто не выяснял заново, почему в
репозитории два разных ответа на один вопрос. Каждая запись: где, в чём
расхождение, какая версия верна, чем проверено.

Проверки — скрипты в `checks/`, они же в `run.sh all`. Запись без скрипта
здесь не живёт: если расхождение нельзя проверить машиной, оно не
несогласованность, а мнение.

---

## 1. Ёмкость клетки: `LAW-capacity.md` против `capacity_law.py`

| где | формула |
|---|---|
| `docs/LAW-capacity.md:92` | `k_max(t) = max(⌊M·r/t⌋, ⌊(M·r − m − bill)/t⌋ + 1)` |
| `checks/capacity_law.py:15` | `jmax = ⌊(M·r − m)/t⌋ + 1` |

**В чём расхождение.** `capacity_law.py` молча выбрасывает `bill` —
энергию починки повреждений (`damage_rate · repair_cost`). Второй файл
его выводит и включает.

**Какая версия верна.** Обе, но про разные вопросы:

- `LAW-capacity.md` — **жёсткая граница**: все организмы на клетке живы,
  включая последнего, которому достаётся остаток. Это условие
  «популяция не теряет никого».
- `capacity_law.py` — **среднее по ансамблю**: `capacity()` ищет
  наибольшее `n`, при котором `E[min(K, j)] ≥ n`, `K ~ Binomial(n, 1/cells)`.
  Часть организмов гибнет, и это усредняется.

Среднее по ансамблю не может быть **ниже** жёсткой границы. Поэтому
`capacity_law.py` обязан быть `≥` `LAW-capacity.md` — и он `≥` на всех
12 точках прогона.

**Что показал прогон.** `checks/capacity_two_answers.py`:

```
  fires    3/12  точек, где ответы различаются
  silent  12/12  точек, где capacity_law.py ≥ LAW-capacity.md
  specific 121  точка, где bill меняет пол
```

Различие не косметическое: при `M=2.0, r=0.8, t=1.0` `capacity_law.py`
даёт `2`, `LAW-capacity.md` — `1`. Файл, который «проверяет закон»,
проверяет формулу без члена, ради которого закон выводился.

**Что делать.** Не «исправлять» один файл под другой: это два разных
вопроса, и оба нужны. Нужно:

1. переименовать `jmax` → `jmax_mean_field` и `capacity()` →
   `capacity_mean_field`, чтобы имя говорило, какое из двух это;
2. в `LAW-capacity.md` назвать свою формулу `k_max_all_survive`;
3. в `capacity_law.py` вывести рядом обе и печатать обе в свипе.

Пункт 3 — единственное, что мешает ошибке вернуться: пока свип печатает
одно число, никто не заметит, что рядом живёт другое.

**Статус:** открыто. Скрипт зелёный, потому что порядок верный; красным он
станет, если `capacity_law.py` когда-нибудь окажется ниже.

## 2. Числа теорем: закрыто

`docs/PLAN-NEXT.md` §2 A3: три документа называли три разных числа
(317, 290, 281) и ни один не говорил, какое дерево он считает.

**Закрыто** в `checks/log_check.py` (коммит `8185849`): считает теоремы и
файлы одной функцией для обеих библиотек и сравнивает с каждым живым
упоминанием. Встроено в `run.sh all`, так что устаревшее число теперь
валит прогон, а не лежит в документе.

Заморожено 149 документов (датированные записи). Живые числа совпадают с
деревом: 317 теорем в 63 файлах (290 в 56 + 27 в 7), 127 тестов Rust,
0 живых `sorry`.

## 3. Порядок клампа в `DeathLaw.lean`: открыто

`laws/Legacy/DeathLaw.lean` описывает порядок операций до §19.3: кламп
энергии до проверки смерти. Живой код (`core/src/organism.rs`) делает
наоборот — сначала проверка смерти, потом кламп.

**Почему не закрыто:** это не число, а утверждение о коде, и проверять его
надо не сравнением строк, а доказательством о живом коде. Пока `Legacy`
не подключён к `core/`, расхождение остаётся описанием, а не дефектом
сборки.

## 4. `Budget.lean`: заголовок против собственной теоремы

Заголовок утверждает, что `Σ B² ≤ T²/d` максимизируется равным делением.
Это ложно: при `T=12, d=4` равное деление даёт `36` — **минимум**,
концентрация в одну клетку даёт `144` — максимум.

**Статус:** открыто. Теорема в файле верна; неверен заголовок над ней.
Правится одной строкой, но требует, чтобы кто-то прочитал файл целиком —
именно этого не случилось в прошлый раз.

## Как добавить запись

1. Найти расхождение, которое видно скриптом.
2. Написать скрипт в `checks/`, который его печатает и падает, если
   порядок нарушится.
3. Вписать сюда: где, в чём, какая версия верна, чем проверено.
4. Встроить скрипт в `run.sh all`.

Запись без шага 2 не добавляется.
