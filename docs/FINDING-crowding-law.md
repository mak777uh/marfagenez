# FINDING: сколько организмов кормит одна клетка

**Дата:** 2026-11-13
**Эксперимент:** `checks/exp25_crowding_law.py` → `results/crowding-law-law3/run-exp25.json`
**Вердикт:** `passed` — 10/10 предсказаний, все три контроля прошли

## Закон

```
k_max = 1 + floor( (M·r − maintenance − damage_rate) / income )
```

Скачок с k на k+1 происходит при

```
r = (income + maintenance + damage_rate) / M
```

Для базовых параметров (M = 2.0, income = 0.8, maintenance = 0.6, damage = 0.02):
`r* = (0.8 + 0.6 + 0.02)/2 = 0.71`. Измерено: при r = 0.70 ещё 1 организм на клетку,
при r = 0.75 уже 2.

## Откуда закон берётся (вывод, а не подгонка)

**Порядок в `Life::advance`** (`core/src/life.rs:429-441`):

```
for каждый организм:  взять (take) → жить (step)
затем  regrow_all()  ОДИН раз
```

Значит на одной клетке с k организмами изъятия идут **последовательно, без
восстановления между ними**. Клетка вычерпывается до нуля и восстанавливается
из нуля в `M·r`, поэтому шаг начинается с `c = M·r`. Измерено: r = 0.80 даёт
`field = 1.600 = 2·0.8` на каждой клетке.

k-й организм получает `min(income, M·r − (k−1)·income)`.

**Учёт организма** (`core/src/organism.rs:148-182`):

```
energy += min(resource, income)      затем зажим до world.capacity
energy -= maintenance_cost
damage += damage_rate
ремонт: energy / repair_cost  идёт на damage, то есть стоит ровно damage_rate
смерть если energy <= 0 или structure <= 0
```

Итог за шаг: `net = taken − maintenance_cost − damage_rate`. Значит выживает тот,
у кого `taken ≥ maintenance_cost + damage_rate`. **Maintenance — это фиксированная
плата за шаг, которую каждый организм платит независимо, а не минимальная доля
клетки.**

## Первая версия закона была неверной — и это урок

Первая версия: `k_max = 1 + floor((M·r − maintenance)/income)`.

Две ошибки:

1. **Пропущен `damage_rate`.** Он не мал: при income = 0.8 это 2.5% бюджета.
2. **Maintenance считался минимальной долей, а не платой за шаг.** Из-за этого
   казалось, что maintenance можно менять свободно. Нельзя: при income = 0.8 и
   damage = 0.02 любой `maintenance ≥ 0.78` убивает всех, сколько бы еды ни было —
   потому что `taken` упирается в `income`. Измерено: mnt = 0.8 → `alive = 0`.

Первая версия провалила все три контроля (`verdict: void`). Это правильное
поведение контракта: провал контроля означает, что неверна постановка, а не
природа.

## Почему прежний кандидат `floor(M·r/income)` был неверен

Он игнорирует и maintenance, и damage, поэтому ставит скачок 1→2 при
`r = income/M = 0.80`, тогда как измерение ставит его между 0.65 и 0.70.
Новый закон ставит его при 0.71. На шести новых плечах старый закон даёт 5/6,
новый — 6/6.

## Контроли

- **fires** — плечи вывода дают `[(1,1), (1,1), (2,2), (2,2)]`, то есть метрика
  действительно меняется, и в предсказанном месте.
- **silent** — `n = cells` с `--layout even` (по одному организму на клетку) даёт
  `max_per_cell = 1` при r = 0.80 и r = 0.95. Закона нет там, где нет давления.
  *Первая версия этого контроля использовала `n = cells` без `--layout even` и
  получила 2 — потому что случайный спавн с возвращением ставит двух в одну клетку,
  а `stay` их не разделяет. Контроль измерял спавн, а не закон.*
- **specific** — на 6 новых плечах новый закон 6/6, старый `floor(M·r/income)` 5/6.

## Что это не доказывает

- Не доказывает, что Lean-модель совпадает с Rust-моделью.
- Ничего не говорит о неоднородном поле.
- Не доказывает, что `k_max` — единственное, что важно для ёмкости: `alive`
  колеблется от seed к seed, тогда как `max_per_cell` стоит на месте.
- Закон предполагает, что клетка вычерпывается до нуля, а для этого нужно
  `k·income ≥ M·r`. О разреженной популяции, которая не держит клетку пустой,
  закон молчит.
- Закон предполагает, что ремонт всегда оплачиваем, то есть `energy > 0`.
- Не предсказывает, **как долго** длится квазистационарное состояние: при r = 0.70
  энергия дрейфует вниз (1.399 → 0.200 за 1200 шагов). `max_per_cell = 2` — это
  квазистационарное состояние, а не вечное.

## Связь с Lean

`laws/Medium/Capacity.lean` пока содержит старую форму ёмкости
(`capacity M r t₀ = M·r/t₀`, условие `0 ≤ c* ↔ t ≤ M·r`). Она описывает **запас**
клетки, а не **число** прокормленных организмов. Закон выше — про число. Формальную
теорему под него ещё предстоит написать; до тех пор закон подтверждён только
измерением.
