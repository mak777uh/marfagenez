# Отброшенное

Здесь записано то, что не сработало. Не свалка — **запись отрицательного результата**.

Правило проекта: **отрицательный результат остаётся**.

## 1. Тест «скорость реакции сужает на 10%» — неверен

**Что утверждал:** ребёнок, который замечает свою скорость и тормозит, сужается на 10% от закона.

**Что вышло:** при демпфировании 0.5 разброс 1.66 против закона 1.73 — **3.5%**, не 10%.

**Почему:** демпфирование убирает часть каждого шага, но **шум продолжает приходить**. Ребёнок всё равно ходит.

**Что заменило:** `core/tests/damping_threshold.rs` — измерение с порогом.

---

## 2. Тест «скорость сужает сильнее позиции» — неверен

**Что утверждал:** демпфирование сужает сильнее, чем тяга к точке, потому что это снижение шума в маске.

**Что вышло:** сравнение некорректно. Тяга к точке с `gain = 0.1` и демпфирование `0.5` — **разные величины**, их нельзя сравнивать напрямую.

**Что заменило:** ничего. Сравнение было неверно поставлено.

---

## 3. Тест «демпфирование не схлопывает даже при 1.0» — неверен

**Что утверждал:** даже при полном демпфировании ребёнок остаётся широким.

**Что вышло:** при 0.99 разброс падает до **0.349** от закона. Ребёнок **схлопывается**.

**Почему:** при `d → 1` чистый шаг `(1-d) → 0`. Ребёнок не может двигаться, шум гасится быстрее, чем приходит.

**Что заменило:** `core/tests/damping_threshold.rs`, тест `the_cliff_is_between_damping_09_and_099`.

---

## 4. «Монотонное сужение при демпфировании» — верно только до порога

**Что утверждал:** чем сильнее демпфирование, тем уже ребёнок — монотонно.

**Что вышло:** монотонно до 0.9, потом **обрыв**. Не постепенное сужение, а **порог**.

| damping | разброс / закон |
|---|---|
| 0.90 | 0.873 |
| 0.95 | 0.791 |
| 0.99 | **0.349** |

**Что заменило:** `damping_threshold.rs`.

---

## 5. `audit.js` давал 6/7 при `k = 2` — не ошибка теоремы

**Что казалось:** закон `Var(exp(k·x)) = 1` неверен при больших `k`.

**Что было:** эффективный размер выборки падает до **5%** при `k=2` и **0.1%** при `k=3`. Симуляция мерила не закон, а шум выборки.

**Исправлено:** проверка ограничена `k ≤ 1.5`, `N_eff` печатается с результатом.

## 7. `Medium::new` каждый шаг сбрасывал `Rng`

**Что было:** в тестах с меняющейся комнатой `Medium` пересоздавался каждый шаг, генератор начинался заново, дети не успевали заполнить комнату.

**Исправлено:** `Medium::set_room` — один `Medium` на весь прогон.

## 8. Тест «без шума популяция схлопывается» — неверен

**Что утверждал:** без шума все дети сходятся в точку.

**Что вышло:** дети, начавшие **врозь**, остаются врозь. Отражение — изометрия, оно не сближает.

**Исправлено:** тест теперь проверяет **оба** случая: начали врозь — разница сохраняется; начали вместе — остаются вместе.

## 9. «Оптимум заполнения 90%» — артефакт малой выборки

**Что было:** в проекте `medium` объявлен оптимум при заполнении 90%.

**Что вышло:** прогон с двумя сидами показал **монотонное улучшение** с ростом заполнения. Разброс по сидам больше, чем разница между точками.

**Исправлено:** в `FINDING-dimension.md` записано опровержение.

## 10. Три неверные теоремы в проекте `medium`

| теорема | ошибка |
|---|---|
| `negative_feedback_collapses` | неверна без `0 ≤ k` |
| `equal_division_maximises` | неверное направление |
| `double_room_sqrt_two_spread` | разброс растёт линейно, не `√2` |

Все три прошли бы, если бы не удалили `module`. Записан урок: **теорема, которая компилируется, не обязательно верна**.
