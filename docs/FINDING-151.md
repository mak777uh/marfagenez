## Вопрос

`FINDING-149` и `FINDING-150` закрыли арифметику **одного** организма на
однородном поле. Во всей цепочке 143 → 150 `taken = income`, потому что делить
клетку было некому. Вопрос этой находки: **переживает ли граница столкновение с
конкуренцией — или она была про одиночество?**

Модель для этого уже была: `core/src/life.rs`, `World::share`
(`Sequential`/`Proportional`), `Field::regrow`. Конкуренция входит в модель
**только через `taken`**: `Life::advance` выдаёт организму его долю клетки, а
`Organism::step` обрезает её по `income`. Поэтому предсказание брифа — «формула
149 не меняется, меняется её вход» — проверяемо буквально.

## Арифметика (предсказание, записанное до прогона)

`m = maintenance_cost`, `t = income`, `S = M·regrow` — сколько клетка отдаёт за
шаг в установившемся режиме (`c_next = M·r + (1−r)(c − съедено)`).

**Что делает код** (прочитано из `Life::advance_with`, не предположено):

* `Sequential` идёт в порядке слотов, каждый берёт `min(t, что осталось)`. При
  `S ≥ n·t` все получают полный `t`; при `S < n·t` доли — **лестница**

    ```
    t_i = clamp( S − (i−1)·t , 0, t )
    ```

* `Proportional` делит **один** `income` на клетку между ещё не евшими, поэтому
  каждый просит `t/n`. При `S ≥ t` все получают `t/n`; при `S < t` первые
  `floor(S/(t/n))` получают `t/n`, остальные — ноль.

**P_mean (предсказание брифа).** Один вход на всех:
`taken_n = min(t, S/n)`, `s_n = taken_n − m`, `edge_n = max(s_n/dr,
min(K·s_n, capacity + s_n))`. Следствие, которое видно глазом: при одном входе
все организмы строки обязаны умереть на одном и том же `rc`, то есть **доля
выживших — ступенька 1 → 0 на `edge_n`**.

**P_rank (предсказание из кода).** Вход у каждого свой:
`edge_i = max(s_i/dr, min(K·s_i, capacity + s_i))`, `s_i = t_i − m`, `t_i` — из
лестницы протокола. Следствие: доля выживших — **лестница по `rc`**, а не
ступенька.

**Средняя доля — не доля никакого организма.** `S/n` есть среднее вектора
`t_i`, а не его элемент: у `Sequential` при `S = 0.8n` это `0.8`, а реальные
доли — `1.0` и `0.0` (при `n = 2`); у `Proportional` это `0.8`, а реальная доля
каждого — `t/n = 0.5`. Значит P_mean — это P_rank с **неверным вектором**, а не
с неверной формулой; различать их надо не краем «в среднем», а тем, кто именно
выжил.

**Где конкуренция перестаёт быть бесплатной.**

* `Sequential` — ровно при `S = n·t`: начиная с него каждый ест `t`, `s` равен
  запасу одиночки и край **не двигается**.
* `Proportional` — **никогда**: протокол делит `income`, а не запас, поэтому
  первый едок начинает терять уже при `S < t`, а толпа на клетке ограничена не
  полем, а организмом: `n ≤ t/m = 5` (EXP-99). Богатое по брифу поле
  (`S ≥ n·t`) тут **не** освобождает от конкуренции: при `n = 4` каждый всё
  равно получает `t/4 = 0.25`, то есть `s = 0.05`.

**Горизонт.** «Жив» — жив на `T`. Выше пошагового края резерв
`R = min(energy0, capacity)` платит дефицит, поэтому измеренный край смещён на
`~R/(T·dr)`; край снимается по двум горизонтам.

**Ожидаемые края при `dr = 0.03`, `K = 34`:** `s = 0.8 → 26.6667`,
`s = 0.4 → 13.3333`, `s = 0.3 → 10.2`, `s = 0.2 → 6.8`, `s = 0.05 → 1.7`,
`s = 0 → 0` (при `s = 0` бесплатна только починка при `rc = 0`). При
`dr = 0.1`, `K = 11`: те же `s` дают `8.8, 4.4, 3.3, 2.2, 0.55, 0`. Ветку
выбирает формула, а не `dr`: при `dr = 0.03` потолок подрезает часы при
`s > 10/33`, и пошаговая цена выигрывает выше `s ≈ 0.324`; при `dr = 0.1` часы
выигрывают у обеих при любом `s < 1`.

**Сетка и число бисекций.** 32 строки населения × 2 горизонта, 120 краёв по
рангам (по одному на каждый различный `taken`), 4641 прогон зонда,
3 мин 55 с. В `run.sh` не вписано (дольше минуты) — команда в поле `command`
записи.

### O2. Кто умирает первым и от чего

* **`Sequential`, бедное поле.** Первым умирает **хвост** лестницы, и умирает
  от голода, а не от урона: при `n = 8` ранг 7 (`taken = 0`) — на 9-м шаге,
  причина `energy`. Ранг 6 (`taken = 0.4`, `s = 0.2`) умирает не от
  голода, а от урона: его доля положительна, но края `6.8` ему не хватает. При `n = 4` ранг 3
  (`taken = 0.2`, `s = 0`) умирает от урона на 43-м шаге. Головные ранги при
  этом не двигаются: их доля — `min(t, остаток)`, а остаток определяется
  только теми, кто ест **раньше**. Поэтому выбывание хвоста не меняет доли
  выживших — лестница устойчива к собственной смерти, и это причина, по
  которой у `Sequential` доля выживших равна `k/n`, а не «все или никто».
* **`Proportional`.** Все организмы клетки симметричны (одинаковая доля
  `t/n`, одинаковая энергия, одинаковый урон), поэтому они умирают **вместе**:
  при `n = 2` — на 50-м шаге оба, при `n = 4` — на 43-м все четыре, при
  `n = 8` (`s = −0.075`) — на 11-м все восемь, причина `energy`. Доля выживших
  тут — ступенька 1 → 0, но **не на средней границе**, а на `edge(t/n)`.
  Это тот же «утёс», что записан в EXP-99 для ёмкости клетки.
* **Смерть от голода — не край по `rc`.** У ранга с `s < 0` края по `rc` нет
  вообще: он умирает на любом `rc`, включая ноль (за `E0/|s|` шагов). В
  записи это отдельное значение `measured_edge = null`, и оно совпало с
  предсказанием на всех таких рангах.

### O3. Протокол дележа — это число, а не слово

Установившиеся доли из записи (`taken_last`), `dr = 0.03`:

| `n` | `Sequential`, бедное | `Proportional`, бедное | `Sequential`, богатое | `Proportional`, богатое |
|---|---|---|---|---|
| 1 | 0.8 | 0.8 | 1.0 | 1.0 |
| 2 | 1.0, 0.6 | 0.5, 0.5 | 1.0, 1.0 | 0.5, 0.5 |
| 4 | 1.0, 1.0, 1.0, 0.2 | 0.25 ×4 | 1.0 ×4 | 0.25 ×4 |
| 8 | 1.0 ×6, 0.4, 0.0 | 0.125 ×8 | 1.0 ×8 | 0.125 ×8 |

Отсюда край в богатом поле (по брифу — «доля не связывает»): у `Sequential`
`26.6666` при **любом** `n` (не сдвинулся ни на бит), у `Proportional`
`26.6666 → 10.2 → 1.7 → нет` при `n = 1, 2, 4, 8`. То есть при `n = 4` и
`M·regrow = 8 ≥ 4·income` протокол меняет границу в **15.7 раза** (26.6666 →
1.7), не меняя ни поля, ни организма, ни `income`. Это и есть ответ «что
делает протокол»: он делит **`income`** (proportional) или **запас клетки**
(sequential), и от этого зависит, чей `taken` попадёт в формулу 149.

### O4. Где конкуренция перестаёт быть бесплатной

* `Sequential`: ровно при `M·regrow = n·income`. На четырёх богатых строках
  (`S = 2n`) край равен одиночному `26.6666` при `n = 1, 2, 4, 8` — порог
  брифа подтверждён как **порог sequential**.
* `Proportional`: **не при `n·income`**. Первый едок теряет уже при
  `S < income`, а вся клетка держит не больше `t/m = 5` организмов (EXP-99);
  поле тут ни при чём: при `S = 2n` и `n = 8` доля каждого `0.125`, `s < 0`,
  края нет. Поэтому фраза «конкуренция бесплатна, пока `M·regrow ≥ n·income`»
  верна только для `Sequential`; для `Proportional` бесплатной конкуренции нет
  ни при каком поле, кроме `n = 1`.

### O5. Контроль `specific`: сдвиг от `taken`, а не от числа организмов

1. **Мир средней доли измерен.** Одиночка с `income' = min(income, S/n)` (поле
   для него богатое) даёт ровно `edge_n`: `20.0000` в бедном режиме
   (`n = 2, 4, 8`) и `26.6666` в богатом. Значит средняя граница — настоящий
   край, просто **другого организма**: формула та же, и `taken` — её вход.
2. **Ни один ранг населения в этом мире не живёт.** На 32 строках населения
   `0` краёв рангов совпали со средней границей там, где средняя доля не
   является входом какого-либо ранга. Средняя доля — среднее вектора, а не его
   элемент.
3. **Внутри одной строки разные доли дают разные края.** На 6 строках с двумя
   и более различными предсказанными краями измерено столько же различных
   краёв (6 из 6), и в предсказанном порядке: при `n = 2` бедного `Sequential`
   — `26.6666` и `13.3333`, ровно `s = 0.8` и `s = 0.4`.
4. **Конкуренция — это толпа на клетке, а не размер популяции.** 3 клетки по
   2 организма дают те же края, что 1 клетка с 2 (`26.6666, 13.3333` для
   `Sequential`; `10.2` для `Proportional`), **отличаются** от краёв одной
   клетки с 8 (там `26.6666 ×6, 6.8, нет` / нет), а по одному организму на
   клетку край возвращается к одиночному `26.6666`.

## Вердикт

**`passed`.** Три контроля:

* `fires` — средний вход ошибается там, где он вообще отличается от
  порангового: 84 края из 120, и доля выживших под средней границей не 1 на 18
  строках (0.50, 0.75, 0.00 вместо 1.00); при этом P_rank совпадает на 120 из
  120. Примеры промаха: бедное `seq`, `n = 2`, `edge_n = 20.0000` против
  измеренных `26.6666` и `13.3333`; богатое `prop`, `n = 4`, `edge_n = 26.6667`
  против `1.7000`.
* `silent` — 14 строк из 32, где оба предсказания совпадают (8 богатых
  `Sequential`, где `S = 2n ≥ n·income` платит всем полный `income`, и строки с
  одним организмом): измерение не расходится ни с одним из них (0 из 14), и
  край на них не двигается с `n`.
* `specific` — сдвиг идёт от `taken` конкретного организма: одиночка с
  урезанным до средней доли `income` воспроизводит среднюю границу (6 из 6),
  разные доли внутри строки дают разные края (6 из 6), локальность выполняется
  (2 из 2), и среднюю границу не имеет ни один ранг.

Тезис в четырёх строках:

1. **Граница 149 переживает конкуренцию — как формула и как закон одного
   организма.** `edge_i = max(s_i/dr, min(K·s_i, capacity + s_i))`,
   `s_i = taken_i − maintenance`, на 120 краях из 120. Формулу не пришлось
   менять: изменился вход.
2. **Вход — вектор, а не число.** `taken_n = min(income, M·regrow/n)` из брифа
   есть среднее этого вектора, и оно не является входом ни одного организма:
   84 края из 120 мимо, 0 совпадений со средней границей там, где средняя доля
   не вход ранга. Наблюдаемая величина, которая это разделяет, — **доля
   выживших**: ступенька у среднего входа, лестница у порангового.
3. **Протокол дележа задаёт вектор, и это число.** `Sequential` — лестница
   `clamp(S − (i−1)·income, 0, income)`: головные ранги сохраняют одиночный
   край, хвост голодает. `Proportional` — `income/n` каждому: край падает с
   ростом `n` даже в богатом поле (`26.6666 → 10.2 → 1.7 → нет`), потому что
   протокол делит `income`, а не запас.
4. **Порог бесплатной конкуренции protocol-dependent.** Для `Sequential` это
   ровно `M·regrow = n·income` (подтверждено: 4 богатые строки, край не
   сдвинулся). Для `Proportional` такого порога нет: предел толпы —
   `income/maintenance`, а не поле.

## Что это не доказывает

* **Горизонт конечен.** «Жив» — жив на `T = 10000` (и на `2T` для края). Край
  восстановлен экстраполяцией по двум горизонтам, которая предполагает
  смещение `c/T`; остаток и есть допуск (`3.2e−5`), а не доказательство
  точного края. Ранг с `|s| < energy0/T` пережил бы горизонт, не будучи
  способным жить вечно; таких рангов на этой сетке нет, но сетка узкая.
* **`K` измерен, а не выведен.** Оба `dr` взяты из модели (`K = 34` и `11`), и
  `FINDING-150` показала, что `ceil(1/dr)` верна не всюду; здесь это не
  переоткрывалось.
* **Толпа навязана, а не установилась.** Размножения нет, поэтому `n` — это
  то, что мы попросили. Измерено, какие ранги заданной толпы выживают, а не
  где толпа установится. Обратной связи «умер один — доля выживших выросла»
  в модели нет; была бы — лестница могла бы сама себя вытягивать.
* **Установившиеся доли — установившиеся.** Поле стартует полным, поэтому
  первые 2–3 шага платят больше установившейся доли. Экстраполяция по
  горизонтам снимает эффект этого разового бонуса на край, но `taken_mean` в
  записи — среднее по жизни организма, а не установившаяся доля.
* **Одно поле, один порядок обхода.** `stay`, однородное поле, порядок слотов
  фиксирован. `Sequential` платит по порядку, и вопрос «что если порядок
  другой» (или если организм может уйти с переполненной клетки) здесь не
  измерялся; политика `sighted` + движение — другой мир.
* **Две ветки формулы, не три.** Потолок `capacity` на этой сетке ни разу не
  был связывающим краем (`10.8` против `26.6666`), так что третья половина
  формулы 149 тут не проверялась — только пошаговая и часы.
* **Одна пара (`income`, `maintenance`).** Форма лестницы — свойство
  протокола, но то, какие ранги попадают в живые, зависит от `t/m`; другие
  отношения не свиповались.
* **`Proportional` симметричен по построению.** «Все умирают вместе» — это
  свойство равных долей, а не общий закон конкуренции.
* **Lean этого не покроет.** Числа — свойство даблов и порядка шага; в
  рациональной арифметике равенства сдвинутся, как и в 148/149.

## Что делать дальше

1. **Назвать вектор в коде.** `World::share` есть, а функции «сколько достанется
   рангу» нет — лестница живёт в Python-скрипте. Кандидат —
   `Life::settled_shares(crowd, supply)` рядом с `World::sustains()`, чтобы
   `ShareProtocol` перестал быть параметром без закона.
2. **Протокол, который делит запас.** Бриф прав для мира, где каждому дают
   `S/n`; такого протокола в `core` нет. Третий вариант `ShareProtocol`
   (`Supply`) сделал бы среднюю долю настоящим входом и отделил бы «дележ
   дохода» от «дележа запаса» одним плечом.
3. **Движение как выход.** `Policy::Sighted` на переполненной клетке — это
   вопрос, схлопывается ли лестница к одиночному краю, когда организм может
   уйти. Модель для этого есть, измерено не было.
4. **Потолок ёмкости под толпой.** Третья ветка `min(K·s, capacity+s)` при
   `capacity+s ≈ K·s` (окно 149) не измерялась с `n > 1`; там `s_i` уже не
   `income − maintenance`, и окно должно сдвинуться.
5. **Ёмкость клетки и край — одна величина?** EXP-99 даёт число организмов,
   которое клетка держит; здесь у каждого из них свой край. Совместить два
   ответа — значит сказать, какой край у установившейся толпы, а не у
   навязанной.
