## Что на самом деле было не так

Я потратил много времени на диагностику `fatal runtime error: failed to initiate panic` и решил, что это проблема инициализации Lean.

**Это была ошибка в моём тесте.**

Тест `time_law_is_exported` содержал неверное утверждение:

```rust
// неверно
assert!(!lean_sooner_than_naive(100, 100, 1));
```

Я думал: при `spread = b` расстояние до стены ноль, значит время до сужения равно наивному.

**Но это не так.** Расстояние ноль → время до сужения ноль. А наивное `B/μ = 100`. Значит `0 < 100` — **истина**.

Утверждение было ложным, `assert!` падал, и падение выглядело как сбой Lean-рантайма.

## Урок

> **`fatal runtime error: failed to initiate panic` — это сообщение Rust, не Lean.**

Оно означает, что **Rust-паника не смогла запуститься** — но не говорит, почему. В моём случае паника была **законной** (неверный assert), а сообщение сбило с толку.

Проверить это было просто: запустить `cargo test --lib` без фильтров. 65 тестов прошли. Значит рантайм в порядке.

## Что реально нужно для FFI

| шаг | зачем |
|---|---|
| `UInt64`, не `Nat` | `Nat` — указатель, `UInt64` — `uint64_t` |
| `lean_initialize()` | поднять рантайм |
| `initialize_Std(1)` | инициализировать глобалы модуля |
| `lean_io_mark_end_initialization()` | завершить инициализацию |
| **конструктор C** | выполниться до `main`, в главном потоке |
| **линковать объект, не архив** | `ar` теряет `.init_array` |

## Что НЕ нужно

**`lean_initialize_thread()`** — в Lean 4.36 её нет в заголовках, и она не нужна: `cargo test` создаёт потоки, но Lean 4.36 ещё не требует per-thread регистрации.

**`lean_init_task_manager()`** — не нужен для чистых функций.

## Формула

```
laws/FFI.lean  --[lean -c]-->  FFI.c  --[gcc + конструктор]-->  FFI.o  -->  Rust
```

Конструктор:
```c
__attribute__((constructor))
static void marfa_lean_boot(void) {
    lean_initialize();
    lean_io_mark_end_initialization();
    lean_init_task_manager();
    lean_object* res = initialize_Std(1);
    if (!lean_io_result_is_ok(res)) lean_io_result_show_error(res);
    lean_dec_ref(res);
}
```

## Чего это не доказывает

**Не доказывает, что Rust-код верен.** Доказывает, что формулы совпадают на проверенных входах.

**Не доказывает, что закон полон.** Пять законов доступны, но не все возможные.

## Честная оговорка

Диагностика заняла больше времени, чем сама реализация, и **по ложной причине**. Если бы я сразу проверил `cargo test --lib` без фильтров, увидел бы 65 проходящих тестов и понял, что рантайм в порядке.

> **Первый шаг диагностики — проверить, что проблема вообще в том, о чём говорит сообщение.**
