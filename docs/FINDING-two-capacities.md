# FINDING — две ёмкости, и почему их нельзя путать

Дата: 2026-11-12.

## Что произошло

Два документа говорили «ёмкость 80» и оба были правы, но про **разные
величины**. Я почти записал третий закон, который противоречил первому.

| | `FINDING-capacity-exact.md` | `FINDING-capacity-law.md` (эта серия) |
|---|---|---|
| политика | `sighted` | `stay` |
| `income` | 0.8 | 1.0 |
| `damage_rate` | 0.02 | 0.01 |
| шагов | 3000 | 300 |
| поле | `alternating(2.0, 0.2, 0.8)` | `new(cells, 2.0, 0.8)` |
| `n` | 100 | 40 |
| **выжило** | **80** | **37** |

Воспроизведено точно: `n=100 → 80`, давка 2.00, все 80 на потолке 9.37.
И `n=200 → 80` тоже — то есть 80 это **насыщение**, а не «выжило сколько
поместилось».

## Две величины

**1. Ёмкость полного кормления** `C_full` — сколько организмов получают
полный `income` каждый. Это `cells · j`, где

```
j = floor((r·M − maint) / income) + 1
```

При `cells=40, M=2, r=0.8, income=1, maint=0.6`: `y = 1.6`,
`j = floor(1.0/1.0)+1 = 2`, `C_full = 80`.

**2. Выживаемость** `alive(n)` — сколько из `n` остаётся живо после 300 шагов:

```
alive(n) = cells · E[min(K, j)],  K ~ Binomial(n, 1/cells)
```

При `n = cells` это `cells · E[min(K,2)] = 36.0` для `cells=40`.
Измерено 37 (один seed), среднее по 10 seed'ам 35.4.

## Где я ошибся

Я взял `C_full = 80` из первого документа, `alive(40) = 36` из своего замера
и решил, что они противоречат. Они не противоречат: 80 это **сколько влезает
на насыщенном поле**, 36 это **сколько из 40 посаженных выжило на пустом**.

Разница: при `n = 40` и `cells = 40` средняя давка 1, и примерно четверть
клеток пустует, а на других сидит по 2–3. Третий жилец получает 0 и умирает.
При `n = 80` давка 2, и почти все клетки заняты двумя — потерь почти нет.

## Проверка `C_full = 80` как насыщения

`FINDING-capacity-exact.md`: `n=100 → 80`, `n=200 → 80`. Оба раза ровно 80.
Это и есть `cells · j`. Подтверждено.

## Проверка `alive(n)` как закона

30 комбинаций `cells × (M,r)`, по 10 seed'ов, `n = cells`:

```
within 2: 30/30  worst |err| = 0.8
```

И на диапазоне `n` при `cells=40, M=2, r=0.8`:

| `n` | измерено | `alive(n)` |
|---|---|---|
| 10 | 10 | 9.9 |
| 20 | 20 | 19.4 |
| 30 | 30 | 28.2 |
| 40 | 37 | 36.0 |
| 50 | 42 | 43.0 |
| 60 | 51 | 49.0 |
| 80 | 59 | 58.6 |
| 120 | 72 | 70.3 |
| 160 | 76 | 75.8 |

Работает на всём диапазоне, не только в одной точке.

## Что это НЕ доказывает

- `alive(n)` выведена для `Policy::Stay` и равномерного независимого
  размещения. При движении размещение перестаёт быть биномиальным, и формула
  не обязана работать. При `sighted` на `alternating` она заведомо другая:
  там 80 = `cells·j`, а не `alive(n)`.
- `j` считается из установившегося `y = r·M`. На первых шагах поле полное
  (`M`), и третий жилец ещё жив; он умирает к шагу 9. Окно 300 шагов это
  скрывает.
- Обе формулы — измеренные закономерности, не теоремы. В Lean не перенесены.

## Урок

**Одно слово — одна величина.** «Ёмкость» означала и «сколько влезает», и
«сколько выживает из посаженных». Пока это одно слово, любой замер можно
объявить противоречием, а любой закон — опровергнутым.

Правило: в каждом замере указывать `policy`, `income`, `damage_rate`,
`steps`, и что именно считается — насыщение или выживаемость.
