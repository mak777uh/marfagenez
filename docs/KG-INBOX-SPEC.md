# Инбокс предложений для `kg/`: совместимость со спекой внешнего агента

**Дата:** 26.11.2026. **Источник спеки:** `C:\111\research\marfagenez-otvet-2026-11-26.md`, Часть VII.
**Реализация:** `tools/kg_inbox.py`, приём через мост `tools/win_bridge.py` (файлы `*.kg.jsonl`).

## Вердикт: совместимо, и почти без изменений

Спека предлагает **инбокс предложений, а не правку графа** — это ровно та дисциплина, которая у нас уже
действует для литературной карты. Поэтому она принята целиком: три типа строк, аппенд-онли, идентификаторы
назначает коллектор, `established` агент не ставит никогда.

**Что проверено на реальных данных (26.11.2026):**

| инвариант спеки | как у нас на самом деле |
|---|---|
| 10 линий слона | `kg/lines.json`: `granica, obmen, svoi-usloviya, organizaciya, proshloe, smert, porog, vybor, individualnost, agentnost` ✓ |
| 12 типов рёбер | в источниках встречаются 7 (`qualifies, analogous_to, extends, normalizes_to, refutes, refuted_by, supports`); полный список из 12 принимается ✓ |
| фронтир «только извлечено» | **136** узлов (claim 109, formula 27) ✓ |
| «без свидетельств» | **38** (в спеке 27 — цифра изменилась с момента её написания) |
| `established ⇒ evidence`, `refuted ≠ цель supports` | оба инварианта у нас есть, второй проверяется в preflight ✓ |

## Грамматика (как реализовано)

```json
{"kind":"node","tmp":"n1","type":"literature","text":"...","quote":"дословно",
 "source":{"doi":"...","level":"abstract_read"},"lines":["vybor"],"context":{"scope":"..."}}
{"kind":"edge","from":"n1","to":"F-016","type":"extends","note":"почему именно так"}
{"kind":"check","id":"F-006","quote":"дословно","verdict":"supported",
 "source":{"url":"...","level":"fragment_read"}}
```

`tmp` — имя строки внутри файла; **идентификатор назначаю я** при слиянии.

## Preflight — пять проверок спеки, все машинные

| # | проверка | отказ |
|---|---|---|
| 1 | строка — валидный JSON, одна сущность на строку | «не JSON» |
| 2 | `edge`: тип из 12, `from`/`to` существуют в `kg` **или** объявлены `tmp` в том же файле | «type не из 12» / «нет такого узла» |
| 3 | `node`: `text` + `quote` + `source.level` + `lines` непустые, `lines ⊆ 10` | «lines вне набора» |
| 4 | текст не дублирует существующие узлы (нормализация пробелов и регистра) | «такой текст уже есть в kg» |
| 5 | `verdict` из трёх; опровергнутый узел не может быть целью `supports` | «нельзя поддерживать опровергнутый узел» |

Плюс наш кап: **≤ 50 строк в файле**, чтобы preflight читался глазами.

**Проверено:** партия `node + edge + check` принята (3 из 3), строка с коротким текстом и без источника
отклонена с тремя причинами одновременно.

## Решение по четырём развилкам спеки

| # | развилка | решение |
|---|---|---|
| 1 | приоритет цикла | **A → C → B.** Сначала цитаты к 136 извлечённым (самое дешёвое и сразу двигает фронтир), потом рёбра между уже существующими, потом новые узлы. Новые узлы без свидетельств лишь увеличивают тот же долг. |
| 2 | кто назначает ID | **коллектор (я).** Подтверждаю выбор спеки: у агента нет реестра занятости, а коллизия `L-107` стоит дороже скорости. |
| 3 | транспорт | **Windows-обменник** `C:\111\graph-bridge\outbox\`. Класть `kg/inbox/` в репозиторий нельзя: агент не имеет доступа к WSL, а пушить в GitHub ему запрещено. |
| 4 | лимит пачки | **50 строк** на файл. |

## Куда попадает принятое

| тип строки | файл | что делает коллектор |
|---|---|---|
| `node`, `edge` | `docs/KG-INBOX.jsonl` | разбираю, назначаю id, вношу в источник и пересобираю `kg/` |
| `check` | `docs/KG-CHECKS.jsonl` | проверяю цитату, двигаю фронтир или завожу `LITERATURE-GAPS` при `not_found` |

**В `kg/` инбокс не пишет ничего** — граф по-прежнему генерируется `kg.py`, и обойти проверки нельзя.

## Что осталось за кадром (честно)

- **Автоматического слияния нет.** `docs/KG-INBOX.jsonl` — очередь, а не применённые изменения. Слияние
  делаю я, потому что оно требует правки источников (`claims.jsonl`, `definitions.jsonl`, `bridges.jsonl`)
  и пересборки.
- **`check` не повышает `epistemic`.** Он даёт цитату и вердикт; повышение до `established` — отдельный шаг,
  который делает только человек/сильный агент по нашим правилам.
- **Спека считает рёбер 101, у нас в источниках 12.** Это разные числа одного и того же: `graph.json`
  разворачивает обратные рёбра и наследует связи от литературных узлов. При слиянии считать по источникам.
