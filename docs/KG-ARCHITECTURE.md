## 1. Принцип, из которого всё выводится

**Статья не является узлом истины. Она источник конкретных утверждений.**

Отсюда центральное различение, которого у нас **не было**:

```
Assertion  — что именно заявил конкретный автор в конкретном месте (цитата, локатор, качество извлечения)
Proposition — нормализованное научное положение, к которому assertions относятся
```

Три статьи о «пороге» могут утверждать **разное**; склеивать их через `same_as` нельзя. Связь
`assertion → normalizes_to → proposition` сохраняет и оригинал, и обобщение.

## 2. Шесть слоёв (смысловые проекции одного пространства)

| слой | что | обязательные связи |
|---|---|---|
| **0. Источники** | статьи, версии, фрагменты, датасеты, коммиты, трассы | `contains`, `hasLocator`, `versionOf` |
| **1. Утверждения** | `Assertion` (автор/агент) и `Proposition` (положение) | `asserts`, `normalizes_to`, `supports`, `refutes`, `qualifies`, `extends`, `supersedes` |
| **2. Математика** | величины, символы, формулы, системы, модели, теоремы | `measuredBy`, `hasUnit`, `depends_on`, `equivalent_under` |
| **3. Lean** | объявления, типы, аксиомы, сборки | `formalizes`, `dependsOn`, `assumes`, `provesInModel` |
| **4. Эксперименты** | прогоны, наблюдения, контрпримеры, воспроизведения | `used`, `generated`, `replicates`, `counterexampleTo` |
| **5. Происхождение** | Activity / Agent / время / версия модели | `wasDerivedFrom`, `wasGeneratedBy`, `wasAssociatedWith` |

**Не шесть баз** — шесть **проекций**, связанных общими ID.

---

## 3. Пять независимых осей статуса (не смешивать)

| ось | значения |
|---|---|
| **знание** | `hypothesis` · `supported` · `contested` · `refuted` · `bounded` · `superseded` |
| **запись** | `extracted` · `normalized` · `reviewed` · `independently_checked` |
| **доступ к источнику** | `full_text` · `abstract` · `figure` · `snippet` · `secondary` |
| **тип свидетельства** | `formal` · `empirical` · `simulation` · `analytical` · `observational` |
| **воспроизводимость** | `not_attempted` · `reproduced` · `failed_to_reproduce` · `inconclusive` |

**Правило, которое нельзя нарушать:** `provenance = extracted` никогда не повышает первую ось. LLM не повышает
статус; повышает **проверка**.

Плюс отдельно от всего — **исход проверки**: `passed / failed / void / insensitive_by_construction / not_applicable`.
Провал процедуры **не** равен опровержению гипотезы (это уже в `PROTOCOL.md`, граф это наследует).

## 4. Математический слой: типы, а не строки

| тип | что хранит |
|---|---|
| `Quantity` | величину: значение, единица (UCUM), размерностный вектор |
| `Symbol` | символ, смысл, тип, единицу |
| `Definition` | определение объекта |
| `Formula` | **AST/структуру**, не только LaTeX |
| `EquationSystem` | систему уравнений |
| `Model` | уравнения + допущения + область определения |
| `Theorem` | математическое утверждение |
| `Proof` | основание вывода |
| `LeanDeclaration` | реальное объявление из кода |

**Формула в статье и её формализация в Lean — не один объект.** Связь `formalizes` / `implements`, но не `same_as`.
У каждой формулы обязательны: дерево выражения, определения символов, единицы, диапазоны параметров, предпосылки,
источник (статья или `FINDING`), связанные формулы, Lean-имя (если есть).

Эталон проверки размерности: **QUDT** (коды и векторы размерностей; версия словаря фиксируется).

---

## 5. Lean как подграф, а не поле

Для каждого объявления хранить: полное имя; тип и нормализованное представление; файл и позицию; commit; версию Lean и
Mathlib; зависимости; используемые **аксиомы**; статус сборки; хэш утверждения.

Связи: `formalizes`, `dependsOn`, `usesAssumption`, `provesInModel`, `empiricallySupportedBy`.

**Граница, которую нельзя размывать:** Lean доказывает утверждение **внутри формальной модели** при её предпосылках; он
не подтверждает, что модель описывает мир. Наш собственный документ уже это фиксирует: Lean о `ℝ` ≠ `f64` в Rust;
Verus доказывает **копии**.

Отсюда тип связи между формулой и тезисом обязан быть квалифицирован: `formalizes_idealized_model`,
`proves_under_assumptions`, `implements`, `validated_by_experiment` — **разные** отношения.

Инструменты для извлечения зависимостей (когда понадобится): **LeanDojo v2** (программный доступ, premise retrieval,
бенчмарк порядка ста тысяч формальных утверждений), **LeanAtlas** (граф объявлений; счётчики — сотни
объявлений и миллионы зависимостей).
**OMDoc/MMT** — ориентир для связи математических теорий, не замена Lean.

## 6. Компилятор знания: ничего не становится `established` само

```
Agent proposes → candidate record → schema validation → provenance validation
   → semantic checks (дубль? противоречие при совпадающих условиях? формулы связаны с определениями?)
   → dimensional check → Lean check (если применимо) → numerical/empirical check
   → review gate → accepted node
```

**Проверки разные для разных типов:** теорема, эксперимент и обзор проходят **разные** ворота. Это ключ: единый
«confidence score» запрещён.

## 7. Два новых объекта, которых у нас нет

### 7.1. `Gap` — недостающая связь как объект

```
gap_id, source_cluster, target_cluster, missing_relation,
supporting_context, search_coverage, existing_evidence, required_test, status
```

Примеры, уже видимые у нас: `A×B` (повреждение под бюджетом), `B×C` (цена как механизм устойчивости). Система должна
уметь **порождать** кандидатов: две теории описывают связанное, но переходной модели нет; формула есть, эксперимента
нет; Lean-теорема есть, эмпирического положения нет.

### 7.2. `Correspondence` — карта переносимости между дисциплинами

Для каждой аналогии три обязательных элемента: **(1)** какие математические структуры совпадают; **(2)** какие
предпосылки сохраняются при переносе; **(3)** что **перестаёт** быть верным в новой области. Отношение называется
`analogous_to` / `mapped_to`, **не** `same_as`.

Пример: теневая цена в LP и цена удержания мембраны могут быть связаны математически — и это **не** значит, что у них
одинаковая физическая интерпретация.

---

## 8. Карта «слона»: не одна иерархия, а оси

Вопросы к одному объекту: **явление · механизм · математическая структура · условия · измерение · доказательство ·
область · нерешённая связь**.

Два уровня доступа:

```
Global Atlas  — компактная карта: сообщества, центральные структуры, счётчики, противоречия, незакрытые мосты
Subgraph      — подграф по вопросу: k шагов, уровни связей, детали по запросу
```

Весь граф в контекст **не** загружается. Критерий пустой области — «покрытие неизвестно», **не** «наука не знает».

## 9. Что берём сейчас, что позже

| сейчас (этот цикл) | позже |
|---|---|
| различение `Assertion` / `Proposition` в схеме | массовое извлечение assertions из литературы |
| типы `Gap` и `Correspondence` как узлы | автоматическое порождение gaps |
| пять осей статуса | компилятор знания с воротами по типам |
| математический слой: `math.structure` + UCUM-единицы | QUDT-коды с версией словаря |
| Lean-подграф: имя, файл, commit, аксиомы | LeanDojo-извлечение зависимостей |
| `atlas` (переименование `meta.json`) | иерархические сообщества алгоритмом |

**Порядок внедрения (совпадает с обзором):** 1) контракт типов; 2) починить `kg`; 3) импорт накопленного
(`L-`, `F-`, `P-`, `EXP-`, `FINDING-`, Lean, `ELIMINATED`, `NOT-CLAIMED`); 4) математический граф; 5) внешние графы
(OpenAlex/OpenAIR/ORKG) как справочные; 6) агентские глаголы; 7) планирование по `Gap` + ожидаемая информативность.

**Чего не делать:** ещё одну широкую кампанию поиска. У нас уже есть `A×B`, `B×C` и 16 предсказаний; следующий шаг —
соединить знание с измерениями и формальными результатами.

## 10. Что это меняет в текущем `kg/`

1. `claims.jsonl` → `nodes.jsonl` с `kind` ∈ {assertion, proposition, formula, lean, experiment, evidence, question,
   gap, correspondence, dataset} — **менять схему надо один раз, пока узлов шестьсот**.
2. Ввести `evidence` как **отдельный узел** (сейчас это поле), чтобы у свидетельства были свой ID и происхождение.
3. `check` дополнить: существование целей `evidence` (не только отношений).
4. `meta.json` → `atlas.json`; добавить в него `gaps` и `correspondences`.
5. Оставить JSONL каноном; `graph.json`/`atlas.json`/индекс — производные.

**Дисциплина остаётся:** уровень доказательности и «что это не доказывает» — в каждой записи, независимо от того,
человек её прочтёт или нет.
