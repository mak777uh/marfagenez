# FINDING: транзиент — один шаг, а не десять

Дата: 2026-11-12. Статус: подтверждено на 4 значениях `M` и на `k = 1, 2`.

## Что было записано раньше и было неверно

В `docs/FINDING-capacity-law.md` и в отчётах о ёмкости говорилось: «поле
выходит на равновесие за ~10 шагов», и «транзиент `step < 10` формулой не
описывается». Оба утверждения неверны. Десять шагов — это **гранулярность
кадра** (`--every 10`), а не физика.

## Арифметика (написана до прогона)

Порядок операций в `Life::advance` (`core/src/life.rs:193-315`):

1. `feed = true`: регенерация **до** всех действий;
2. для каждого организма: восприятие → память → движение → `take`;
3. `feed = false`: регенерация **один раз в конце** шага.

По умолчанию `feed = false`, то есть **взять, потом отрастить**.

Клетка с `k` организмами, каждый берёт `t = income`, регенерация `r` к `M`:

    c₁ = c − min(c, k·t)                 (взятие, последовательное)
    c₂ = c₁ + (M − c₁)·r                 (регенерация)

При `c = M` (полное поле) и `k·t ≥ M`:

    c₁ = 0,  c₂ = M·r

При `c = M·r` и `k·t ≥ M·r`:

    c₁ = 0,  c₂ = M·r

**Неподвижная точка `M·r` достигается за один шаг.** При `k·t < M·r`
регенерация не успевает вернуть взятое, и клетка оседает ниже.

## Измерение

`n = 1`, `cells = 40`, `r = 0.8`, `income = 1.0`, `feed = false`,
поле однородное (`--rich M --poor M`):

| M | поле после шага 1 | предсказано `(M−t)+(M−(M−t))·r` | `taken` |
|---|---|---|---|
| 1.0 | 0.8000 | 0.8000 | 1.000 |
| 1.5 | 1.3000 | 1.3000 | 1.000 |
| 2.0 | 1.8000 | 1.8000 | 1.000 |
| 4.0 | 3.8000 | 3.8000 | 1.000 |

`n = 2`, `cells = 1` (двое на одной клетке):

| M | поле после шага 1 | предсказано для `k = 2` |
|---|---|---|
| 1.0 | 0.8000 | 0.8000 |
| 2.0 | 1.6000 | 1.6000 |

Устойчивость: `M = 2`, `k = 2`, шаги 1…6 — поле **1.6000 на каждом шаге**,
оба организма живы. Это и есть равновесие `c* = M + t − t/r` из
`laws/Medium/Field.lean`, посчитанное для `k = 2` (`t` на клетку `= 2`).

## Ловушка, которая это скрывала (моя ошибка)

Я передавал `--capacity M`, считая, что это ресурс клетки. Это **энергоёмкость
организма**. Ресурс клетки задаётся `--rich` и `--poor`, а `--field uniform`
строит поле как `(rich + poor) / 2` (`core/src/bin/trace.rs:165`).

Мои прогоны при `--capacity 2.0` на самом деле шли на поле
`(2.0 + 0.2)/2 = 1.1`, и я полдня объяснял «аномалию» 0.88/0.9/1.1, которой
не было: это ровно `1.1 − взятое` и `1.1` после регенерации.

Правильный вызов однородного поля с ресурсом `M`:

    --field uniform --rich M --poor M

## Что это меняет

* Транзиент не нужен как отдельный закон: он **один шаг** и уже покрыт
  `cellStep` из `laws/Medium/Field.lean`.
* Все прошлые измерения, где я задавал ресурс через `--capacity`, относятся
  к полю `(rich + poor)/2`, а не к `M`. Их надо перепроверить отдельно.
* «Все лишние умирают на шаге 10» — это кадр, а не смерть на шаге 10.

## Чего это не доказывает

* Только `Policy::Stay`, однородное поле, `feed = false`.
* Не проверено `feed = true` (регенерация до взятия) — там `c₂` на шаге 1
  будет `M − k·t`, а не `M·r`.
* Не проверено, как транзиент выглядит при движении: там `k` на клетке
  меняется каждый шаг.
