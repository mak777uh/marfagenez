## 0. Три аудита, которые приняты как ошибки

| # | ошибка | исправление |
|---|---|---|
| 1 | в потоке приёмки `epistemic` ограничивался значением **provenance** (`extracted`) — смешение осей | исполняемый потолок: `epistemic ≤ cap(provenance)`, `extracted → hypothesis`, `verified_agent → established`; `replicated` требует **триангуляции**, а не provenance |
| 2 | лестница смешивала обоснованность, спор и границы | `hypothesis → supported → established → replicated` + `refuted`; **`contested` и `at_risk` — вычисляемые флаги**, не хранимые; `bounded` уходит в `context` |
| 3 | LaTeX как источник diff | истина — **структурная запись**; LaTeX **рендерится** из неё; diff по struct |

Плюс: `A1` («прогон — свидетельство») и §6 (прогон — узел) не противоречат, если объявить **двухслойность**:
**слой знания** (`claim`, `formula`) и **слой свидетельств** (`experiment`, `dataset`), плюс язык (`definition`) и
повестка (`question`). Лестница epistemic живёт только на слое знания; у прогона — `validity: valid | buggy | superseded`,
у датасета — целостность. Инварианты **скоупятся по `kind`**.

## 1. Четыре сквозных паттерна

**P1. Мост — это узел, а не ребро.** «Наш параметр `h` соответствует `h_c` из DOI:X при отображении M» — отдельное
утверждение с флагом `bridge: true`, свидетельством с **двух** сторон и статусом `contested` по умолчанию. Мостов
десятки, они несут всю связность корпусов и теряются первыми, поэтому выписываются **до** массового импорта.
Это ответ на §1 постановки («порог складки = полюс параметра нигде не записано»).

**P2. Сила свидетельства — отношение, не свойство.** Прогон силён для `model`-утверждения и слаб для `world`;
статья сильна для «авторы утверждают X» и условна для «X истинно». Значит `strength` живёт **на ребре**
(свидетельство × утверждение × условия) с обязательным `rationale`. Двух ступеней (`strong | weak`) достаточно.

**P3. Граф — это система поддержания истины (JTMS/ATMS).** Всё выводимое вычисляется: `contested`, `at_risk`,
валидность цепочек, frontier. Авто-понижение — безопасно и обязательно; авто-повышение — запрещено. Устаревание
запускается **зависимостями** (изменился код прогона, опровергнут upstream), а не только календарём.

**P4. Вместо новых `kind` — два ортогональных поля.** `domain: model | world` и `basis: empirical | analytic |
stipulative`. Правила приёмки — функция `(kind, basis, domain)`. Аналитическое может быть `established`, но **не
считается находкой**; стипулятивное (определения, допущения, нормативные позиции) вне лестницы: `active | deprecated`.

## 2. Решения Q1–Q23 (кратко)

| Q | решение | цена |
|---|---|---|
| Q1 | граница утверждения = граница **независимой опровержимости**; `same_as` только для нотационных вариантов с совместимым `context` | больше узлов; держится дедупом |
| Q2 | `domain`, не `kind`; прогон устанавливает только `model`; `world` требует полного текста или моста (`P1`); это verification ≠ validation | мировые утверждения дорожают |
| Q3 | число — значение внутри прогона/утверждения/контекста; узлом становится только константа с собственной жизнью | — |
| Q4 | определение — узел, версии через `supersedes`; утверждения ссылаются на **версию** термина полем `terms` | определения не истинны, а приняты/устарели |
| Q5 | две ступени **на ребре** + `rationale` + `domain × basis`; GRADE не берём | грубость снимается типизацией |
| Q6 | `basis: analytic` + `by_construction` + ссылки на допущения; исключается из метрик находки и frontier | «плательщики выигрывают» больше не украшает отчёт |
| Q7 | чужое утверждение = **наш узел** + свидетельство-локатор (DOI + секция + цитата); «авторы утверждают X» и «X верно» — разные узлы | больше узлов, зато сравнение утверждение-с-утверждением |
| Q8 | struct + LaTeX, struct — истина, парсится (sympy-грамматика), единицы UCUM; OpenMath/MathML не берём | ограничение грамматикой |
| Q9 | кусочная формула — **один узел** с `cases: [{context, expr}]`; режимы — ветви, не версии | — |
| Q10 | UCUM `1` + нулевой вектор + пометка `ratio | count | index` | доли не складываются со счётчиками |
| Q11 | карта фиксированного размера: counts, communities, инварианты, frontier top-k с маркером усечения, хэши | всё растущее — top-k |
| Q12 | сообщества вручную по линиям; алгоритм — только аудит кандидатов в мосты | ручная разметка дешевле неверной |
| Q13 | `graph_hash` (Merkle) + `schema_version` + `built_at`; глаголы сверяют хэш | — |
| Q14 | ребро experiment → чужой claim со `scope`; фактически подтверждает **мост**; `model`-прогон не может `supports` `world` без моста | третий узел в цепочке |
| Q15 | импорт **всех** `FINDING-` как legacy (`extracted`/`hypothesis`); refuted только по валидному контр-свидетельству; кладбище решается фильтром `--all` | полный импорт шумит меньше, чем теряет |
| Q16 | обязательный `refutation_reason: code_defect | setup_defect | nature | scope_error`; **дефект кода опровергает прогон, а не утверждение** | «опровергнуто багом» не вечно |
| Q17 | T0 повтор = целостность; T1 робастность (≥3 сида) = усиление; T2 репликация = независимая реализация **или** согласие Lean и прогона → `replicated` | свою терминологию фиксируем в `definition` |
| Q18 | `human_confirmed` = владелец, аннотация с датой; тратить только на мосты, определения и спорные повышения | уровень редок — так и надо |
| Q19 | три триггера: календарь, **зависимости**, миграция схемы; Lean-доказанное не протухает, протухает применимость | dependency-driven главный |
| Q20 | не блокировать сборку; авто-понижение `established → at_risk` вниз с логом; жёсткий fail — только структурные инварианты | противоречие остаётся знанием |
| Q21 | git-тег + `graph_hash` в отчётах; «знали на дату X» = checkout | — |
| Q22 | `basis: stipulative` вне лестницы; философия без нагрузки остаётся в markdown | KG хранит только используемое |
| Q23 | заморозить eval **до** импорта: ~20 вопросов + **5 негативных контролей**; метрики: покрытие без чтения файлов, F1 выданного множества, токены | база сама обязана быть опровержима |

## 3. Дельта схемы

```json
{"id": "CLM-0412", "kind": "claim", "text": "При h < 1 плато конечно",
 "domain": "model", "basis": "empirical", "bridge": false,
 "context": "CTX-0142", "terms": ["DEF-07@2"],
 "provenance": "verified_agent", "epistemic": "supported",
 "evidence": [{"ref": "EXP-0311", "strength": "strong", "scope": {"seeds": [1,2,3]}, "rationale": "verdict passed, T1"}],
 "created_at": "…", "valid_time": "…", "stale_after": "…", "supersedes": null}

{"id": "CTX-0142",
 "params": [{"symbol": "h", "op": "<", "value": 1, "unit": "1"}],
 "prose": "детерминированный режим, без внешнего шума"}
```

Сравнение контекстов: пересечение интервалов по общим символам; отсутствующий символ = без ограничения; проза-хвост
даёт компонент `unknown`. Условное противоречие = противоположные claims ∧ overlap ≠ disjoint. `unknown` → очередь
разбора, **не** молчаливый пропуск.

| kind | обязательное | ось статуса |
|---|---|---|
| claim | context, domain, basis, evidence (для `supported`+) | epistemic + provenance |
| formula | struct, symbols+units, cases[context], check (Lean ∨ прогон) | epistemic + provenance |
| experiment | cmd, seed, code_hash, params, verdict, tests[] | validity |
| dataset | PID, license, accessed_at, version | integrity |
| definition | текст, область употребления | active / deprecated |
| question | владелец, условие закрытия, context | open / closed |

**Три группы инвариантов вместо одного списка.**

- **Жёсткие (fail):** висячие ссылки; ID не переиспользуются; дубли (текст+context) вне `same_as`; `same_as` —
  классы эквивалентности; `supersedes` ацикличен; обязательные поля по `kind`; формат `context`; единицы всех символов;
  гомогенность размерностей; безразмерные аргументы `exp/log/sin`; запрет аффинных единиц (°C) в произведениях.
- **Потолки (вниз автоматически, вверх никогда):** `epistemic ≤ cap(provenance)`; `established ⇒ ≥1` strong-валидное
  свидетельство ∧ ¬contested ∧ upstream чист; `refuted ⇒` валидное контр-свидетельство; `world-established ⇒` полный
  текст ∨ валидный мост; `contested ⇒ ≤ supported`.
- **Вычисляемые:** `contested`, `at_risk`, условные противоречия, цепочки, frontier, аудит сообществ.

## 4. Источник истины: решение конфликта

**Решение:** канон — **корпуса** (`kg/claims.jsonl`, `docs/ELEPHANT-LITERATURE.md`, `results/*/run-*.json`, `laws/`).
`kg/nodes.jsonl` — **производное** представление, пересобирается `migrate.py`; править его руками нельзя, и агентские
изменения идут в корпус. `check` теперь падает, если `nodes.jsonl` расходится с корпусом (пересборка даёт другой хэш).

**Что уже сделано в коде** (этот цикл):

| изменение | зачем |
|---|---|
| `kg.py` получил `resolve_refs` и отчёт по ссылкам | 410 «висячих» ссылок на прогоны были не дырой данных, а **неумением разрешать**: теперь разрешаются 518 из 518 (путь, алиас `EXP-NN`, файл `FINDING-NNN`) |
| `migrate.py` больше **не глотает** битый JSON и повтор ID | потеря свидетельства больше не проходит молча |
| `run.sh all` включает раздел `kg` | гейт проекта теперь проверяет и граф |

## 5. Исправленный порядок шагов

0. Документ решений (эта страница) + заморозка eval-вопросов (`docs/KG-EVAL-QUESTIONS.md`).
1. Пилот: 8 узлов с `kind/context/basis/domain`.
2. `check` v2: три группы инвариантов + размерностный чекер + overlap контекстов — **ворота импорта**.
3. 31 формула: struct-first, единицы, `cases` — первый настоящий экзамен.
4. **Мосты `A↔B`** — выписать десятки alignment-claims **до** `FINDING-`-импорта.
5. `FINDING-`: полный триаж + `dataset`-узлы + дедуп; eval после каждой партии.

**Критерий этапа:** «что мы знаем про цену удержания» — один `expand`, ноль открытых файлов; негативные контроли
отвечают «не знаем»; карта ≤ 15k токенов; `check` зелёный по жёсткой группе.
