# QUESTIONS.md — очередь вопросов

**Зачем.** Владелец выходит на связь не постоянно. Вопрос, заданный в пустоту,
теряется; вопрос, записанный здесь, доживает до разговора. Когда владелец
появляется, он собирает ответы по всей очереди и приносит их пачкой.

**Правило:** см. `AUTONOMY.md` §1.1c. Упёрся — записал — продолжил, если можно.

**Формат.** Одна запись на вопрос. Вопрос должен быть самодостаточным: понятен
через три дня без контекста.

| поле | что писать |
|---|---|
| дата | когда возник |
| кому | `владелец` или `исследователь` |
| вопрос | сам вопрос, с границами: «что известно о X при условии Y» |
| что блокирует | какой шаг не идёт без ответа |
| что делаем, пока нет ответа | обходной путь или «ждём» |
| статус | `открыт` / `отвечен` / `снят` |

### Q-003 · владелец · 2026-11-15

**Вопрос.** Как задавать горизонт `T` в пункте 3 `PROTOCOL-0` (сканирование
смерти от урона)? Прогон на точной модели `step()` показал: смерть от урона
достижима при любом `taken >= maint`, но наступает на шаге

протокол ставит 5000 и получит `alive` там, где смерть придёт позже. Варианты:
(а) считать `T` по формуле с запасом x2; (б) ограничить сетку `dr >= 0.01`;
(в) оставить 5000 и объявлять `void` для ячеек, где `T` недостаточен.

**Что блокирует.** Запуск пункта 3 и любые утверждения о «смерти от урона».

**Что делаем, пока нет ответа.** Пишем в протокол формулу горизонта как
требование, без выбора варианта.

**Статус:** открыт.

**Что делаем, пока нет ответа.** Держим как рабочую заметку, в протокол не
вносим.

**Статус:** открыт.
