# EXTERNAL-SKILLS-2026-11-20.md — что взять из `scientific-agent-skills` и что не брать

**Источник:** https://github.com/K-Dense-AI/scientific-agent-skills (MIT, 177 навыков, стандарт Agent Skills,
статья arXiv:2609.00065).

**Короткий ответ.** Устанавливать коллекцию **не нужно**: 90 % навыков — мокрая лаборатория, клиника, химия, приборы.
Но **пять** из них закрывают ровно те дыры, которые мы нашли в кампании. Их дисциплину берём **текстом**, а не
пакетом: репозиторий должен оставаться самодостаточным.

---

## 1. Что там есть (по важности для нас)

| навык | что делает | нужно ли нам |
|---|---|---|
| **paper-lookup** | 18 научных API: PubMed, PMC, Europe PMC, arXiv, **OpenAlex**, **Crossref**, Semantic Scholar, CORE, Unpaywall, OpenCitations, Zenodo, DOAJ, ROR…, с проvenance | **да** — но у нас уже есть `domain_search` с теми же движками; не хватает **журнала поиска** (§3) |
| **literature-review** | систематические обзоры: **охват поиска**, «записи против исследований», ограничения доказательств | **да** — это наша слабая сторона (`G-001`, `G-002`) |
| **bgpt-paper-search** | извлечение **утверждений уровня claim** из полного текста, с ограничениями и provenance | **да** — это ровно то, для чего мы сделали `kg/` |
| **hypothesis-generation** | ограниченные доказательствами гипотезы, конкурирующие объяснения, **preregistration-ready** план | **да** — совпадает с `PREDICTIONS.md` |
| **uncertainty-and-units** | проверка размерностей, порядков величины, «правдоподобно ли число» | **да** — наши «невозможные числа» — тот же класс |
| **statistical-analysis / power / experimental-design** | выбор теста, **MDE**, план эксперимента | **частично** — у нас есть `mde` в прогонах, но нет проверки предположений |
| **arbor** | дерево гипотез: постоянные гипотезы, изолированные эксперименты, распространение свидетельств | **интересно** — близко к `kg/` + `PREDICTIONS.md`; смотреть как архитектуру, не ставить |
| **citation-management** | поиск по OpenAlex/PubMed, валидация ссылок, BibTeX | **частично** — наши `L-` уже с локаторами; BibTeX понадобится для бумаги |
| **scientific-critical-thinking** | оценка качества доказательств (GRADE, risk of bias) | **да** — для ревизий и рецензий |
| остальные ~165 | геномика, протеомика, визуализация, постеры, LIMS, регуляторика | **нет** |

## 2. Что берём — и в какой форме

**Форма:** не пакет, а **правила в наших файлах**. Причины: (1) 177 навыков раздувают каталог и внимание; (2) каждый
навык — код, который может выполнять скрипты (риск); (3) наши правила уже проверяются гейтом, а их — нет.

| берём | куда |
|---|---|
| **журнал поиска** (охват, запросы, источники, дата) | `docs/LITERATURE-SEARCH-LOG.md` — заведён |
| «записи против исследований» (одна статья ≠ одно свидетельство) | `ELEPHANT-LITERATURE.md`: поле `Проверено` уже есть, добавить правило «сколько записей — столько свидетельств» |
| claim-level извлечение | `kg/`: утверждение с `evidence` и `context`, а не цитата абзаца |
| preregistration | `PREDICTIONS.md`: вероятность до прогона (уже есть) |
| проверка размерностей и порядков | новое правило: **любое новое число проверяется на размерность и порядок** до записи |
| GRADE-подобная оценка | в `L-` добавить `strength` (сильная/слабая) рядом с уровнем доверия |

## 3. Главный вывод: чего у нас не было

Из шести навыков один указывает на **реальную дыру кампании**: систематический обзор требует **фиксировать охват
поиска** — какие источники, какие запросы, когда, сколько найдено и сколько отсеяно. Мы этого **не делали**, отсюда
`G-001` («не закрыто») и `G-002` («полные тексты недоступны») выглядят как мнение, а не как процедура.

**Исправлено:** заведён [`docs/LITERATURE-SEARCH-LOG.md`](LITERATURE-SEARCH-LOG.md) — каждая строка: дата, запрос,
источник, найдено, отсеяно, что записано.

---

## 4. Что **не** берём и почему

1. **Установку всей коллекции** — 90 % нерелевантно, а каталог навыков влияет на поведение агента.
2. **Навыки, требующие ключей** (Exa, Parallel, Paperclip, Benchling): сначала бесплатные пути, ключи — по нужде.
3. **Навыки-генераторы** (слайды, постеры, инфографика): не наш этап.
4. **arbor как зависимость**: архитектура интересна, но у нас уже есть `kg/` и `PREDICTIONS.md`; дублировать не надо.

---

## 5. Что стоит сделать дальше (предложения, не сделано)

1. **`kg/` ↔ `paper-lookup`**: связать утверждения с внешними ID (DOI, OpenAlex ID), чтобы проверка ссылок была
   машинной.
2. **`strength` в `L-`**: сильное/слабое свидетельство — по GRADE, а не по интуиции.
3. **Проверка размерностей** в `checks/`: новое число в документе обязано иметь единицу или быть безразмерным.
4. **`arbor`-подобное дерево гипотез** поверх `kg/`: гипотеза → конкурирующие объяснения → различающий эксперимент.
