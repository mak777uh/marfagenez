# FINDING-275. Личный запас стоит чего-то, только если вмещает **один шаг починки**

**Слону:** уточняет, что именно даёт локальный возврат. Я думал, что всё дело в **бездонности** кармана, и
предсказал, что потолок 1.0 убьёт преимущество. **Не убил** — потому что 1.0 больше, чем карман когда-либо
держит (0.361). Настоящий порог оказался **ровно равен нужде одного шага**: при `cap < u_min` население падает,
при `cap ≥ u_min` — держится на потолке.

**Дата:** 2026-11-19. **Статус:** (a)(b) **опровергнуты**, (c) `passed`; и найден настоящий порог. **Цикл:** 239.

## Предсказания, записанные до прогона

- **(a)** при бездонном кармане население растёт с долей;
- **(b)** при потолке кармана **1.0** преимущество исчезает;
- **(c)** с потолком кармана форм не больше, чем без него.

## Результат 1: потолок 1.0 **ничего не меняет**

| доля | бездонный | с потолком 1.0 |
|---|---|---|
| 0.00 | 500 | 500 |
| 0.20 | 550 | 550 |
| 0.40 | 450 | 450 |
| 0.60 | 1200 | 1200 |
| 0.80 | 2450 | 2450 |
| 1.00 | 5000 | **5000** |

**Совпадение во всех шести точках.** Причина: при полной локальности средний карман **0.361** — потолок 1.0
**не связывает**.

## Результат 2: свип потолка при полной локальности — **порог найден**

| потолок кармана | живых |
|---|---|
| **0.001** | **550** |
| **0.005** | **1000** |
| **0.010** | **5000** |
| 0.020 | 5000 |
| 0.050 | 5000 |
| 0.200 | 5000 |
| 1.000 | 5000 |
| нет потолка | 5000 |

**Порог — ровно 0.010 = `u_min`, нужда одного шага починки.**

Ниже него население падает (550 и 1000), на нём и выше — упирается в потолок 5000. Переход **резкий**.

## Что это доказывает

- **Личный запас полезен тогда и только тогда, когда вмещает следующий шаг починки.** Меньше — и он не успевает
  помочь: возвращённое приходит по капле, а починка нужна целым шагом.
- **Бездонность не при чём:** потолок в 1.0 (втрое больше среднего кармана) ничего не меняет.
- **Порог дискретный и точный:** `pocket_max ≥ u_min`.

## Что это не доказывает

- Не объясняет **немонотонность по доле** (550 при 0.2 против 450 при 0.4) — она остаётся необъяснённой.
- Не доказывает, что порог равен именно `u_min` при других параметрах: проверен один набор
  (`d = 0.05`, `q_min = 0.2`, `c = 1`).
- Один `ready_max = 5`; при другом потолке среды порог может сдвинуться.

## Что дальше — предсказание до кода

**Проверить, что порог равен `u_min`, а не «0.01»:** изменить `q_min` (0.1 и 0.4) и посмотреть, поедет ли порог
вместе с нуждой.

**Предсказание:** при `q_min = 0.1` порог станет **0.005**, при `q_min = 0.4` — **0.02**. Если порог останется
0.01 — значит он привязан к чему-то другому (например, к `birth_price`), и моя формулировка неверна.
