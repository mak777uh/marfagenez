## 2. Моя работа по приоритетам

### П1. Формулы — основная линия (каждый раунд)

Одна формула или теорема за раунд. Порядок проверки **всегда один и тот же**:

1. **единицы** — все символы объявлены; размерность каждого слагаемого сходится;
2. **пределы** — что при `x → 0`, `x → ∞`, на границе параметров; есть ли разрыв или излом;
3. **различимость** — отличается ли предсказание от ближайшей альтернативы; если нет, формула не проверяема;
4. **опровергающее условие** — какое наблюдение её убьёт (и это должно быть наблюдаемо);
5. **числа** — пример с посчитанными значениями, а не «примерно».

Инструмент в `tools/`, документ `docs/FORMULA-*.md`, `rc=1` когда опровергающее условие срабатывает.

**Очередь (по состоянию на 25.11.2026):** `F-004` ✅ (единица `κ` исправлена), `F-022` ✅ (условие
переименовано), `F-030` ✅ (новизна переформулирована), `F-011` ✅ (помечен набросок).
**Осталось:** `F-031` (граница: RAF необходимо, но не достаточно), `F-028` (adder/sizer), `F-002`
(удержание и плато), `F-001` (кумулятивная опасность), `F-013`, `F-018`, `F-023`, `F-025`, `F-026`, `F-027`
(проверены ранее — при новых данных перепроверять).

### П2. Проверка **за** формулами (связка с данными)

Формула без проверки на числах — не проверена. Для каждой формулы:

- `math.checked` указывает на прогон/источник;
- если формула опирается на данные ячеек — записать, **какие** ячейки и **какое** число;
- если опора — литература, указать `L-*`/DOI и что именно подтверждено.

Это то, что «за формулами»: не проверка данных (`probe`), а проверка того, что формула опирается на данные,
а не на воздух.

### П3. Публикация и приём (обязательно, каждый раунд, но быстро)

`inbox` → `map_ingest` (с `--edges`) → `kg/migrate.py` → `kg.py build` → `regress.py` → эмбеддинги по
маркеру → `verify`/`close` раундов агентов → **журнал до коммита** → коммит и push.

### П4. Покрытие: ингест источников, которых в карте нет

**Главный рычаг, а не сшивка.** 94 узла `L-*` без ячеек в карте. Работа:

1. выписать `L-*` с DOI, которых нет среди DOI карты;
2. отдать `fast` партиями: «вот работа, внеси 3–5 ячеек с локаторами»;
3. после приёма — искать `S`-пары обычным порядком.

### П5. Синтез (`P10`) — раз в ~20 раундов

Обзор для читателя: «что проверено / что наша конструкция / что открыто». Материал копится в
`docs/THREE-CRITERIA.md`, `docs/FORMULA-*.md`, `docs/ERRATA-SUMMARY.md`.

## 5. Правила, которые соблюдаю

1. **Журнал до коммита.** После правки `kg/` — прогон `units_symbol_audit` и `wiring_audit` **до** коммита.
2. **Порядок величин** проверять пересчётом, а не «на глаз».
3. **Свою арифметику — так же, как чужую.** За вечер три раза ошибался я, а не данные.
4. **Если «не сходится в 1000 раз»** — сначала проверить свои единицы.
5. **Проверка без подложенной ошибки, скорее всего, не работает.** Мой валидатор трижды отвергал корректную
   работу агента — проверки тоже надо проверять.
6. **Историю не переписываю:** правки — датированными дополнениями, старая формулировка — в `MAP-ERRATA.md`.
7. **Не выдаю своё за источник.** Восстановленное из чисел помечаю как «наша реконструкция».

## 6. Протокол раунда (короткий)

```
1. probe_bridge --serve          → принять вопросы/посылки
2. адъюдикация                    ≤15 мин: вердикт + балл + правка данных
3. П1: одна формула по 5 шагам    инструмент + документ
4. П2: связать формулу с данными  math.checked / какие ячейки
5. П3: партии fast → ingest → kg → гейт по маркеру
6. П4: если есть DOI-долг — выписать fast
7. журнал → коммит → push
```

Полный `bash run.sh all` — раз в 3–5 раундов, не каждый.

## 7. Эскалация

- Гейт красный **два раунда подряд** по одной причине → стоп содержательной работы, чиню причину.
- Внешняя блокировка (платный DOI, нет текста) → пишу владельцу, не выдумываю.
- `probe` прислал вопрос, который я не могу проверить → отвечаю «не могу проверить» с причиной, а не
  «принято».
