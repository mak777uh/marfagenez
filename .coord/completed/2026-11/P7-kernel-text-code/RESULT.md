# Раунд P7 — 2026-11-25 — `KERNEL-TEST`: текст против кода

## Вопрос

Совпадает ли документ `docs/KERNEL-TEST.md` с тем, что **реально считает** `tools/kernel_viab.py`?
Прежняя формулировка обещала «проекцию ядра выживания», а код, насколько было видно, ядро не вычисляет.

## Предсказание (до проверки)

Ожидалось: (а) симулятор стартует из одного состояния и не перебирает начальные; (б) «полоса alpha»
считается алгебраической формулой, а не из множества выживающих траекторий; (в) «пусто» — это ветка
`if`, а не результат вычисления.

## Что проверено в коде

| утверждение документа | что в коде |
|---|---|
| «проекция ядра выживания на ось alpha» | функция `kernel_alpha_band()` — формула бюджета запаса: `need = 0.02·k·p`, `lo = 1 − need/INCOME` |
| «ядро для трёх определений K» | три вызова той же формулы с разными `p_need`; перебора начальных состояний нет |
| «пусто» в строке про `q ≥ 0.5` | ветка `if q_star < 0.5`, то есть **условие**, а не вычисление |
| ширина `[0, 1]` в строке про `q ≥ q*` | следствие `max(0, lo)` при `lo = 1 − 0,02·400·0,02/0,04 = 1 − 4 < 0` |
| симулятор | `one()` стартует из `q = 1, stock = 0, damage = 0`; используется только для валидации `FINDING-314` и разброса |

## Что исправлено в тексте

1. Раздел переименован: «Три определения K: аналитическая полоса по бюджету запаса».
2. В начало раздела вставлено предупреждение: симулятор стартует из **одного** состояния, полоса —
   формула, а не множество траекторий.
3. Под таблицей сказано, что «пусто» — условие в коде, а `[0, 1]` — следствие ограничения снизу.
4. Добавлен раздел «Что этот тест реально проверяет»: (а) порт воспроизводит `FINDING-314` с
   расхождением не больше 6 %; (б) разброс 12 % против записанных 10 %; (в) аналитическая полоса даёт
   только 0 % или 100 %.
5. Явно сказано: вычисления ядра выживания как множества начальных состояний в файле **нет**;
   «проекция ядра» относится к замыслу.

## Числа (из прогона)

- расхождение порта: худшее 6,0 % (при допуске 15 %) — порт верен;
- разброс средних времён жизни по `alpha` в режиме смертельной засухи: **12 %** против записанных 10 %;
- ширины аналитической полосы: 100 % / 0 % / 100 % — ни одна не попадает в полосу 3–10 %.

## Проверки

- `python3 tools/kernel_viab.py --write` — документ пересобран;
- `python3 checks/doc_links.py` — зелёный;
- `python3 checks/doc_numbers.py` — числа совпадают с деревом;
- `python3 checks/log_check.py` — журнал непрерывен.

## Что это НЕ доказывает

- Что ядро выживания в этой системе действительно имеет ширину 100 % или 0 %: ядро просто не вычислялось.
- Что `CORR-01` неверен по существу: показано лишь, что прежний тест его не проверял.
- Что разброс 12 % подтверждает 10 %: это разные числа, совпал только порядок.

## Следующий вопрос

Если формулировка `CORR-01` сохраняется, нужен **настоящий** расчёт ядра: перебор начальных состояний
`(q, stock)` на сетке и проверка выживания на горизонте. Без этого «проекция ядра» остаётся названием,
а не результатом.
