# Раунд P79 — 2026-11-25 — сплошной экран S-пар: одна переоценка найдена

## Вопрос

Можно ли проверить все 37 `S`-пар механически, а не перечитыванием, и есть ли среди них переоценённые?

## Ответ: механически проверяется часть; одна переоценка нашлась

Правило уточнено:

- для **узла-определения** `S` = «атом из той же работы формулирует то же утверждение»;
- для **измерения** `S` = «совпадает величина», и числа должны совпадать, если они есть с обеих сторон.

`tools/stitch_s_screen.py` проверяет второе: ищет `S`-пары, где числа есть с обеих сторон, но не совпадают.
Годы исключены (это ссылки, а не величины) — без этого было 3 «кандидата», из которых 2 оказались годами.

| категория | сколько |
|---|---|
| чисел нет с одной стороны (только чтение) | 28 |
| числа есть с обеих сторон и не совпадают | **1** |
| числа совпадают | 8 |

## Найденная переоценка: `B26-01-0004 | C-003`

- **атом:** в модели `E. coli` iML1515 наибольшая SCC содержит **748 из 1713** метаболитов — **43,7 %**;
- **узел:** мера замыкания **различает** цепочку, частичный цикл и замкнутый цикл значениями
  **0,25 / 0,75 / 1,0**.

Величина та же (доля вершин в наибольшей SCC), но **предсказание другое**: 43,7 % для реальной сети не
подтверждает различение трёх топологий. **Понижено `S → Ch`.**

## Цена

| метрика | было | стало |
|---|---|---|
| `S`-пар | 37 | **36** |
| узлов с `S`-парой | 22 | **21** |
| из них с `lit_ref` | 20 | **19** |

Пол понижен **явно** через `--update` и объяснён в записи, а не подменён молча.

## Проверки

- `python3 tools/stitch_s_screen.py` — 1 кандидат (тот самый), 28 пар требуют чтения;
- `python3 checks/stitch_coverage_floor.py` — 36/21, пол совпадает;
- `python3 checks/doc_numbers.py`, `python3 checks/doc_links.py` — зелёные.

## Что это НЕ доказывает

- Что остальные 36 `S`-пар верны: **28 из них не проверяются механически** — в них нет чисел с обеих
  сторон, и судить можно только чтением.
- Что `C-003` вообще не опёрта: мера та же, не хватает именно проверки различения топологий.
