# Раунд P40 — 2026-11-25 — различимость параметров сведена в правило

## Вопрос

Пять раз в этой линии встречалось одно и то же: параметры входят произведением, данные различают
комбинацию. Можно ли сделать из этого общее правило и инструмент, а не повторять открытие каждый раз?

## Результат

**Правило.** Если параметры входят только произведением:
- в тексте называть наблюдаемую **комбинацию**, а не «параметр»;
- проверка не может быть точечной — нельзя «измерить δ», можно δ·T;
- два набора множителей с одинаковым произведением — **одна формула**, выбрать между ними по данным нельзя.

**Подтверждённые случаи:** `F-001` (`alpha = lambda·delta`), `F-002` (`delta·T`), `F-017` (`q^nu`),
`F-006`/`F-019` (`Pi·lambda`), `F-020` (`μ₀` и `α` компенсируют друг друга).

**Инструмент.** `tools/identifiability.py` механически ищет произведения в латексе и печатает кандидатов;
первая версия давала мусор из обрывков слов (`l·n` из `ln`, `d·t` из слов), добавлен фильтр. Полученный
список всё равно требует чтения глазами — это написано в документе.

## Что сделано

- `tools/identifiability.py` — поиск произведений по латексу;
- `docs/IDENTIFIABILITY.md` — сводка: подтверждённые случаи + кандидаты + как пользоваться;
- `docs/UNITS-AUDIT.md` §10 — правило и таблица случаев.

## Проверки

- `python3 tools/identifiability.py --write` — генерация воспроизводима;
- `python3 checks/doc_links.py` — зелёный.

## Что это НЕ доказывает

- Что параметр в произведении бессмыслен: смысл может быть, а измерение — только комбинации.
- Что комбинацию нельзя расщепить другим опытом: часто можно, меняя один множитель независимо.
- Что кандидаты из латекса верны: регексп даёт ложные срабатывания, список — для чтения.
