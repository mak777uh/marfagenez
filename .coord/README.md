# `.coord/` — координация исследовательских агентов

Один общий каталог, никаких отдельных копий и веток. Git обслуживает **только `main`**: остальные
агенты пишут файлы напрямую, `main` публикует завершённые изменения всех.

## Кто есть

| агент | роль | Git |
|---|---|---|
| `main` | основной исследователь, публикует, закрывает задачи после проверки | **да** |
| `fast` | равноправный исследовательский партнёр, работает быстрыми циклами | **нет** |

Регистрация: `.coord/agents/<name>.md`.

## Каталоги

```
pending/<ID>/TASK.md     свободная задача: менять можно (формулировка, приоритет, область)
active/<ID>/TASK.md      взятая задача: НЕИЗМЕНЯЕМА (контроль по sha256 в .claim.json)
active/<ID>/RESULT.md    результат (пишет только исполнитель)
active/<ID>/DONE.json    заявка о завершении: артефакты + проверки
completed/<ID>/...       закрытые задачи (переносит только main после проверки)
events/                  журнал событий, только добавление
```

## Команды (инструмент `tools/coord.py`)

```
python3 tools/coord.py list
python3 tools/coord.py add --id ID --title "…" --area "glob1,glob2" --accept "команда" --priority N --agent main
python3 tools/coord.py take ID --agent fast       # атомарно: temp → rename в active/
python3 tools/coord.py finish ID --agent fast     # заявка о завершении (RESULT.md + DONE.json)
python3 tools/coord.py verify ID                  # main: прогнать accept-команды
python3 tools/coord.py close ID                   # main: active → completed
python3 tools/coord.py stale                      # смерть по boot/heartbeat; возраст — диагностика
python3 tools/coord.py status                    # read-only; --write явно обновляет STATUS.md
python3 tools/coord.py release ID --agent fast --reason "…"
```

**Взятие атомарно:** карточка и claim сначала собираются в скрытом temp-каталоге, затем один
`os.rename` делает commit-точку. `recover` завершает обрыв между rename и удалением pending-дубликата.

## Правила

**Объявляйте область шире, чем кажется нужным (25.11.2026).** За один день шесть задач пришлось
перезаключать или закрывать в два-три захода, потому что область объявлялась поштучно и не включала файлы,
которые работа затрагивала неизбежно: `docs/FINDING-*.md` при находке, `docs/FORMULA-UNITS-BASELINE.json`
при обновлении порога, `tools/new_finding.py` при правке аллокатора.

Практика: указывайте **каталоги и шаблоны**, а не отдельные файлы, если работа хоть немного
исследовательская:
`docs/FINDING-*.md` вместо `docs/FINDING-450.md`, `docs/` вместо одного документа. Область — это
контракт о том, что вы не тронете чужое, а не попытка угадать список файлов.

## Правила, которые нельзя нарушать

1. **Взятая задача неизменяема.** `take` записывает sha256 `TASK.md`; правка после взятия — нарушение.
2. **Рабочая область — из карточки.** Файлы вне области не редактируются; нужные — отдельной задачей.
3. **Завершение проверяется, а не заявляется.** `finish` — только заявка. `main` прогоняет
   `accept`-команды из карточки и лишь потом делает `close`.
4. **Очередь меняют все, активную задачу не трогает никто** (кроме исполнителя в рамках работы).
5. **Просрочка доказывается смертью исполнителя.** `recover`/`release --force` используют смену `boot_id`
   или отсутствие heartbeat дольше 30 минут. Возраст больше 180 минут при живом heartbeat — только
   предупреждение: по возрасту живую задачу нельзя забрать.

## Защищённые зоны (fast НЕ правит)

`core/`, `laws/`, `verus/`, `checks/`, `run.sh`, `AGENTS.md`, `kg/nodes.jsonl`, `kg/migrate.py`,
`kg/kg.py`, `tools/coord.py`. Причина: на них стоит контракт состояния агента и инварианты гейта.
Нужна правка — отдельная задача с явным указанием файла и согласованием через очередь.

## Как агенты пишут в литературную карту, не затирая друг друга

Прямая правка `literature/map/atoms.jsonl` и `edges.jsonl` **двумя агентами невозможна** (потеря
записи). Поэтому:

- каждый агент пишет **свой** файл `literature/map/inbox/<agent>-<task>.jsonl` (атомы и/или рёбра);
- приём идёт через `tools/ingest_safe.py` (flock, backup, rollback, contract), который вызывает `tools/map_ingest.py`; затем `main` пересобирает `kg/`;
- `main` — единственный, кто запускает `tools/build_embeddings.py`.

## Журнал циклов

Номера циклов в `docs/agent/AGENT_LOG.md` присваивает **только `main`** при публикации, чтобы не было
дублей. Агент пишет фрагмент в `active/<ID>/JOURNAL-FRAGMENT.md`, `main` переносит его с номером.

## Проверки

- `fast` гоняет **точечные** проверки своей области (например `checks/map_contract.py`,
  `checks/doc_links.py`) — это секунды.
- `main` гоняет **полный** `bash run.sh all` перед публикацией — это дорого, поэтому редко.

1. **Пересечение областей.** Если `--area` новой задачи пересекается с областью любой активной —

2. **Защищённые зоны.** Если область задевает `core/`, `laws/`, `verus/`, `checks/`, `run.sh`,

   `main`. Причина: на этих файлах висит контракт состояния агента и инварианты гейта.

### Git: запрещено не только перечисленное

Кроме `add/commit/push/pull/checkout/reset/clean/merge/rebase` запрещены **`stash`, `restore`,
`switch`, `rm`, `worktree`**. Причина: они меняют незакоммиченное состояние чужих правок и формально
не нарушают букву старого списка.

### Дорогие операции — только `main`

| операция | почему |
|---|---|
| `tools/build_embeddings.py` | 580 узлов, сетевой кэш модели; гонка двух сборок ломает индекс |

| `results/` целиком | каталог общий, пишут только задачи, которые явно это объявили |

`fast` гоняет точечные: `checks/map_contract.py`, `checks/doc_links.py`, `checks/log_check.py` — секунды.

### Общие документы

`docs/*.md` — **один автор за раз**. Свой документ правишь свободно; чужой — только через отдельную
задачу. Иначе правки теряются молча (файл перезаписывается целиком).

### Что делать с частичным результатом

Если задачу не удалось довести: `release ID --agent <имя> --reason "…"`. Файлы `RESULT.md` и
`DONE.json` при этом переименуются в `*.abandoned`, карточка вернётся в `pending`. `main` решает,
переиспользовать её или закрыть.

### Требование к пути

Оба агента работают по одному пути **`/root/marfagenez`** (WSL). Путь через
`\\wsl.localhost\...` медленный и рвётся — использовать нельзя.

## Постоянные задачи (`standing`)

Три задачи **никогда не исчезают** и не закрываются в `completed/`. Каждое взятие создаёт отдельный
раунд `active/<ID>-<время>/`; карточка остаётся в `pending/` для следующего раунда.

| ID | о чём | полная инструкция |
|---|---|---|
| `S1-experiments` | прогоны, проверки, воспроизводимость | `.coord/standing/S1-experiments.md` |
| `S2-literature-graph` | ячейки, связи, сшивка, дипы | `.coord/standing/S2-literature-graph.md` |
| `S3-formulas-lean` | вывод, единицы, пределы, Lean | `.coord/standing/S3-formulas-lean.md` |

**Раунд** — это один инкремент: один вопрос, одно предсказание до запуска, один результат с командой,
точечные проверки, `RESULT.md` + `DONE.json`. Раунд постоянной задачи закрывается как обычная задача
(`finish` → `verify` → `close`), но карточка в `pending/` остаётся.

Отказ от раунда: `release <ID-раунда> --agent <имя> --reason "…"` — каталог раунда удаляется,
постоянная карточка не страдает.

Правило разделения: **постоянные задачи — для регулярной работы**, задачи вида `P*` — для конкретных
целей из плана. Если постоянная задача упирается в правку защищённой зоны, оформляется `maint`-задача.

## Что проверяется кодом (после аудита 25.11)

Это не обещания, а отказы инструмента:

| правило | где | что происходит при нарушении |
|---|---|---|
| рабочая область **обязательна** и нормализуется (без `..`, без абсолютных путей) | `take` | отказ брать задачу |
| пересечение областей считается по литеральному префиксу, **без границы `/`** | `take` | отказ при конфликте (цена — редкие ложные отказы, это осознанно) |
| защищённые зоны распознаются и после `./` и `..` | `take` | отказ для всех, кроме `main` |
| задачи вида `maint` | `take` | берёт только `main` |
| `verify` и `close` | `verify`, `close` | только `main` |
| `release --force` | `release` | только `main` |
| закрытие без проверки | `close` | отказ, если нет зелёного `VERIFY.json` с совпадающим sha256 карточки |
| `accept: true`, `echo …`, команда без `/` | `add` | отказ при заведении задачи |
| возраст задачи | `stale` | диагностика по UTC (`calendar.timegm`); сам по себе не даёт `recover` забрать claim при живом heartbeat |
| события | `event` | уникальное имя (`ts-pid-N-agent`); два события в одну секунду больше не затирают друг друга |


## Что теперь проверяется кодом (после внедрения F1–F10)

| правило | где | поведение при нарушении |
|---|---|---|
| **атомарная запись** всех файлов состояния (temp + fsync + replace) | весь `coord.py` | читатель видит старую или новую версию, не обрезок |
| **двухфазное взятие**: сборка в `.take-*` + один `os.rename` | `take` | до `rename` задачи не существует; `kill -9` оставляет только мусор `.take-*`, его снимает `recover` |
| **общий замок** `.coord/locks/coord.lock` на критические секции | `add/take/release/close` | протухший замок (>120 с) ломается по возрасту |
| **UTC-часы** (`calendar.timegm`) | `stale`, `list`, `status` | возраст считается верно при любом TZ |
| **область обязательна**, нормализуется, без `..` и абсолютных путей | `add`, `take` | отказ завести или взять задачу |
| **пересечение областей** по литеральному префиксу, без границы `/` | `take` | отказ (ложные отказы — осознанная цена) |
| **защищённые зоны** видны и после `./` и `../` | `take` | отказ всем, кроме `main` |
| **вид задачи** `maint` | `take` | берёт только `main` |
| **права** | `verify`, `close`, `recover`, `release --force` | только `main` |
| **завершение** | `finish` → `verify` → `close` | `close` без зелёного `VERIFY.json` невозможен |
| **артефакты** | `finish --artifacts` | путь проверяется: существует, внутри области, хэш фиксируется |
| **живой исполнитель** | `release --force` | отказ, если heartbeat свежий и `boot_id` тот же |
| **события** | `event` | имена уникальны (`ts-pid-N-agent`), ничего не затирается |
| **закрытие** | `close` | один `rename` в `.coord/completed/<YYYY-MM>/` |
| **мусор после сбоя** | `recover` | `main`: `.take-*` старше 5 мин, сироты без `.claim.json`, замки старше 10 мин |

## Heartbeat — обязательный элемент работы

```
python3 tools/coord.py heartbeat <ID> --agent <имя>
```

- не реже **каждых 15 минут** активной работы;
- обязательно **перед** и **после** долгой операции (`cargo build`, `lake build`, приём партии ячеек);
- `heartbeat` делает `os.utime` на `.claim.json` — если процесс убит, файл просто перестаёт обновляться;
- без heartbeat 30 минут задача считается брошенной, и `main` вправе вернуть её (`release --force`),
  но только если **и** `boot_id` сменился, **и** heartbeat протух — иначе отказ.

## Что добавлено по итогам аудита 25.11 (вторая волна)

| гарантия | как обеспечена |
|---|---|
| **ID и имена агентов** | `^[A-Za-z0-9][A-Za-z0-9._-]{0,79}$`, `..` и `/` запрещены — путь за пределы `.coord/` невозможен |
| **accept не исполняет shell** | строки с `; && \|\| \| > < \` $(` отвергаются; разрешён только `python3 <скрипт>`, запуск через `shlex` без `shell=True` |
| **артефакт «внутри области»** | отдельная функция `in_area` (нормализация + glob-match), а не `overlap`; `../` и абсолютные пути отвергаются |
| **замок не отнимается у живого** | слом только по возрасту >120 с, через `os.rename` в уникальное имя (ровно один ломатель); `finally` удаляет замок, **только если токен владельца совпал** |
| **release под замком** | проверки живости и перенос — в одной критической секции |
| **verify гасит старый зелёный** | любой ранний отказ пишет `VERIFY.json{ok:false}`; в зелёный добавлен `done_sha256` |
| **close перепроверяет всё** | `TASK.md`, `DONE.json` по `done_sha256`, каждый артефакт по хэшу |
| **kind** | только `research / request / maint` (argparse `choices`) |

### Граница доверия (честно)

`--agent main` — это **заявленная роль**, а не аутентификация: при общей учётной записи WSL процесс
технически может назваться кем угодно. Механические гарантии действуют против **ошибок и гонок**;
против намеренного обмана внутри одной учётной записи защита была бы нужна на уровне ОС (разные
пользователи, права файлов), и это вне рамок `.coord/`. Область задачи — тоже договорный барьер, а не
файловая песочница.

## Известные ограничения (не блокируют работу)

- `flock` вместо `mkdir`-замка был бы устойчивее к «зависшему» держателю; текущий замок ломается по
  возрасту 120 с, что для кооперативных агентов приемлемо.
- `finish`/`heartbeat`/`verify` не находятся в общем замке: узкая гонка с `close`/`release` возможна,
  лечится повторным запуском команды.
- `gens` фиксируется в claim, но не требуется как обязательный токен в каждой записи: зомби-процесс
  под тем же именем агента технически может писать. Для трёх кооперативных агентов это принято.

## Почта агентов и доска

Агенты переписываются не «в чате», а файлами в репозитории. Канал нужен для того, что не влезает в
карточку задачи: «здесь я сломал», «так делать нельзя», «передаю тебе контекст», «вопрос».

### Команды

```
python3 tools/coord.py note --agent fast --to main --kind bug \
    --topic "build_embeddings падает" --text "…" [--ref "PLAN P1"]
python3 tools/coord.py inbox --agent fast [--all] [--verbose]
python3 tools/coord.py read <файл.md> --agent fast [--print]
python3 tools/coord.py board --agent main --text "…"
python3 tools/coord.py unread
```

### Где лежит

```
.coord/mail/<агент>/new/<время>-<pid>-<от>.md   непрочитанное
.coord/mail/<агент>/read/<то же имя>            прочитанное
.coord/board.md                                  общая доска (append-only)
```

- `note` пишет письмо в чужой inbox; **никто не может стирать чужие письма**;
- `read` переносит письмо в `read/` — это и есть отметка «прочитано»;
- `inbox --all` показывает и прочитанное;
- `take` предупреждает о непрочитанном, `status` показывает счётчики.

### Виды сообщений

| вид | когда |
|---|---|
| `note` | передача контекста, «посмотри сюда» |
| `bug` | «здесь сломалось»: что именно, чем воспроизводится |
| `instruction` | указание другому агенту (в рамках его задачи или общей дисциплины) |
| `question` | вопрос, на который нужен ответ |
| `reply` | ответ на письмо (`--ref <id>`) |

### Правило

Почта — **оперативный канал**, а не хранилище знаний. Всё, что должно остаться, переносится в журнал
или в документ (`main` делает это при публикации). Поэтому `.coord/mail/` и `.coord/board.md` **не
коммитятся**: они не должны попадать в проверки чисел и в историю репозитория.

### Что писать в `bug`

1. Команда, которая падает (дословно).
2. Что ожидалось и что произошло.
3. Минимальный воспроизводимый шаг.
4. Что **не** делать, пока не исправлено (это самое ценное в письме).

## Приём партии в литературную карту (`tools/ingest_safe.py`)

`tools/map_ingest.py` перезаписывает `atoms.jsonl` и `edges.jsonl` целиком, поэтому напрямую его
запускать нельзя: два одновременных приёма теряют записи, а партия с нарушением контракта ломает карту.

```bash
python3 tools/ingest_safe.py literature/map/inbox/<агент>-<раунд>.jsonl --agent <агент> [--report …]
```

Обёртка: замок `.coord/locks/map-ingest.lock` → резервная копия в `.coord/backups/` → `--dry-run` →
приём → `checks/map_contract.py` → **откат при красном контракте**. Не-`main` принимает только свои
файлы `literature/map/inbox/<агент>-*`. Пересборка `kg/` и эмбеддингов после приёма — по-прежнему
только `main`.

## Нумерация `FINDING-*` по агентам

Карточки не умеют выражать числовые диапазоны, поэтому действует **конвенция**, а не проверка:

| агент | диапазон номеров |
|---|---|
| `main` | 300–349 |
| `fast` | 350–399 |

Номер выдаёт скрипт, а не глаз:

```
python3 tools/new_finding.py --agent fast --title "короткая формулировка"

Если диапазон исчерпан, добавляется следующий свободный блок: `main-2` = 450–549 (после исчерпания 300–349, 25.11.2026).
```

Скрипт берёт первый свободный номер в диапазоне агента и создаёт файл эксклюзивно (`O_EXCL`), поэтому перезапись чужой находки невозможна.
| `third` | 400–449 |

Правило: `FINDING-NNN.md` — **всегда новый файл**, никогда не правка существующего. Уникальный номер
делает фактическое пересечение невозможным; общий glob `docs/FINDING-*.md` в областях задач поэтому
допускается только для задач, которые пишут **новые** файлы.
