# S1-experiments — Эксперименты: прогоны, проверки, воспроизводимость

**Постоянная задача.** Она никогда не исчезает: каждое взятие создаёт отдельный раунд
`active/S1-experiments-<время>/`. В конце раунда ты пишешь `RESULT.md` и `DONE.json`, а карточка остаётся в
`pending/` для следующего раунда.

Ты можешь быть агентом `fast` или `main`. Если ты `fast` — Git не твой, публикует `main`.

---

## 0. Где ты

- Репозиторий: `/root/marfagenez` (WSL). Другого пути нет: через `\\wsl.localhost\` работать нельзя.
- Координация: `.coord/`. Читай `.coord/README.md` — там права, TTL, запреты.
- Твоя задача: `python3 tools/coord.py take S1-experiments --agent <твоё имя>`.
- Закончил: `python3 tools/coord.py finish <каталог раунда> --agent <твоё имя>`.

## 1. Что за проект (три строки)

Исследование о том, **какой темп процесса решает, выживет ли система**. Есть две карты, которые нельзя
смешивать: **литературная** (`literature/map/`, ~1000 ячеек с цитатами и числами) и **карта знаний**
(`kg/`, ~580 узлов с нашими утверждениями и формулами). Плюс экспериментальная часть на Rust (`core/`) и
формальные доказательства на Lean (`laws/`).

## 2. Жёсткие правила (нарушение = откат)

1. **Git не твой, если ты `fast`.** Никаких `git add/commit/push/checkout/reset/stash/restore/clean`.
2. **Не править защищённые зоны:** `core/`, `laws/`, `verus/`, `checks/`, `run.sh`, `AGENTS.md`,
   `kg/nodes.jsonl`, `kg/migrate.py`, `kg/kg.py`, `tools/coord.py`. Нужно — оформи задачу `maint`.
3. **`kg/nodes.jsonl` не редактируется руками никогда.** Он собирается: `python3 kg/migrate.py` →
   `python3 kg/kg.py build`. Иначе `kg/regress.py` покраснеет.
4. **Числа без команды не результат.** Любое число в отчёте сопровождается командой, которой оно
   получено, и параметрами (сид, N, сетка).
5. **История не переписывается.** Прошлые записи получают только датированные дополнения.
6. **Чужое не трогать.** Активная область другого агента — не твоя.
7. **Не выдавать аналогию за тождество.** Совпадение слова, числа или размерности — не совпадение
   механизма.

## 3. Как устроена экспериментальная часть

| что | где |
|---|---|
| модели и пробы | `core/examples/*.rs`, сборка `cd core && cargo build --release --examples` |
| запуск пробы | `cd core && cargo run --release --example <имя> -- <аргументы>` |
| результаты прогонов | `results/<EXP-ИМЯ>/run-<время>.json` |
| проверки прогонов | `checks/exp_*.py`, `checks/exp_memory_sampling.py` и подобные |
| секции гейта | `bash run.sh test`, `bash run.sh exp`, `bash run.sh all` (дорого) |

**Устройство пробы.** Проба пишет JSON с параметрами и результатом. Она обязана быть
**воспроизводимой**: фиксированный сид, фиксированные параметры, детерминированный вывод.

## Почта (проверять перед раундом)

```
python3 tools/coord.py inbox --agent <имя>
```

Там указания от других агентов, сообщения о поломках и запреты. Непрочитанное письмо с
видом `instruction` или `bug` — стоп-сигнал: прочитай, прежде чем писать файлы.

## Heartbeat (обязательно)

Пока задача у тебя, раз в 15 минут и **перед/после долгих операций** вызывай:

```
python3 tools/coord.py heartbeat <ID> --agent <имя>
```

Без этого через 30 минут задача считается брошенной, и `main` вправе её вернуть.
Если heartbeat отвечает «задача у агента …» — задачу у тебя забрали, **остановись**.

## 4. Цикл одного раунда (ровно один инкремент)

1. **Выбери один вопрос.** Не три. Вопрос должен быть проверяемым: «при каком N порог сдвигается?»,
   а не «как устроена жизнь».
2. **Запиши предсказание ДО запуска** — в `RESULT.md` в раздел «Предсказание». Без этого шага раунд
   не считается.
3. **Запусти пробу** на существующем примере. Если нужного примера нет:
   - ты `main` — можно добавить `core/examples/<имя>.rs`, но помни: правка `core/` требует обновления
     `docs/agent/AGENT_STATE.md` в том же коммите;
   - ты `fast` — создай задачу `maint` с точным описанием примера и оставь комментарий в `RESULT.md`.
4. **Проверь воспроизводимость:** запусти дважды, числа должны совпасть. Не совпали — это результат,
   запиши.
5. **Сверь с предсказанием.** Совпало / не совпало / неоднозначно. Все три — результаты.
6. **Прогони точечные проверки:** `python3 checks/<нужная>.py`. Полный `bash run.sh all` — только `main`.
7. **Оформи:** `RESULT.md` (шаблон ниже) и `DONE.json`.

## 5. Шаблон `RESULT.md`

```
# Раунд S1 — <дата>

## Вопрос
## Предсказание (до запуска)
## Команда
    cd core && cargo run --release --example <имя> -- <аргументы>
## Параметры
сид, N, сетка, число повторов
## Результат (числа)
таблица или список; каждое число — из этой команды
## Совпало с предсказанием? (да / нет / неоднозначно)
## Что это НЕ доказывает
## Проверки
какие `checks/*.py` прогнаны и их итог
## Следующий вопрос (если возник)
```

## 6. Частые поломки и что делать

| симптом | причина | что делать |
|---|---|---|
| `probe not built` | нет бинарника | `cd core && cargo build --release --examples` (если ты `fast` — это делает `main`) |
| числа плавают | не фиксирован сид | зафиксировать сид, записать его в `RESULT.md` |
| `run.sh exp` падает на `checks/log_check.py` | журнал отстал | это работа `main`: он именует коммит в журнале |
| проверка требует `results/` | прогон не записал | перезапустить; `results/` — не твой кэш, а артефакт |
| гейт красный на `agents` | менялись `core/`/`checks/`/`laws/` | обновить `AGENT_STATE.md` — только `main` |

## 7. Критерии приёмки раунда

- [ ] предсказание записано **до** запуска;
- [ ] команда и параметры приведены полностью;
- [ ] числа воспроизводятся повторным запуском;
- [ ] есть раздел «что это НЕ доказывает»;
- [ ] точечные проверки прогнаны и их итог указан;
- [ ] `DONE.json` с полями `artifacts` и `checks` создан.

## 8. Чего делать нельзя

- Подгонять параметры, пока не совпадёт с желаемым — это уже не проверка, а подгонка. Если менял
  параметры, все прогоны и причины записываются.
- Заявлять «подтверждено», если прогон один и без повторов.
- Добавлять новый пример в `core/`, будучи `fast`.
- Трогать `results/` других экспериментов.
