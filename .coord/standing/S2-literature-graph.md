# S2-literature-graph — Литература и граф: ячейки, связи, сшивка

**Постоянная задача.** Она никогда не исчезает: каждое взятие создаёт отдельный раунд
`active/S2-literature-graph-<время>/`. В конце раунда ты пишешь `RESULT.md` и `DONE.json`, а карточка остаётся в
`pending/` для следующего раунда.

Ты можешь быть агентом `fast` или `main`. Если ты `fast` — Git не твой, публикует `main`.

## 1. Что за проект (три строки)

Исследование о том, **какой темп процесса решает, выживет ли система**. Есть две карты, которые нельзя
смешивать: **литературная** (`literature/map/`, ~1000 ячеек с цитатами и числами) и **карта знаний**
(`kg/`, ~580 узлов с нашими утверждениями и формулами). Плюс экспериментальная часть на Rust (`core/`) и
формальные доказательства на Lean (`laws/`).

## 2. Жёсткие правила (нарушение = откат)

1. **Git не твой, если ты `fast`.** Никаких `git add/commit/push/checkout/reset/stash/restore/clean`.
2. **Не править защищённые зоны:** `core/`, `laws/`, `verus/`, `checks/`, `run.sh`, `AGENTS.md`,
   `kg/nodes.jsonl`, `kg/migrate.py`, `kg/kg.py`, `tools/coord.py`. Нужно — оформи задачу `maint`.
3. **`kg/nodes.jsonl` не редактируется руками никогда.** Он собирается: `python3 kg/migrate.py` →
   `python3 kg/kg.py build`. Иначе `kg/regress.py` покраснеет.
4. **Числа без команды не результат.** Любое число в отчёте сопровождается командой, которой оно
   получено, и параметрами (сид, N, сетка).
5. **История не переписывается.** Прошлые записи получают только датированные дополнения.
6. **Чужое не трогать.** Активная область другого агента — не твоя.
7. **Не выдавать аналогию за тождество.** Совпадение слова, числа или размерности — не совпадение
   механизма.

## 3. Как устроена литературная карта

| что | где |
|---|---|
| ячейки | `literature/map/atoms.jsonl` (одна JSON-строка = одна ячейка) |
| связи | `literature/map/edges.jsonl` |
| инсайты | `literature/map/insights.jsonl` |
| приём | `python3 tools/map_ingest.py <файл> --report <md>` |
| контракт | `python3 checks/map_contract.py` (M1–M11) |
| чтение | `python3 tools/map.py digest`, `... zoom --atom ID`, `... zoom --domain D` |
| дипы | `python3 tools/dip.py add --task T --domain D --question "…"`, отчёты в `literature/dips/reports/` |

**Схема ячейки:** `atom, statement, domain, kind, mechanism, formula, symbols, conditions, works[{doi,
locator, access, quote}], confidence, locator_status, tags, notes, kg_ref[]`.
`kind` строго из: `mechanism | formula | condition | contradiction | gap | definition | measurement`.

**Схема связи:** `from, to, type` где `type` из `requires | contradicts | generalizes | measures |
derives | analogous | refines`.

**Сшивка с картой знаний:** `kg_ref` — список узлов `kg/` (`C-*`, `F-*`, `L-*`, `GAP-*`, `CORR-*`).
Импорт и пересборку `kg/` делает **только `main`**.

## 4. Жёсткие правила литературы

1. **Любое число — из текста или таблицы с локатором.** Числа «с графика» не принимаются.
2. **Цитата дословная, 10–30 слов**, без пересказа. `access: fragment|full` требует `quote`.
3. **DOI проверяется**: `works/https://doi.org/<DOI>` в OpenAlex. Не выдумывать идентификаторы.
4. **`confidence: high`** требует формулы или цитаты и `locator_status: verified`.
5. **`gap`** требует `searched` (каналы, запросы, дата) и `scope` (что просмотрено).
6. **Доля `analogous` среди связей ≤ 1/3** (M9). Иначе карта превращается в метафоры.
7. **Один агент — один файл приёма.** Пиши в `literature/map/inbox/<твоё-имя>-<раунд>.jsonl`,
   не правь `atoms.jsonl` напрямую.

## Почта (проверять перед раундом)

```
python3 tools/coord.py inbox --agent <имя>
```

Там указания от других агентов, сообщения о поломках и запреты. Непрочитанное письмо с
видом `instruction` или `bug` — стоп-сигнал: прочитай, прежде чем писать файлы.

## Heartbeat (обязательно)

Пока задача у тебя, раз в 15 минут и **перед/после долгих операций** вызывай:

```
python3 tools/coord.py heartbeat <ID> --agent <имя>
```

Без этого через 30 минут задача считается брошенной, и `main` вправе её вернуть.
Если heartbeat отвечает «задача у агента …» — задачу у тебя забрали, **остановись**.

## 5. Цикл одного раунда

1. **Выбери одну дыру.** Источник: `docs/SUPPORT-WORKLIST.md` (что без опоры),
   `python3 tools/map.py digest` (пустоты), задачи `P*` в очереди.
2. **Сформулируй вопрос так, чтобы ответ был числом.** «При каком уровне X ремонт падает во сколько
   раз» — годится. «Как связаны старение и ремонт» — нет.
3. **Поиск:** OpenAlex → Europe PMC (`fullTextXML`) → PMC HTML → издательские OA. При 5xx — менять
   канал, а не формулировку (`docs/SEARCH-STOP-RULE.md`).
4. **Проверь цитату по полному тексту.** Не нашёл текст — `access: abstract`, и так и пиши.
5. **Запиши ячейки** в свой inbox-файл. Для каждой: число, локатор, цитата, условия, `kg_ref`.
6. **Связи:** только если совпадает **измеряемая величина**, а не слово. Помни: совпадение числа
   (1/6, 0.9) — не совпадение величины.
7. **Проверки:** `python3 checks/map_contract.py`, при дипах — `python3 checks/dip_reports.py`.
8. **Оформи** `RESULT.md` + `DONE.json`.

## 6. Шаблон `RESULT.md`

```
# Раунд S2 — <дата>

## Вопрос
## Запросы (дословно) и каналы
## Что найдено
| ячейка | работа (DOI) | число | локатор | цитата |
## Что НЕ найдено (с запросами и датой)
## Предложенные связи
| пара | тип | что совпадает: величина или только слово/число |
## Файлы, которые я создал
## Проверки
## Следующий вопрос
```

## 7. Частые поломки

| симптом | причина | что делать |
|---|---|---|
| `M2: дубль id` | ячейка уже есть | взять новый префикс `fast-<раунд>-NN` |
| `M4: нет conditions` | `medium` без условий | добавить условия эксперимента |
| `M9: аналогий больше трети` | слишком много `analogous` | перевести слабые в `refines` с обоснованием |
| `D2: нет works` у `gap` | нет `searched`/`scope` | добавить протокол поиска |
| DOI не проверяется | опечатка/закрытый | сверить через OpenAlex, иначе `locator_status: unverified` |

## 8. Чего нельзя

- Писать `verified`, не открыв текст.
- Ставить `analogous` там, где совпало только слово.
- Править `atoms.jsonl` напрямую (потеря чужих записей).
- Переписывать уже принятые ячейки: только новые ячейки или датированные дополнения в `notes`.
