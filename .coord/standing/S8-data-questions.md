# S8-data-questions — вопросы к данным без правок

**Постоянная задача.** Раунд = одна партия вопросов.

## Зачем

В карте есть места, где две ячейки говорят об одном и том же, но числа не сходятся; где единицы
не переводятся друг в друга; где величина выглядит на порядки мимо. Такие места **не исправляются связью** —
их надо сначала заметить.

Твоя работа — **задавать вопросы с числами**, а не ставить связи.

## Что искать (в этом порядке)

1. **Одно и то же с разными числами.** Две ячейки об одной величине, значения расходятся.
2. **Единицы, которые не сходятся.** Одна ячейка в см/с, другая в мкм/с; одна в Дж/м², другая в пДж/мкм².
3. **Порядки врозь.** Величины «одной природы», но различаются в 10²–10⁶ раз — это либо разные величины, либо
   ошибка записи.
4. **Пробел, выданный за опору.** Ячейка утверждает «не найдено», а на неё ссылаются как на подтверждение.
5. **Число без локатора.** В утверждении есть число, но не сказано, откуда оно.

```bash
cd /root/marfagenez

```

## Куда класть результат

Файл `literature/map/inbox/probe-<YYYYMMDD-HHMM>.jsonl`, строка на вопрос:

```json
{"question": "DIP24-0005 и DIP24-0011: 1,0·10⁻³ см/(с·осмоль) против 71,9 — это разные единицы длины или разные величины?",
 "atoms": ["DIP24-0005", "DIP24-0011"], "kind": "units", "numbers": ["1.0e-3", "71.9"]}
```

`kind` — один из: `units`, `numbers`, `order`, `gap-as-support`, `no-locator`.

В каталог раунда — `RESULT.md`:

```markdown
# Раунд probe — <дата>

## Вопросов: N (units X, numbers Y, order Z, …)
## Самый серьёзный вопрос и почему
## Что проверил и не нашёл проблем
```

## Жёсткие правила

- **Только вопросы.** Никаких связей, вердиктов и правок карты.
- Не больше **6 вопросов** за раунд: каждый я должен проверить руками.
- Числа — **из текста ячейки**, а не «по памяти».
- Git не твой; `run.sh all` не запускаешь.

## Критерий приёмки

Каждый вопрос содержит минимум два числа или две ячейки и **проверяемый** ответ («да, разные единицы» /
«нет, одна величина»).
